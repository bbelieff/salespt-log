# SSOT Grandfathered List

> **이 파일이 무엇인가요?**
> - **한 줄 요약**: SSOT 미등록 상태이지만 `doc-drift.sh` 가드레일 검사를 면제할 기존 누락분 박제 리스트
> - **누가 읽나요**: 개발자, 에이전트
> - **어떤 기능·작업과 연결?**: `scripts/doc-drift.sh`
> - **읽고 나면 알 수 있는 것**:
>   - 면제 받는 심볼 목록 (왜 누락됐는지 + 어디 등재 권장)
>   - 점진 backfill 진행 방법
> - **관련 문서**: [components.md](./design/components.md), [data-model.md](./domains/data-model.md), [sheet-structure.md](./domains/sheet-structure.md)

## 원칙

- **새 PR이 추가하는 누락은 절대 면제 안 됨.** 새 컴포넌트/타입은 SSOT 등록 후 추가.
- 이 파일은 **줄어들기만** 한다. backfill PR이 SSOT에 등재할 때마다 해당 줄을 삭제.
- 라인 0 = backfill 완료.

## 사용 방법

`doc-drift.sh` 가 ` - SYMBOL` 형식의 라인을 grep 한다. 라인 시작은 정확히 `- ` 두 글자.
주석/설명은 같은 라인 뒤쪽에 적어도 무관 (스크립트는 첫 단어만 본다).

## B. 타입 (data-model.md 미등록)

> 5개 탭 v2 모델은 plan 문서에는 있으나 data-model.md 본문에 정확한 식별자명으로 등재 안 됨.
> data-model.md가 한글 컬럼명·산문 위주로 적혀있어 TS export 식별자와 grep 매칭 안 됨.

### 코어 (개념은 적혀있지만 식별자명 미등재)
- Channel — 4채널 enum. data-model.md는 "채널"만, `Channel` 타입명 등재 X
- ChannelDailyRow — 영업관리 1행 타입. 영업관리 컬럼 표만, 타입명 X
- MeetingState — 5상태 enum. "미팅 상태 enum" 표만, `MeetingState` 식별자 X
- MetricKey — 4지표 enum (production/inflow/contactProgress/contactSuccess). 식별자 X
- User — 마스터 레지스트리 row 타입. 컬럼 표만, `User` 식별자 X

### v2 모델 (탭 추가되며 등재 누락)
- Progress — 계약수납 진행률 enum (0%/20%/40%/60%/80%/100%)
- PaymentSlot — 분할 수납 1슬롯 (6필드)
- ContractPayment — 1계약 row (자동연동 3 + 체크박스 7 + 슬롯 3)

- DBProduction — DB 직접생산 raw
- DBBanner — DB 현수막 raw
- DBLead — DB 콜·지·기·소 raw

> backfill 시: 각 타입을 data-model.md 적절한 섹션에 1줄 식별자 + Zod 정의 인용으로 등재.

## D. 미등재 좌표 상수 (별도 backfill 대상, 면제 X)

> 다음은 `doc-drift.sh` 검사 범위 밖이지만 외부 에이전트 위험도가 가장 큰 항목.
> `docs/ssot-backfill-current-state` PR에서 본문 보강으로 처리.

- `SHEET_RANGES.sales.blockStart=10` / `blockStride=34` (영업관리 행 좌표)
- `SHEET_RANGES.contractPayment.headerRows=5` / `firstDataRow=6` (계약수납 6행부터 데이터)
- `SHEET_RANGES.dbManagement.headerRow=3` / `maxRow=100` (DB관리 헤더/스캔 상한)

- DB 섹션별 `formulaCols` 가드 리스트 (수식 컬럼 쓰기 금지 명시)
