# 개발 과업 계약 양식

[workflow](workflow.md)의 주문·목업 승인·자동 완주를 기록한다. 새 업무의 `docs/plans/active/<업무명>.md`에 필요한 항목만 사용한다. 다른 큐/역할 지침을 복제하지 않는다.

## 주문·설계
- 과업 ID / 주문 / 목표 / 제외 범위:
- 기준 master SHA / worktree / branch:
- 총괄·제작·검증·배포 책임자와 실제 thread:
- 담당 파일·공용 계약·선행 작업:
- 수용조건(화면·동작·데이터 보존·회귀):
- 현재 단계 / 다음 행동 / 대기 사유:

## 목업·승인
- 목업 버전 / 직접 열 수 있는 링크 / 제품 기준 SHA:
- 재사용 컴포넌트·CSS·폰트·토큰 / 합성 fixture·모의 요청 경계:
- 변경 전후 / 모바일·PC / 로딩·빈 화면·실패·완료:
- 목업 검증 / 실제 visibility·열람 경로:
- 미승인 / 수정 요청 / 승인(과거 승인본 보존):
- 사용자 승인 시점·메시지 근거 / 승인 화면·동작·범위:
- 목업/제품 차이·비지원 상태:

## 구현·독립 검증
- PR / 현재 head SHA / 변경 범위:
- check.sh / runtime build(PASS·FAIL·NOT_RUN와 이유):
- 승인본과 구현 비교 / 회귀·경계 / 비식별 증거:
- 검증자 / 대상 head / 결함·재현 / 수정 후 판정:

## 배포·운영 완료
- last-good / merge SHA / 현재 head CI run·결론:
- Deploy run·headSha·결론 / root·health HTTP:
- 승인본과 운영 비교 / 실화면·동작(PASS·FAIL·NOT_RUN):
- 미완료·차단·재개 조건 / 복구 방법 / 다음 행동:
- 모델별 실제 입력·출력·합계·시간·집계 범위·계측 한계:
