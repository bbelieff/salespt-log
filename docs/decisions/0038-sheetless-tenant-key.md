# ADR-0038 · 시트 없는 수강생 고유 번호 (2026-11-10)

## 상태
채택(1단계 — 규칙·관문·샌드박스 시험). 실제로 시트 없는 수강생을 만드는 것은 계획 문서의 단계를 따른다.

## 맥락
DB 는 모든 기록(일지·미팅·계약·DB관리·금고·지출…)을 `spreadsheet_id` 로 사람(사업장)별로 나눈다.
이 값은 지금까지 항상 구글 시트 ID 였다. 시트 없이 수강생을 만들려던 #798 은 이 값을 빈칸으로
저장해, 시트 없는 수강생끼리 기록이 한 통에 섞이는 문제가 있었다(샌드박스 시험 X 로 재현).
`users.id` 는 행을 다시 쓸 때마다 새로 발급돼(`rekeyUserRow`) 고유 번호로 쓸 수 없다.
`spreadsheet_id` 는 한 사람이 아니라 **사업장 단위**다 — 직원·가족 이메일이 같은 번호를 공유한다.

## 결정
- **고유 번호 = `spreadsheet_id` 열의 값, 의미만 「불투명한 번호」로 바꾼다.** 열 이름은 그대로(1,500곳 넘는 이름 바꾸기는 위험만 크다).
- **기존 시트 ID 는 그대로 번호로 쓴다.** 데이터 이동·재키잉 0 — 기존 수강생은 아무것도 바뀌지 않는다.
- **시트 없이 만드는 수강생 = `local:<uuid>`.** `:` 는 시트 ID 문자집합에 없어 절대 겹치지 않는다.
- **빈 번호("")는 수강생 기록 번호로 금지.** 트레이너·관리자(기록 통 없음)만 빈칸.
- **단일 관문**: `sheets-client` 의 모든 시트 호출은 `local:` 번호면 네트워크 전에 `SheetlessTenantError("[no-sheet] …")` 를 던진다. 시트 없는 번호가 구글로 새는 길이 구조적으로 없다.

## 그대로 두는 것
- 기존 수강생의 번호·시트 미러·시트 기수(1·2·3·5기).
- 열 이름 `spreadsheet_id`(나중에 별도 결정으로 이름만 바꿀 수 있다).

## 되돌리기
`local:` 번호를 가진 사용자가 0명인 동안은 PR revert 1건으로 끝난다(관문은 기존 번호에 영향 0).
