# ADR-0039 · 사업계획서 작성도구 (2026-11-23)

## 상태
채택. 1단계(① 내 구독 = 자료 꾸러미) 구현. ②·③ 은 아래 순서대로 별도 PR.

## 맥락
belie 가 정책자금 사업계획서를 「빌더 md + 고객 서류」로 클로드·ChatGPT 에서 만들어 왔다(빌더 v4.8).
이것을 경영일지 업무도구로 옮겨 이용자 누구나 같은 품질로 쓰게 한다. 비용 문제가 커서(클로드 API 는
건당 수천 원, 다른 모델은 문장 품질이 낮음) 방식을 셋으로 나눈다. 2026-11-22 기획 페이지 승인.

## 결정
1. **쓰는 사람 = 경영일지 이용자 모두** — 관리자, 활성 트레이너, 승인된 수강생(수료생 포함). 승인 대기·미등록은 안 된다
   (`canUseBizplan`). 현재 범위(scope.md)가 이미 모두를 포함하므로 범위 확장은 아니다.
2. **세 방식, 이 순서로 연다**: ① 내 구독 — 자료 꾸러미(빌더·팩트시트·원본 자료·시작 프롬프트)를 받아 내 AI 대화창에서 직접 만든다(추가 비용 0).
   ② 내 API 키 — 키를 연결하면 경영일지가 단계별로 만들고, 빠진 정보는 멈추고 묻는다. ③ 실비 결제 — 키 없이 만들고 끝나면 실제 사용량만큼 건별 카드 결제(무료 건수 없음, 결제 전 파일 잠금 = 미수 없음).
   ③ 은 ② 로 실제 원가를 몇 건 잰 뒤 연다. 기본 모델은 Claude Sonnet 5.5 · 노력 높음(②·③).
3. **클로드 구독(Pro·Max) 계정으로 다른 앱에 로그인하는 방식은 쓰지 않는다** — Anthropic 약관상 금지(code.claude.com/docs/en/legal-and-compliance). 그래서 ① 은 「꾸러미를 받아 직접」이다.
4. **고객 자료는 ① 에서 서버에 오지 않는다.** 파일은 브라우저 안에서만 ZIP 으로 묶는다(`zip-store`, 압축 없는 표준 ZIP). 글자 입력만 이 브라우저에 임시저장.
   ②·③ 은 만드는 동안만 서버에 임시로 두고 끝나면 지운다. 보관 원본은 사용자 본인 구글 드라이브(경영일지가 만든 폴더 안, 별도 연결)에 둔다 — 드라이브 연결은 별도 PR.
5. **공식 빌더·양식은 저장소에 넣지 않는다.** 이 저장소는 공개라 빌더가 그대로 드러난다. 관리자 구글 드라이브의 비공개 폴더(`bizplanKitFolderId`)에 두고,
   서버가 관리자 OAuth(ADR-0015)로 읽어 경영일지 이용자에게만 내려 준다. 새 공식 판 = 그 폴더에 새 md 를 올리기(이름의 v 번호가 가장 큰 것이 최신). DB 표를 새로 만들지 않는다.
6. **빌더는 두 부분**: 글쓰기 규칙(바꿀 수 있음 — 내 빌더) / 디자인 키트(②·③ 에서는 경영일지 코드가 그림, 공식만).

## 그대로 두는 것
- 서류 자동입력(OCR)·간편인증 서류 조회 — 꾸러미 팩트시트 「숫자 자동 읽기」는 다음 PR 에서 기존 OCR 을 다시 쓴다.

## 되돌리기
