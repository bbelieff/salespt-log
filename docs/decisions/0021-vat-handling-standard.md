# ADR-0021 — 부가세 처리 표준 (입력 시 부가세여부 기록, 인식은 항상 부가세 제외)

## 맥락

비용(매입DB·직접생산·현수막)과 매출(수임비·수수료)에 부가세 포함/미포함이 섞여 들어온다. 영업이익 = 매출 − 비용이 일관되려면 양쪽 모두 같은 기준(부가세 제외)이어야 한다. 또한 `03 DB관리`는 좌우 섹션이 인접해 신규 컬럼 공간이 없다.

## 결정

1. **저장값 = 부가세 제외(인식값)**: 입력이 부가세 포함이면 `÷1.1` 후 저장. 역산 헬퍼 `lib/pricing.ts unitPriceFromTotal(총액, 개수, 부가세여부)`.
2. **부가세여부 플래그 저장**: 재편집·감사 시 원 총액 복원용. 비용측 위치 = **매입DB F · 현수막 U · 직접생산 N**(직접생산은 C1에서). 기존 `주문금액`(=개당단가×개수) 시트 저장을 제거해 그 자리를 부가세여부로 사용.
3. **파생값은 시트에 저장하지 않고 계산**: `주문금액`(개당단가×개수)·직접생산 `개당단가`(예산÷개수)는 시트 컬럼에서 빼고 read 시 코드가 계산. 대시보드 비용/영업이익은 계산값을 read(추가 보정 불필요 — 이미 ex-VAT).
4. **전환은 lazy**: 컬럼 의미 변경(F/U)은 전환 read(F/U 가 boolean이면 신규, number면 구 #425 H/W에서 fallback) + 쓰기 시 신규 레이아웃 기록·구 칸 정리. 블로킹 일괄 마이그레이션 없음(편집 시 점진 이전).

## 대안 / 기각

- **#425 gap컬럼(H/W)**: 부가세여부를 빈 H/W에 두는 방식. 주문금액 컬럼이 파생값인데도 시트를 점유 → 일관성↓. 정식 컬럼 방식(주문금액 자리=부가세여부)으로 대체.
- **부가세 보정을 대시보드에서**: 저장은 포함값, 표시 때 ÷1.1. → 합계·수식 곳곳 보정 필요, 누락 위험. 저장 시점 ex-VAT 통일이 단순.
