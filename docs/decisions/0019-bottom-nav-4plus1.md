> **📄 이 문서는 무엇인가요?**
> - **한 줄 요약**: 하단 5탭을 활성화 퍼널 순서(DB생산→컨택→[캘린더]→일정·계약→실무/수납)로 재배치하고, 중앙 캘린더를 입체 FAB로, 단계는 라벨 아래 점 갯수로 표현하기로 한 결정.

## 맥락
components.md §5가 "5탭 순서·라벨·아이콘 고정(변경 시 ADR 필요)"으로 박혀 있다. 기존 순서(컨택/일정·계약/캘린더/수납/DB관리)는 영업 활성화 퍼널 순서를 전달하지 못했고, 캘린더가 일반 탭이라 일정 진입 동선이 약했다.

## 결정
1. **4+1 재배치** — 좌2(DB생산·컨택관리) · **중앙 캘린더 FAB** · 우2(일정·계약·실무/수납). 좌→우가 활성화 퍼널 단계 순서.
2. **단계 인디케이터** — 라벨 아래 **점 갯수 = 단계(1·2·3·4)**. 현재 탭만 파랑(blue-600), 나머지 회색. 서수/알림 뱃지 아님.
3. **중앙 캘린더 = 중립 입체 FAB** — 흰 원 + 테두리 + 그림자 + 위로 띄움. **대시보드(상단 홈)보다 약한 강조**(색 채움 없음).
4. **라벨 리네임** — 사용자 노출 `DB관리 → DB생산`. **라우트(`/db`)·코드 키·내부 식별자는 불변**(이름표만).
5. **반응형 캡** — 모바일 전폭(flex-1), 넓은 화면 max-width **480px**(`max-w-bottom-nav` 토큰) 중앙정렬, 캡 안 flex-1 균등.

## 근거
- 순서가 곧 "어디까지 진행했나"를 시각적으로 전달(활성화 퍼널). 점 갯수로 단계 직관화.
- 캘린더는 매일 쓰는 진입점 → 중앙 FAB로 접근성↑. 단, 홈(대시보드)보다 약한 입체로 위계 유지.
- `DB관리→DB생산`: 학생 멘탈모델은 "DB로 생산을 만든다"에 가까움.

## 불변/스코프
- **바(네비게이션)만** 변경. 기능 변경(DB생산 집계쓰기, 컨택 경량화 등)은 별도 PR.
- 라우트·코드 키·아이콘 SVG path는 유지(레거시 보존). 정본 = prototypes/bottom-nav-4plus1.html.
