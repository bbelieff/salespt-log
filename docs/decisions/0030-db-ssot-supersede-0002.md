# ADR-0030 — DB(Postgres) 단일 정본 전환 + 시트 은퇴 (ADR-0002·D3 supersede)

## 맥락

ADR-0002(2026-04-16)는 "Sheets API 쿼터가 실제 병목이 되면 캐시 레이어 또는 BigQuery 미러링을 새 ADR로 도입한다"는 번복 조건을 스스로 예고해뒀다. 실제로 온 트리거는 쿼터가 아니라 **관리자 화면(BBE-48, [수강생관리] 진입 지연 — 전 기수 시트를 매번 개별 조회)과 ADR-0031(무제한 CRM, 수료 후에도 계속 쓰는 CRM으로 확장)**였지만, 본질은 같다 — 시트를 정본으로 삼는 구조가 규모가 커질수록 병목이 된다는, 0002가 이미 내다본 전환점에 지금 도달한 것이다.

R2(읽기)·R3(쓰기 일부)로 DB는 이미 파일럿 4개 기수(8·9·연습·아레나)에서 사실상 정본 역할을 하고 있다. 다만 이 사실이 ADR에 반영되지 않아 **문서(0002="시트가 SSOT")와 코드(R2/R3="DB가 일부 정본")가 모순**된 상태였다 — `docs/plans/active/sheet-retirement-r7.md` §2-G-2가 지적한 문서 드리프트다. 본 ADR은 이 모순을 해소하고, R7(시트 은퇴) 전체가 근거로 삼을 목표 아키텍처와 그 도달 조건을 명문화한다.

D3(2026-07-08, `docs/worklog.md` — R3 착수 시점 belie 결정, 요지: DB 정본 후에도 시트 자동 미러 유지 — 트레이너·운영자 열람 + 롤백 안전망)는 이후 2026-08-05 belie의 "시트는 다운로드 버튼 형태로 남기자"(Linear BBE-51 카드 회신, 원문 그대로)로 뒤집혔다 — 영구 자동 미러 대신, 필요할 때 눌러 받는 export로 같은 역할(열람·안전망)을 더 가볍게 수행한다.

## 결정

### 1. DB(Postgres)를 단일 정본으로 — ADR-0002 §2 supersede

앱의 모든 상태는 최종적으로 **Postgres**에 있다. Google Sheets는 정본이 아니다. 이는 **지금 당장의 상태 선언이 아니라 R7이 도달할 목표 아키텍처 선언**이다 — 실제 전환은 `sheet-retirement-r7.md` §3의 Phase 1(레지스트리 DB화, #5~9)·Phase 2(나머지 쓰기 flip, #10~13)를 거쳐 점진적으로 이뤄진다. 그 과정에서 ADR-0002 §1·§4·§5(스택·인증·배포)는 손대지 않는다.

### 2. 시트 자동 미러 폐지 — 시점·조건 (R7-#20, Linear BBE-69)

R3에서 도입한 fire-and-forget 시트 미러(dual-sync)와 `googleapis` 런타임 의존(설치 스크립트·진단 도구·미러 수렴 큐 등)은 **폐기 대상**이다. 단, 즉시가 아니라 아래 조건을 **전부** 충족한 뒤에만 착수한다:

1. **R7-#18(BBE-67) 완료** — 잔여 기수(1~7기·10기) 전량 백필 + `/admin/db-parity`(행수)·`scripts/ops/dashboard-parity.mjs`(항목별 값) 대조에서 **diff = 0**.
2. **R7-#19(BBE-68) 완료** — 파일럿 게이트 제거. diff-0이 이 단계의 유일한 안전 근거다.
3. **R7-#22(BBE-71) 완료** — 아래 §3의 export가 실제로 동작 확인됨.

이 세 조건이 갖춰지기 전까지 시트 자동 미러는 **계속 켜둔다**. `AUTH_GOOGLE_*`(로그인·gcal)와 공지 이미지 업로드용 Drive 클라이언트 일부는 이 폐기 대상에서 제외한다(BBE-69 범위 그대로).

### 3. 대체물 = 다운로드 export — 미러 폐지의 선행조건 (R7-#22, Linear BBE-71)

시트가 하던 역할(트레이너·운영자 열람, 데이터 반출, 심리적 안전망)은 **앱 안에서 눌러 내려받는 export 기능**(xlsx/csv)이 대신한다.

> ⛓️ **순서 구속 — 반드시 지킨다**: **export(R7-#22/BBE-71)가 실제로 동작하기 전에는 미러(R7-#20/BBE-69)를 끄지 않는다.** 순서를 바꾸면 데이터를 꺼낼 방법이 사라진 채로 시트 갱신만 멈추는 상태가 된다. Linear에는 이미 `BBE-69 blocked_by BBE-71`로 배선돼 있다 — 이 배선을 해제하거나 우회하지 않는다.

export의 파일 형식(xlsx/csv)·담을 범위·사용 주체는 이 ADR이 결정하지 않는다 — BBE-71 소관(belie 미결 항목)이며, 이 ADR은 착수에 그 결정을 필요로 하지 않는다.

### 4. 은퇴 후 되돌릴 수 없는 것 — 롤백 경계

R7은 단계마다 가역성이 다르다. 이 경계를 명확히 하지 않으면 "언제든 되돌릴 수 있다"는 착각으로 게이트를 조기 제거하는 사고가 난다.

| 구간 | 가역성 | 되돌리는 방법 |
|---|---|---|
| R7-#1~18 (백필까지, 게이트 살아있음) | **완전 가역·경량** | `DB_READ_COHORTS` 게이트 플립 1건으로 즉시 시트 정본(R2)으로 복귀. 지금까지 유지해온 1차 안전망. |
| **R7-#19 게이트 제거(BBE-68)** | **⚠️ 안전망 상실 지점 — 여기서 "쉬운 되돌리기" 자체가 사라진다** | 게이트 코드 자체가 폐기되므로 플립할 스위치가 없다. 유일한 수단은 **PR revert + 재배포**(BBE-68 본문 명시). 무겁지만, 시트는 아직 최신이므로(미러 계속 켜짐) 데이터 자체는 복구 가능하다. |
| R7-#19 이후 ~ R7-#20 미러 폐기 이전 | **가역(무거움) — PR revert 한정** | 위와 동일 상태 유지 구간. 미러가 계속 켜져 있어 시트가 최신을 유지 — 이 구간이 끝나기 전까지가 데이터 기준으로는 사실상 마지막 안전 구간. |
| **R7-#20 미러 폐기(`googleapis` 런타임 제거, BBE-69)** | **⛔ 데이터 비가역 지점** | 이 순간부터 시트는 갱신이 멈추고 **은퇴 시점의 스냅샷으로 박제**된다. PR을 되돌려도 그 사이 쌓인 변경분은 시트에 없다 — 수동 재동기화 없이는 자동 복구 불가. |
| R7-#21 이후 생성되는 신규 기수(DB insert만) | **완전 비가역** | 애초에 그 기수는 시트 자체가 없다. "시트로 되돌아간다"는 개념이 성립하지 않는다. |
| R7-#20 인프라 철거(`setup-formulas.ts`·진단 도구·미러 큐 삭제) | **비가역** | 시트 기반 운영으로 돌아가려면 되돌리기가 아니라 재구축이 필요하다. |

**실무 규칙**: 진짜 "언제 멈춰도 안전한" 구간은 **R7-#19 이전**뿐이다. R7-#19(게이트 제거) 자체가 이미 안전망을 경량 → 중량(PR revert)으로 격하시키는 결정적 분기점이므로, BBE-68이 요구하는 착수 조건(R7-#4·10·11·13·17·18 완료 + belie 최종 승인)을 전부 충족하기 전에는 절대 착수하지 않는다. R7-#20(미러 폐기)은 §2의 3개 조건 전부 충족 후에만 — 그 전에 착수하면 위 표의 데이터 비가역 지점을 조기에 건너는 것과 같다.

## 결과

- ✅ 문서(ADR)와 코드(R2/R3 이미 진행 중인 DB 정본화)의 모순이 해소된다 — 이후 세션은 "시트가 SSOT"라는 stale한 전제로 판단하지 않는다.
- ✅ D3가 지키려던 것(트레이너·운영자 열람, 롤백 안전망)은 export + diff-0 검증으로 형태만 바뀌어 계승된다 — 목적을 버리는 게 아니다.
- ✅ Phase 1(레지스트리 DB화, R7의 실질 병목)이 이 ADR로 착수 가능해진다 — `sheet-retirement-r7.md`가 이 ADR을 임계경로 첫 관문으로 지정.
- ⚠️ R7-#20(미러 폐기)은 명시적으로 비가역 지점이다 — §2의 3개 선행조건 없이 착수하면 데이터 오손·소실 위험(§0.7 화이트리스트①).
- ⚠️ 관련 문서(`docs/architecture.md`의 "유일 SSOT" 문구, `CLAUDE.md` §2.5의 "별도 DB·Redis·ORM 금지" 문구)는 이 ADR과 모순되므로 갱신이 필요하나, `CLAUDE.md`는 공용부 계약이라 **별도 단독 PR**로 처리한다(BBE-52 소관, 이 PR 범위 밖).

## Out of scope

- export 파일 형식(xlsx/csv)·담을 범위·사용 주체 — BBE-71 소관, belie 미결.
- ADR-0003(외부 DB 도입 기각 사유)·ADR-0028(gcal 토큰 시트 저장) — 두 ADR 모두 ADR-0002 §2를 전제로 한 판단을 담고 있어 그 전제가 바뀌었지만, ADR은 불변 원칙(CLAUDE.md §5)에 따라 **고치지 않는다**. gcal 토큰의 실제 DB 이전은 `sheet-retirement-r7.md` Phase 1 #9(별도 실행 항목)에서 다룬다.
- `docs/architecture.md`·`CLAUDE.md` §2.5 문구 갱신, ADR-0029 번호 중복(0029×2) 정리 — BBE-52(R7-#3, 문서 정합 수리) 소관.
- Phase 1~4 각 항목의 구체 구현(스키마·이중기록·읽기 flip 등) — `sheet-retirement-r7.md` §3 정본.
