# ADR-0009: PostHog 제품분석 채택 및 개인정보 정책

## 맥락
기존 계측은 GA4(트래픽 집계)와 Sentry(에러)뿐이라 "수강생이 **무엇을 어떤 순서로** 하고 **어디서 막히는가**"를 알 수 없다. 제품 개선을 위해 행태 분석(퍼널·리텐션·세션 리플레이)과 통합 에러/예외 추적이 필요하다.

## 결정
1. **PostHog 채택** (제품분석 + 세션 리플레이 + Error Tracking). GA·Sentry는 유지(병행).
2. **수집은 운영(배포) 환경 한정.** `NODE_ENV==='production'` + 클라이언트 키 존재 시에만 init. 로컬/개발 비활성.
3. **식별 = 이메일.** person 속성: `cohort`, `name`, `role`. 1인 1시트 구조라 개인별 분석이 핵심 가치.
4. **세션 리플레이 ON, 텍스트/입력 마스킹 OFF** (사용자 결정). `lib/analytics.SESSION_MASK_PII` 플래그로 즉시 마스킹 전환 가능. password 입력은 항상 마스킹.
5. **수동 이벤트 속성은 비-PII만**(카테고리·개수·불리언). 이름·금액·업체명·전화번호 등 식별/민감 값은 이벤트 속성으로 전송 금지.
6. **에러 수집 3중**: 전역 `api_error` + `$exception`(자동) + 리플레이/rage click.

## 개인정보(PII) 리스크 — 중요
- 본 앱은 실제 수강생의 **성명·계약금액·업체명** 등을 다룬다. 세션 리플레이 마스킹 OFF + person 속성에 이름 전송은 이 PII가 **PostHog(해외 서버)에 저장**됨을 의미한다.
- 한국 개인정보보호법(PIPA)상 **수집·이용 및 (해외)제3자 제공 동의**가 필요할 수 있다(법률 자문 권고 — 본 ADR은 자문이 아님).
- **완화책**:
  - 마스킹은 `SESSION_MASK_PII=true` 한 줄로 전환 가능하게 구현.
  - PostHog 프로젝트에서 데이터 보존기간 단축·IP 익명화 설정 권장.
  - 앱에 개인정보 처리방침/동의 고지 추가를 **후속 작업으로 권고**.

## 대안
- **마스킹 ON 유지**: PII 안전하나 "왜 막혔나" 시각 파악 약화 → 사용자가 전부 녹화 선택.
- **익명 집계만**: 개인별 분석 불가 → 1인 1시트 제품 특성상 가치 절반 손실.
- **GA만 강화**: 세션 리플레이·퍼널·Error Tracking 통합 불가.

## 결과
- 신규 `lib/analytics/` (구조 테스트·doc-drift 비대상). init은 기존 `app/providers.tsx` 내부 → 신규 컴포넌트 파일 없음.
- 되돌리기: 키 환경변수 제거 시 전체 비활성. 코드 롤백은 단일 PR 단위.
