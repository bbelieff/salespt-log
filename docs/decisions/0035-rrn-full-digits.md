# ADR-0035 · 주민등록번호 13자리 저장 (2026-10-23)

## 상태
채택. 2026-09-28 「주민등록번호는 앞 6자리만 저장」 결정을 대체한다.

## 결정
업체정보 「주민등록번호」 칸은 13자리를 `NNNNNN-NNNNNNN` 으로 그대로 저장하고 화면·TXT에 그대로 보인다(belie 결정, 요청 처리판 결정 0번 「13자리 그대로 저장하고 표시」).

## 위험 고지와 수용
결정 전에 belie 에게 다음을 설명했다: 개인정보 보호법은 법령 근거 없는 주민등록번호 수집·저장을 제한하고, 유출 시 과징금 대상이며, 정책자금 서류에는 대개 생년월일·성별이면 충분하다. 대안(성별 숫자까지만 / 13자리 받되 가림·암호화)을 함께 제시했고 belie 가 「그대로 저장·표시」를 골랐다.

## 범위
- 저장 정규화 `normalizeRrn`: 숫자만 최대 13자리, 6자리 미만은 빈 값, 옛 `NNNNNN-` 값은 그대로 유효(마이그레이션 없음).
- 편집기: 7번째 숫자에서 하이픈 자동, 13자리 초과분은 버리고 칸 아래에 알림.
- 시트 미러(04 BA·이월·보관 탭)도 같은 모양.
- **문서 자동입력(OCR·메모)은 그대로 앞 6자리만** — 문서에서 뒷자리를 읽어 오지 않는다. 자동입력이 지금 13자리 값을 앞 6자리로 덮지 않게 「같아요」로 처리.

## 되돌리기
이 ADR 를 대체하는 새 ADR + `CompanyInfo.주민등록번호` transform 을 `normalizeRrnFront` 로. 저장된 뒷자리는 그 transform 이 다음 저장 때 지운다.
