# ADR-0023 — 현수막 주문→게시 1:N (게시 로그 AF:AI, 생산=게시일)

> **📄 이 문서는 무엇인가요?**
> - **한 줄 요약**: 현수막 주문(P:V) 1건에 게시 N건을 별도 로그(AF:AI)로 두고, 현수막 생산(E)을 게시일 기준 Σ게시수로 재정의한다.
> - **누가 읽나요**: 개발자, 에이전트
> - **어떤 기능·작업과 연결?**: lib/repo/banner-post.ts, lib/service/db.ts, BannerPostingLog, /api/db/banner-post
> - **읽고 나면 알 수 있는 것**: 왜 1:N인지, 게시 로그 컬럼, 생산 기준일 변경 영향
> - **관련 문서**: [정본 §3-A](../handoff/pr-db-channels-full.md), [ADR-0020 생산 SSOT](./0020-production-metric-ssot-to-db.md)

- Status: accepted

## 맥락

현수막은 **한 번 주문(발주)하고 여러 날에 나눠 게시**한다. 기존 모델은 주문 1행에 발주일 기준으로 생산을 집계해, "언제 몇 장 게시했는지"와 "남은 수량"을 표현하지 못했다. 현수막의 실제 "생산(영업활동)"은 **게시 시점**이다.

## 결정

1. **게시 로그 신설 (AF:AI)**: 03 DB관리에 새 섹션 — `게시id(AF)·주문ref(AG)·게시일(AH)·게시수(AI)`. 1행=1게시. 주문 행(P:V)은 1건 유지. 콜·지·기·소(AD) 뒤 스페이서 AE 다음, 신규 컬럼이라 **마이그레이션 없음**(additive).
2. **주문ref = `주문일|업체명`**: 게시 행을 주문에 연결하는 합성 키. 한 주문이 여러 게시 행을 가진다(1:N).
3. **생산(E) 기준 변경**: `productionCountFor(현수막)` = **게시일(AH)==date 의 Σ게시수(AI)** (구: 발주일 Σ주문개수). 주문 CRUD는 생산 E를 더 이상 만들지 않고(비용=주문금액만 대시보드 반영), 게시 CRUD가 게시일별 E를 재집계(`syncProduction`).
4. **남은 = 주문장수 − Σ(같은 주문ref 게시수)** — 시트 컬럼 신설 없이 클라/서비스 파생.
5. **보존가드(§2.5)**: 게시 append 는 게시일·게시id 모두 빈 행에만(타값 비침범), update/clear 는 명시 row. `lib/repo/banner-post.ts` 독립 모듈(db.ts 500줄 한도).

## 결과

- **기존 현수막 주문은 게시 로그가 없으므로 현수막 생산 E가 0이 된다** — 의도된 변화(생산=게시). 사용자가 게시를 기록하면 그 게시일에 E 반영. (발주만 하고 미게시 = 아직 미생산.)
- XP(`r.production`)가 현수막 집계 변화로 달라질 수 있음 — 가중치 불변, 회귀만 확인(R7).
- C4(컨택 첫 행)에서 현수막 "오늘 게시 / 남은" 표시가 이 로그를 사용.
- `data-model.md`(DBBannerPost)·`sheet-structure.md`(AF:AI)·`components.md`(BannerPostingLog) 동기화.
