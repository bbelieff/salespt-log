# ADR-0006 — 실무진행 / ToDo 데이터 모델

> **📄 이 문서는 무엇인가요?**
> - **한 줄 요약**: ToDo는 신규 `05 실무투두` 탭에 저장(04 미팅 집계 수식과 격리), 기관진행은 02 슬롯 재사용
> - **누가 읽나요**: 개발자
> - **어떤 기능·작업과 연결?**: 신규 `05 실무투두` 탭, 02 슬롯, `lib/repo/todos.ts`(신규), `lib/repo/meetings.ts`(04)
> - **읽고 나면 알 수 있는 것**: 왜 투두를 04에 안 넣고 05에 분리했나, 키 구조, Scope 3 조인
> - **관련 문서**: `practice-and-drive.md`, `0007-drive-link-permission.md`, `0008-tab-label.md`

- **Status**: accepted
- **Date**: 2026-06
- **Supersedes**: 없음

## Context
실무진행(기관 진행)과 ToDo 데이터를 어디에 저장할지. 제약:
- `02 계약수납관리`는 상단 합계 수식(승인총액·수납총액)이 수납1/2/3 슬롯을 집계 → **구조/수식 불변** 필요.
- `04 업체관리`는 **`1행=1미팅`(미팅 원본)**. `01 영업관리`·대시보드의 집계 수식이 04를 **전부 미팅으로 가정**해 COUNTIFS/SUMIFS/TEXTJOIN(키=미팅날짜+**채널**) 한다. 또한 앱의 `lib/repo/meetings.ts`가 04 전 행을 미팅으로 매핑한다.
- ToDo는 **1:N 누적**(한 계약에 여러 개, 계속 쌓임), **(계약 × 기관)** 단위(슬롯 안에 위치). 기관진행은 **1:N(최대 3)**.
- 데이터 구조 추가는 **템플릿 시트**에서 하면 전 수강생에 전파됨(사용자 확인).

## Decision
1. **기관진행 = `02`의 기존 수납1/2/3 슬롯 재사용.** (새 저장소 없음 — 데이터 이미 존재. 슬롯 값은 웹 쓰기 영역 `F~AH`.)
2. **ToDo = 신규 전용 탭 `05 실무투두`에 행 적재.** 04에 넣지 않는다. 키 `contract_ref` + `institution_ref`(=슬롯 진행기관, 항상 존재).
3. **Scope 3 = `02` 슬롯 + `05` 투두를 키로 조인**하여 업체별/기관별 뷰 구성.
4. 캘린더는 **04(미팅) + 05(투두)** 둘 다 읽어 합쳐 표시(읽기 전용).

## Alternatives considered
- **`04` 행 적재(+`종류` 칸)** — *처음 채택했다가 기각*: 01/대시보드 수식이 채널 키로 04를 집계하므로 투두를 섞으면 미팅 카운트·미팅사유가 오염. 채널을 비워 수식을 피하더라도 `lib/repo/meetings.ts`의 모든 read 경로에 `종류=미팅` 필터를 박아야 하고(핵심 미팅 경로 회귀 위험) 04 범위 `A2:S`→확장·미팅 행에 빈 투두칸이 붙는 희소 구조가 됨 → **기각**.
- **`02` 컬럼/행 확장**: 1:N 누적 불가, 수식·bulk-write 가드 위험 → 기각.
- **신규 전용 탭(`05`)** — *채택*: 그린필드라 미팅 수식/코드와 완전 격리, 투두 스키마만 깔끔. 템플릿 탭 추가가 허용됨. 비용 = `SHEET_RANGES`/`sheet-structure.md` 등재 + 신규 `lib/repo/todos.ts`(추가형, 저위험).

## Consequences
- (+) `02`·`04` 무변경(미팅 퍼널 안전). 투두는 독립 스키마(부록 F). 회귀 위험 ≈ 0.
- (작업) 05 신설 → `SHEET_RANGES` 05 키 + `docs/domains/sheet-structure.md` 등재 + `lib/repo/todos.ts` + `lib/types`(Zod)·`docs/domains/data-model.md` 등재. 캘린더는 04+05 두 소스 머지.
- (조인) Scope 3는 `02`+`05` 조인 → `contract_ref`/`institution_ref` 정합성 중요. me-bundle/pMapBundle로 묶어 quota(60req/min) 관리.
- (마이그레이션) 템플릿에 `05 실무투두` 탭 추가 → 전 수강생 전파. 04 backfill 불필요.

## Update — 디자인 세션 확정 (ToDo = 슬롯 단위)
- ToDo는 각 진행 슬롯 **안**(메모와 진행률 사이) → **(계약 × 기관)** 단위 → `institution_ref` 항상 존재.
- ToDo "장소" = **05의 자체 `장소` 칸**(신규 탭이라 보유). 별도 출처 불필요.
- 계약 공통 ToDo(기관 미지정)는 현재 범위 밖. 필요 시 `institution_ref` 빈 행으로 확장(저비용).

## Update — 02 웹 쓰기 영역 실측 정정 (2026-06, 형 세션 코드 대조)
- 기존 표기 `F~AA`는 **옛 표기**. 실제 `lib/repo/contract-payment.ts`의 슬롯 쓰기는 **`F~AH`** (AE 로드맵 메모 · AF/AG/AH 슬롯별 메모 포함, 슬롯이 M~R / Y~AD 등으로 분산). 02 구조/합계 수식 **불변** 원칙은 동일.
