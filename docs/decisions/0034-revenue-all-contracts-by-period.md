# ADR-0034: 화면 매출은 아레나 구분 없이 기간 기준

- Status: accepted
- Date: 2026-10-08
- Scope: 수강생 화면(대시보드·실무/수납)의 매출·비용·계약 집계와 계약 표시. 아레나 순위표·점수는 범위 밖.
- Supersedes (부분): ADR-0026 §1-2 의 「이월은 아레나 매출에서 제외」 — 이제 **순위표에만** 적용된다. `docs/plans/completed/arena-start-revenue-split.md` §2 「이월 뱃지+흐린 색」 중 흐린 색.

## 배경

아레나 시작 전 계약(이월)은 흐리게 보이고, 대시보드 매출·실무/수납 성과 요약에서도 빠졌다. 학생에게는 모두 실제로 맡은 일이고 매출이라, 어떤 계약이 왜 빠졌는지 헷갈렸다(belie 2026-10-08: "상관없이 다 잘 보이게, 매출집계도 상관없이, 아레나로 따로 파악하려면 직접 설정해서 보면 된다").

## 결정

1. **표시** — 이월 계약은 흐리게 하지 않는다(실무/수납 목록·기관 목록·계약 행, 일정·계약 미팅 카드). 회색 「이월」 배지와 「아레나 점수 미포함」 안내는 정보로 남긴다. **해지 계약은 지금처럼 흐리게**(빨간 「해지」 표시).
2. **매출 정의**(화면 공통, `lib/util/finance-period.ts` `periodRevenue`) — 수임비(계약일) + 수납액(수납일) − 반환액(해지일, 없으면 계약일). 이월·해지·숨김 구분 없이 모든 계약. 계약 건수 = 계약일이 기간 안인 계약.
3. **비용** — DB 비용은 서버와 같은 날짜·금액(매입DB 구매일·주문금액, 직접생산 시작일·기간예산, 현수막 날짜·주문금액), 추가 비용은 원장의 하루 단위 배분(서버와 같은 `allocateExpenseByDay`, 오늘까지만).
4. **기간 선택** — 대시보드 매출·비용·영업이익과 실무/수납 성과 요약은 같은 `PeriodPicker`(전체 · 이번 달 · 이번 주 · 직접 설정)를 쓴다. 「전체」= 기록된 기간 전체. 주 = 월~일, 달 = 1일~말일, KST 날짜로 계산. 아레나 기준이 필요하면 「직접 설정」으로 시작일부터 고른다.
5. **진행 현황**(`activeWorkContracts`) — 숨김·해지만 빼고 이월은 포함한다.
6. **범위 밖** — 아레나 순위표 매출(`scoreboard.ts` → `splitContractRevenue().arena`)·해지 차감 점수, 퍼널·미팅 활동 집계의 이월 제외, 일정·계약 탭 주간 수임비 합계는 그대로 둔다. 서버 `/api/dashboard` KPI 필드도 바꾸지 않는다(대시보드 매출 박스만 화면 계산으로 대체).

## 한계·되돌리기

- 「직접 설정」의 시작일=아레나 시작일은 이월 깃발(`구분=이월`)이 붙은 개강 후 계약과, 개강 전 계약의 개강 후 수납을 포함하므로 순위표 아레나 매출과 정확히 같지는 않다. 정확한 아레나 매출은 순위표가 정본이다.
- 대시보드 매출 박스가 서버 KPI(아레나) 대신 화면 계산을 쓰므로 순위표 매출과 숫자가 다를 수 있다 — 의도된 차이.
