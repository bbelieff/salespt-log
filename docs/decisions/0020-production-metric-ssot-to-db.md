# ADR-0020 — 생산(E) 지표 SSOT를 컨택 수기입력 → DB생산 집계로 이동

> **📄 이 문서는 무엇인가요?**
> - **한 줄 요약**: 01 영업관리 E(생산)의 진실원천을 "컨택관리 수기 입력"에서 "DB생산 탭 raw 행 집계(앱이 자동 기입)"로 옮기는 결정.
> - **누가 읽나요**: 개발자, 에이전트
> - **어떤 기능·작업과 연결?**: DB생산(/db), 컨택관리, lib/service/db.ts·lib/repo/sales.ts, 01 영업관리 E
> - **읽고 나면 알 수 있는 것**: E를 누가 소유하나, 집계 규칙, §2.5 가드 적용 여부, 이중입력 제거
> - **관련 문서**: docs/domains/sheet-structure.md, activation-redesign PR 묶음(PR1)

- **status**: accepted
- **date**: 2026-06-19

## 맥락
기존: 생산(E)은 컨택관리 스테퍼로 학생이 수기 입력. 그런데 같은 생산 raw는 DB생산 탭에도 입력해야 해서 **이중입력**이었고, 둘이 어긋나면 CrossTabHintModal(DB합 불일치 경고)로 보정시켰다. 매일 동선인 컨택관리를 무겁게 만드는 원인.

## 결정
1. **E(생산)의 SSOT = DB생산 raw 집계.** E는 더 이상 사용자 수기입력이 아니라 **앱이 소유하는 파생값**.
2. **집계 규칙** (DB raw 변경 시 그 채널·날짜만 재집계해 E 기입):
   - 매입DB = Σ주문개수 by 구매일 · 직접생산 = Σ생산개수 by 날짜 · 현수막 = Σ주문개수 by 날짜 · 콜·지·기·소 = 행수 by 접수일.
   - 편집 가능 기간(1~10주) 밖 날짜는 기입 생략.
3. **항상 overwrite** (belie 결정 2026-06-19). E는 app-derived라 §2.5 보존가드 **비대상** — 기존 E:H daily writer 가 무가드인 것과 동일(사용자 수기입력 셀이 아님). 컨택 저장은 이제 **F:H 만** 쓴다.
4. **CrossTabHintModal(DB↔생산 불일치/일치 안내) 제거** — 컨택이 E를 안 쓰니 불일치 개념 자체가 사라짐.

## 근거
- 이중입력 제거 → 컨택관리는 유입→컨택→미팅 흐름만. 북극성(첫 미팅) 경로 경량화.
- 비용/생산은 DB생산 탭에 모아 입력 → 단일 입력점, 자동 반영.

## 영향
- E의 보존가드 적용 범위 변화: E는 이제 app-owned(무가드 overwrite). F~H·기타 사용자 입력 셀의 §2.5 가드는 그대로.
- 마이그레이션 = lazy: 배포 후 각 (채널,날짜)의 DB raw가 다음 변경될 때 E가 집계값으로 갱신됨. 옛 수기 E는 그 전까지 유지.
- 컨택 생산 스테퍼 UI 제거는 PR2(별도). PR1~PR2 사이엔 스테퍼가 보이되 E에 안 써짐(inert).

## 후속
- PR2: 컨택 생산 스테퍼 제거. PR5: 비용 미기록 넛지. 결정 변경 시 새 ADR로 supersede.
