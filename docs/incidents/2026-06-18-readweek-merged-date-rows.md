# 2026-06-18 — 컨택관리 일별 read 가 병합 날짜 행을 누락

## 증상
- 전 사용자. 컨택관리에서 4채널(매입DB/직접생산/현수막/콜지기소) 일별값을 입력·저장 후 **이탈했다 복귀하면 매입DB 외 채널이 빈칸**으로 보임(시트엔 그대로 저장돼 있음). 예: 강구수 6/12 현수막 60 이 안 보임.

## 원인
- 시트 01 영업관리 일별 블록은 **하루 = 4행(채널)**, **날짜(C열)는 하루 첫 행(매입DB)에만** 있고 나머지 채널 행은 **셀 병합으로 빈칸**.
- `readWeek` 루프가 `dateRaw === undefined → continue` 로 **빈 날짜 행을 통째 스킵** → 직접생산/현수막/콜지기소 일별값이 read 결과에서 누락 → `loadDay` 필터에 안 잡혀 빈칸.

## 수정 (fix/readweek-merged-date-rows)
- 파서를 순수 함수 `lib/repo/week-parse.ts` `parseWeekRows(data, toISO)` 로 분리(테스트 가능 + sales.ts 500줄 cap 회복).
- **날짜 forward-fill**: 마지막으로 본 날짜(`lastISO`)를 유지 — 날짜 있으면 갱신, 없으면 직전 날짜 상속. **채널(D열)은 행마다 존재**하므로 그걸로 채널 판별. → 현수막 행이 위 매입DB 행의 6/12 를 상속 → 필터 매칭.
- 스킵 조건은 **채널 빈 행**으로 한정. #VALUE! tolerant(`numCell`)·zod safeParse 유지(이전 사고 가드 보존).

## 검증
- 단위테스트 `tests/repo/week-parse.test.ts`: 병합(빈 C) 입력에도 4채널 전부 파싱, 다음날 날짜 갱신, #VALUE!→0 보존, 채널 빈 행/첫 날짜 이전 행 스킵.
- 라이브(배포 후): 강구수 6/12 현수막 60·6/13 현수막 20 이 컨택관리에 그대로, 4채널 저장→이탈→복귀 시 값 유지.

## 재발 방지
- 파서 순수분리 + 단위테스트 박제(병합 케이스 회귀 방지).
- (대안 기록) 더 견고한 방식 = 행 인덱스로 좌표 계산(`dayIdx=floor(i/4)`, `channel=ORDER[i%4]`) — 시트 C열에 일절 의존 안 함. 현재는 병합 forward-fill 로 최소 변경, 4채널 고정순서 가정이 깨질 조짐 보이면 인덱스 방식으로 승급.
