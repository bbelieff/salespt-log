# 2026-06-23 — 영업관리 O5 승인 leak + 02 탭 세대 불일치

> **📄 요약**: "매출에서 승인 제거"(ADR-0026) 후속으로 시트 O5(수수료총합) 수식을 감사하니, 02 탭 구조가 시트 **세대별로 달라** 원래 작업 가정(`02 계약수납관리!D2:D3`)이 틀렸다. dry-run 으로 잡아 5개 시트만 정밀 교정.

## 발견 (dry-run/진단으로 잡음 — 무피해)
`fix/revenue-exclude-approved`(#451) [A] 전광판 매출 = JS SSOT 로 즉시 정상화(배포됨). [B] 시트 O5 install 을
`--apply` 전 **읽기전용 감사**했더니:

- **02 탭이 두 세대**: 구형 `02 계약관리`(승인=D1, **수납=D2**) / 신형 `02 계약수납관리`(승인=D2, **수납=D3**).
- 원래 작업 프롬프트 가정(`02 계약수납관리!D2:D3`)은 신형만 맞음. 단일 수식(`'02 계약수납관리'!D3`)을 구형에 설치하면
  그 탭이 없어 `#REF` 로 깨짐.
- 실제 O5 승인 leak = **구형 5개 시트**(`'02 계약관리'!D1` = 승인총액 참조): 김선주·김서준·최정한·황정환·박준영.
  나머지 59개는 이미 정상(수납 셀 참조).

## 조치
1. **#451 setup-formulas O5 install 은 안전** — installFormulas 가 구형 시트에선 `02 계약수납관리` read 에서 먼저
   throw 해 O5 블록까지 못 감 → 신형 시트(D3 정답)에서만 실행. 되돌릴 필요 없음(forward 온보딩용).
2. **기존 시트는 `scripts/fix-sales-o5-formula.mjs`** (탭 인식형, §2.5 가드, dry-run 우선)로 교정.
   구형→`'02 계약관리'!D2`, 신형→`'02 계약수납관리'!D3`. raw 값은 보존.
3. dry-run(전 시트) 2회 일치 확인 → `--apply` → 5개 시트 D1→D2 교체 완료. 59개 무변경.

## 재발 방지 (Hashimoto)
- 작업 프롬프트의 시트 좌표 가정은 **`--apply` 전 읽기전용 감사**로 실측 검증한다(이번처럼 세대 불일치를 잡는다).
- 라이브 시트 일괄 쓰기는 항상 dry-run → 결과 공유 → 확인 → apply 순서.
- SA 읽기 quota(분당 60)로 64시트 스캔 시 끊김 → 스크립트에 시트당 1.2s 지연.

## 남은 것 (별개·후속)
- 구형 `02 계약관리`!D2(수납총액)는 `=sum(...)` 로 **이월 제외 안 함**(2026-06-12 carryover-leak 의 구형판). 신형은
  setup-formulas 가 SUMIFS-이월제외(D3)로 설치. 구형 수납총액의 이월 제외는 별도 판단(영향 범위·활성 여부 확인 후).
