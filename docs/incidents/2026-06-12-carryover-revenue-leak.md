# 2026-06-12 — 이월 매출 leak (carryover-revenue-leak)

## 증상
6기 재참가자(조정욱) 클레임·이월 직후, 이월된 24건 계약의 수납액 합 **6,325,000원이
대시보드 수수료(C21)·총매출(D21)·영업이익에 합산**. 이월 깃발(02 AI=이월) 화면 뱃지도
계약 카드 접힘 상태에선 안 보였음.

## 진단 (실측)
| 항목 | 결과 |
|---|---|
| 04 AO=이월 / 02 AI=이월 깃발 | **100% 정상**(9/9·24/24) — 깃발 누락 아님 |
| 01 K/L/N/O 수식 AO 가드 | **없음** — #346 수식은 코드에만, 기존 시트 전파 미실행 |
| 누수 경로 | `02!D3 =sum(Q6:Q36,W:W,AC:AC)`(수납총액, **코드 미관리 원본 양식 수식**) → `01!O5` → 대시보드 C21/D21 → 전광판 |
| SummaryBar(일정·계약 매출 배너) | 04 수임비 직접 합산 — 코드 가드 없음(이월 계약 행 생기면 leak) |

## 수정
1. `setup-formulas`: **02!D3 이월 제외 SUMIFS** 추가(원본 Q 36행 한정 버그도 정상화) + 가드 단위테스트.
2. **전파**: installFormulas 를 검증 시트 → 조정욱(카나리아) → 아레나 전체에 실행(§2.5 pre-read — preserved 0, 사용자 값 비파괴). 조정욱 C21 **6,325,000 → 0** 실측.
3. SummaryBar 매출(수임+수수료 키)에 `구분≠이월` 가드, ContractRow **접힘 헤더에도** 이월 뱃지+흐림.
4. 깃발 backfill: 불필요(진단 결과 100% 정상).

## 교훈 — 이월 0건 카나리아의 한계
#346 카나리아는 이월 0건 상태라 "수식 가드가 실데이터를 실제로 거르는지"를 검증하지 못했고,
"코드 반영 ≠ 기존 시트 전파"라는 운영 갭도 드러나지 않았다.

**박제 규칙**:
- 집계·수식 가드 변경은 **이월(또는 해당 케이스) 실데이터가 존재하는 시트에서 수치 전/후
  실측**이 머지 조건. 0건 카나리아는 "에러 없음"만 증명할 뿐 "정확함"을 증명하지 못한다.
- 시트 수식 변경 PR 은 **기존 시트 전파 실행까지가 작업 범위** — "사용자가 나중에
  [ID로 수식 설치]" 로 미루지 않는다(이번 사고의 직접 원인).
- 코드 미관리 원본 양식 수식(02!D3 같은)도 집계 원천이면 setup-formulas 관리 대상으로 편입.
