## 1. 왜 (배경·급소)

10기 6명은 admin 기수생성 흐름으로 정상 등재됐지만, 생성 모달의 **날짜 입력이 자동화 조작으로
React 상태에 반영되지 않아** 서버가 "날짜 없음 → 시트 값 유지" 경로를 탔다(worklog ⑪ 자백).
그 결과 6개 시트가 0605 템플릿(=8기 사본)의 값을 그대로 물고 있다.

`영업관리!O1` 은 대시보드 `C33:H40` **주차 버킷의 앵커**다. 8/7 개막 후 기록이 6/12 기준으로
계산되면 9주차 밖으로 튀어 **전 지표가 0** 으로 보인다(AR-2b 진단 스크립트가 경고하는 그 사고).
또 `B3`(기수)는 앱 표시 기수의 **정본** — `lib/service/me.ts:403` 이 시트 값을 레지스트리보다
우선하므로, 두면 10기 6명이 앱에서 **"8기"** 로 표시된다.

## 3. 어떻게 (스크립트 안전장치)

`scripts/ops/finalize-cohort10.mjs` — dry-run 기본, `--execute` 로만 기록, `--verify` 는 읽기 전용.
1. 대상은 **레지스트리에서 발견**(시트ID 하드코딩 없음), 기대 6행·유일·공란 0 아니면 **중단**.
2. O1/O2 를 FORMULA + SERIAL 두 렌더로 pre-read — 수식/빈값/개막일 이전 날짜만 "템플릿 잔재"로
   판정해 덮어쓴다. 그 밖(개막일 이후 등 사람이 넣었을 값)은 **hold + 보고**(§2.5 사용자값 보존).
3. O1·O2 는 한 쌍으로만 기록(`planCourseDateWrite` 원자성 규칙), `USER_ENTERED`(시리얼 인식).
4. B3 은 수식이면 손대지 않고, C3 은 **빈값일 때만** 채운다(다른 이름 있으면 hold).
5. 시트 hold 인 행은 레지스트리 캐시도 함께 보류 — 캐시가 시트를 앞서지 않게.
6. 실행 후 전 시트·전 행 재실측 표 출력(3중 일치 카운트).

## 5. 적대 리뷰 반영 (4렌즈 워크플로우)

실행 전 검증에서 나온 **HIGH 3 · MED 4** 를 스크립트에 전부 반영했다:

| 지적 | 무엇이 위험했나 | 반영 |
|---|---|---|
| HIGH read 실패 삼킴 | `.catch(()=>[])` 가 읽기 실패를 "빈 셀"로 만들어 §2.5 보존 가드가 **반대로** 작동(사람이 넣은 값 덮어쓰기) | `ok:false` 로 올려 **읽기 실패 행은 무조건 hold** |
| HIGH 사후검증이 옛 스냅샷 | 완전 성공해도 항상 "레지스트리 0/6 ❌ exit 1" → 운영자가 실패로 오판해 `--allow-unexpected` 같은 위험 후속 | `verify()` 가 **재조회** |
| HIGH 기존 기록 미확인 | O1 을 옮기면 이미 적힌 기록의 주차 귀속이 통째로 밀린다 | **Phase 0 기록 탐지** 신설(수식·라벨 제외) → 기록 있으면 flip 보류 |
| MED B3 무조건 덮기 | `"PRM 10기"` 같은 사람이 넣은 라벨도 덮음 | 빈값·숫자기수(잔재)만 write, 그 밖 hold |
| MED 날짜 hold 인데 프로필은 씀 | "안 만진다"는 판정과 동작 불일치 | 날짜 hold → 프로필·캐시도 동반 보류 |
| MED 프로필 hold 가 캐시엔 미반영 | 시트는 보존하고 캐시가 화면을 이겨 무의미해짐 | hold 집합을 합쳐 캐시에서도 제외 |
