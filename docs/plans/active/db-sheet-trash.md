# DB관리시트 휴지통 · 공급처 일괄 바꾸기 (2026-10-26)

belie: [2] 「삭제 후 같은 DB를 다시 등록하려니 이미 등록된 업체」 [3] 「공급처를 체크해서 유형부터 이름까지 일괄로」 [4] 「10초가 아니라 휴지통에서 가져오기, 휴지통 비우기」.

## [2] 원인
여러 줄 삭제가 화면에서만 숨기고 10초 뒤에 서버에 확정했다. 그 사이 같은 DB를 등록하면 서버엔 남아 있어 중복 검사에 걸렸다(캡처의 이름 없는 줄 = 지우는 중인 DB).

## 바꾼 것
- 삭제 = 즉시 서버에서 휴지통으로. 지우기 직전 DB 행·상담 기록(db_sheet_contacts)·이력(db_sheet_history)을 `sheet_rows`(tab `db_sheet_trash`, mirror_pending=false)에 그대로 보관하고, 기존처럼 활성 행·STEP 2 기여분은 정리. → 중복 검사에서 빠진다.
- 되돌리기: 같은 id 로 행·상담 기록·이력을 다시 넣고 STEP 2 기여분(_recorded 기준)을 되살린다. 같은 업체가 이미 있으면 막고 「그래도 되돌리기」. 미팅 연결 흔적(`_dbSheetLeadDeleted`)은 지운다.
- 영구 삭제·비우기: 보관본만 지운다(되돌릴 수 없음, 확인 상자).
- 공급처 바꾸기: 체크한 줄에 유형·공급처(빈 칸은 그대로), 줄마다 바로 저장(유형이 바뀌면 STEP 2 유입 칸도 서버가 옮김). 미팅 연결 DB의 유형은 STEP 3 이 정본이라 바꾸지 않고 알린다.
- 10초 되돌리기 줄·「변경사항」 이탈 확인은 없앴다.

## 확인
- 저장소 시험(pglite): 삭제 → 휴지통 목록 → 같은 DB 다시 등록 가능 → 되돌리기 시 중복 막힘·허용 → STEP 2 유입 되살아남 → 비우기.
- 스토어·화면 시험, check.sh.
- 되돌리기: squash revert 1회(휴지통에 쌓인 보관본은 sheet_rows 에 남지만 화면이 안 읽을 뿐 — 필요하면 tab=db_sheet_trash 행 삭제).
