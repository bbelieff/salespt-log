# 업체정보 [재무] 백만원 · 연도별 매출 표 (PR-7)

## 1. Scope (belie 확정 2026-09-28 — "오케이 백만원으로 확정")

A. [재무] 금액 19칸 = 백만원(소수 한 자리, 손익 3칸만 음수). 입력 중 소수 한 자리까지, blur 에 쉼표, "백만원" 표시, "약 2.5억" 도움말. 문서(원·천원)는 가져올 때 백만원으로 바꾼다(`wonToMillion`, 반올림). 옛 자유 글은 저장값을 바꾸지 않고 안내 + 「백만원으로 바꾸기」.
B. 「연도별 매출」 한 표(상반기 · 하반기 · 합계 × Y~Y-3). 반기가 있으면 합계 자동(apply 에서 저장), 둘 다 비면 합계 직접 입력. 옛 「반기별 매출」 묶음 삭제.
C. 새 키 `매출기준연도` — Y 줄 연도. 비면 오늘 연도로 보이고 재무 칸을 처음 고칠 때 저장. 모든 연도 라벨(편집기·TXT·자동입력 비교표)과 문서 연도 → 칸(slot = 기준 − 문서 연도)이 이 값을 쓴다.
D. 부채비율·이자보상배율·당기순이익률 자동(읽기 전용), 재무제표 파서는 더 이상 비율을 채우지 않는다.
E. [기업정보] 업종·업태·주생산품목 줄 ↔ 4대보험 직원 자리 바꿈(TXT 동일).
F. [대표자] 생년월일 칸 삭제(값 유지), 이름·주민등록번호 / 신용점수·연락처 한 줄. 주민등록번호가 비면 생년월일로 "880124-" 를 보여 주고 편집 때만 저장.
G. 저장: 04 **CD** · 06 **BL**(기존 열 이동 없음).

## 2. 저장 모양·좌표

- 금액 정본 = `"250.1"` · `"1,234"` · `"-3.2"` · `"0"`(끝 ".0" 없음, "-0" 없음). 계산은 십만원 정수(tenths)로 — 소수 오차 없음.
- `매출기준연도` = 04 CD(81) · 06 BL(63). 확장4 `COMPANY_FIELDS_EXT4` 로 모든 경로를 넓혔다: 스키마 · 04 코덱(apostrophe) · stripUserEnteredEscapes · 04 읽기 폴백 · 헤더 빈 셀 보강(AU1:CD1) · 쓰기/지우기 AU:CD · 06 행 빌더/헤더/읽기 · DB 열문자 복원(04 A~CD · 06 BL) · 이월(확장 읽기·payload·시트 쓰기) · TXT.
- **자율결정 — 04 읽기 폴백은 4단계**: A:CD → A:CC → A:BN → A:AS. CD 실패 때 곧장 BN 으로 가면 CC 까지만 넓힌 시트(#1068 이후 쓴 적 있는 시트)에서 확장3 값이 읽기에서 사라진다(#1068 과 같은 원칙).
- **자율결정 — 이월 T~AN 도 apostrophe**: 이월 시트 쓰기가 T~AN(과년도매출·금년도매출 포함)을 그대로 USER_ENTERED 로 써서 "1,234"·"250.1" 이 숫자로 바뀔 수 있었다. meetingToRow 와 같은 규약(문자열은 `'` 접두)으로 맞췄다.

## 3. 옛 값 보존 (데이터 손실 0)

| 상황 | 화면 | 저장 |
|---|---|---|
| 옛 자유 글 금액("25' 250백만"·"3,200만"·"-3,200만") | 글 그대로 + "글로 적힌 값이에요 — 계산에는 X백만원으로 써요" + 「백만원으로 바꾸기」 | 열기만 해선 안 바꿈. 버튼 = 그 칸만 정본으로, "6월" 같은 표시가 있던 글은 업체기타메모에 "<라벨> 원래 적은 값: …" |
| 못 읽는 글("모름") | "읽을 수 없어 계산에서 빠져요" | 그대로 |
| 단위 없는 옛 숫자("25' 250") | 백만원으로 읽음(칸 단위) | 그대로 |
| 반기 합이 덮게 될 사용자 합계(금액이 다르거나 반기로 안 드러나는 "3월" 같은 표시) | "이전 합계 … — 반기 합과 달라 저장할 때 업체 기타메모로 옮겨 둬요" | **자율결정**: apply 때 업체기타메모에 "매출 Y-1(2025) 이전 합계: …" 로 옮긴 뒤 반기 합 저장. 자동 합계가 저장한 값·같은 금액의 모양 차이는 옮기지 않음. **리뷰 반영**: #1068 자동입력 모양("25' 247백만" = 백만 반올림 ±0.5백만, "26' 6월 …" + 상반기만 / "12월" + 두 반기)도 같은 값으로 봐 옮기지 않음. 문서 자동입력이 합계 칸을 직접 체크해 바꾼 경우 옛 값은 옮기지 않되, 고른 문서 값이 반기 합과 다르면 그 값을 "매출 Y-1(2025) 합계(반기 합과 달라 옮김): …" 로 남긴다(버려지지 않게) |
| 반기가 다시 모두 비었을 때 | 합계는 직접 입력 칸 | **리뷰 반영(자율결정 교체)**: 자동으로 적었던 합계(반기 합과 같은 정본 숫자)는 지운다 — 치다 지운 "1" 이 합계로 남아 증가율·당기순이익률을 틀리게 만들던 문제. 그 줄의 옛 합계를 기타메모로 옮겨 둔 줄이 있으면 되돌리고 그 메모 줄을 뺀다. 반기 합과 다른 합계는 그대로 |
| 원 단위로 적은 큰 숫자("250,000,000" — #1068 까지 "쉼표 숫자 = 원") | "원 단위로 적은 숫자 같아요 — 계산에는 250백만원으로 써요" + 「백만원으로 바꾸기」 | **리뷰 반영**: 1,000,000 이상(백만원으로 1조 이상)은 원으로 읽는다. 저장값은 그대로 |
| 괄호 음수("(1,234)" — 재무제표 표기) | 손익 칸: 음수 옛 글 안내·바꾸기, 그 밖 칸: 읽을 수 없는 글 | 그대로 |
| 주민등록번호를 지움 | 칸이 빈 채로 | **리뷰 반영**: 생년월일(화면에 없음)도 함께 지운다 — 안 그러면 apply 마다 생년월일에서 다시 채워져 지울 수 없었다 |
| 옛 비율 글("120%") | 계산값 + "이전에 적은 값: 120%" | 계산값이 있으면 다음 편집 때 계산값으로(지시대로). **자율결정**: 계산할 금액이 없으면 옛 글은 그대로 두고, 자동으로 저장했던 값만 비운다 |
| 대표자생년월일 | 칸 없음(값 유지). 주민등록번호가 비면 "880124-" 표시(자동으로 채운 값) | 편집 때 apply 가 주민등록번호 앞자리를 저장. TXT 는 주민등록번호가 비었을 때만 생년월일 줄 |

## 4. 계산·저장 시점

- `lib/service/company-finance.ts` `deriveCompanyInfo(prev, next, today)` = 편집기 `apply()`(직접 입력·선택·문서 자동입력 공통): 기준 연도(비었고 재무 입력 칸이 바뀌거나 **재무 값이 있으면** 오늘 연도 — 리뷰 반영: 옛 업체의 다른 칸만 고쳐도 합계·증가율과 함께 저장돼 해가 바뀌어도 칸이 안 밀림) → 반기를 모두 지운 줄의 자동 합계 정리 → 덮이는 합계 보존 → 합계 → 증가율 → 비율 → 주민등록번호 앞자리. 열기만 해선 아무것도 저장하지 않는다.
- 증가율 = 줄 합계(반기 합 또는 합계 칸)에서. Y 상반기만 있으면 Y-1→Y 설명에 "Y(2026)는 상반기 매출만 있어 낮게 보일 수 있어요"(기준 연도로 — '올해' 아님).
- 비율 소수 한 자리 반올림은 금액과 같이 0 에서 먼 쪽(-2.45 → -2.5). 옛 비율 글은 숫자로 비교("120%" = "120.0%" 면 "이전에 적은 값" 안 보임).
- 비율: 부채비율 = 부채총계÷자본총계×100("120.0%", 자본총계 ≤ 0 → "자본잠식"), 이자보상배율 = 영업이익÷이자비용("2.4배", 이자비용 없음·0 → ""), 당기순이익률 = 당기순이익÷(결산연도 줄 합계, 기준 연도로 칸을 찾음)×100.
- TXT 내보내기 = `companyInfoForExport`(저장할 때와 같은 계산 + 화면의 기준 연도).

## 5. 문서 자동입력

- 부가세: 반기·연도 합계·면세 = 백만원 + `sourceWon`(원문 원). 칸 = 기준 연도 − 문서 연도, 칸 밖 연도는 "YYYY년 금액은 매출 칸(…) 밖이라 넣지 않았어요". 올해 부분 연도는 "N월까지 신고 금액" 경고, 지난해 부분 연도는 기존 "일부만" 경고. 면세 연도는 참고 정보로.
- 재무제표: 금액 백만원(천원 문서는 ×1,000 뒤) + `sourceWon`, 매출 = 기준 연도 칸(결산연도 = 기준 연도면 Y). 비율 3칸은 채우지 않음.
- 비교표: 금액 칸 "250.1백만원 (원문 250,123,456원)", 지금 값도 숫자면 "백만원". 업체에 기준 연도가 없고 금액 칸을 반영하면 `매출기준연도`(파서가 칸을 고른 해)를 함께 넣는다.
- 옛 `formatManwon`·`formatBaekman`(lib/document-ocr/amount.ts)은 쓰는 곳이 없어 지웠다(`groupThousands` 만 남김 — 임차 원 금액·원문 표기).

## 6.5 남은 위험

- **단위 없는 옛 숫자**: 지시대로 칸 단위(백만원)로 읽는다. 단 1,000,000 이상은 원으로 본다(리뷰 반영) — 그래서 "500,000"(50만원을 원으로 적은 값)처럼 1조 아래의 원 숫자는 여전히 백만원(5,000억)으로 읽힌다("약 5,000억" 도움말로 드러남). 저장값은 바뀌지 않는다.
- **면세 수입금액 연도**: 부가세 자동입력은 지시(정본 백만원 숫자)대로 값만 넣고 연도는 비교표 참고 정보로만 보인다 — 저장값엔 연도가 없다(#1068 은 "25년 3,200만" 처럼 붙였음).
- **좁은 칸**: 320px 팝업에서 표 칸 58px — "12,345.6" 같은 긴 숫자는 칸 안에서 끝이 가려질 수 있다(넘침 없음, 포커스하면 보임).
- **반기 합이 합계를 덮음**: 반기 칸에 값이 있는 줄은 합계를 직접 고칠 수 없다(지시). 다른 금액의 옛 합계는 기타메모로 옮긴다.
- **해 바뀜**: 기준 연도를 한 번 저장한 업체는 해가 바뀌어도 라벨이 그대로다(의도 — 값이 칸을 따라 움직이지 않게). 새해에 칸을 옮기려면 학생이 기준 연도를 바꾸고 값을 옮겨 적어야 한다.
