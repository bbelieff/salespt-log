# 사용 가이드 → 네이버 카페 게시판

**요청**: belie 2026-09-07 — "팝업의 사용방법 확인하기가 노션으로 가는데 노션이 너무 오래됐다"

## 왜 카페인가

처음엔 「카페는 게시판이라 답을 찾으러 간 사람에게 목록이 뜬다 + 가입 벽」을 이유로
노션 갱신을 권했다. **두 전제가 다 틀렸다** —

1. belie 확인: **경영일지 사용자는 전원 카페 회원**이다 → 가입 벽 없음.
2. belie 확인: 그 게시판에 **지금 노션보다 자료가 많다** → 최신성도 카페가 낫다.

낡은 노션을 따로 갱신하면 **관리 대상이 둘로 늘어난다**(어제 붙인 업무매뉴얼 노션까지 셋).
이미 살아 있는 곳으로 보내는 편이 낫다.

**목적지**: `https://cafe.naver.com/f-e/cafes/31423785/menus/152?viewType=L`

## 왜 env 에서 코드로 내렸나

이전엔 `NEXT_PUBLIC_GUIDE_URL` 환경변수였고 그 값은 **VPS 에만** 있었다 — 주소를 바꾸려면
서버에 들어가야 했다. 그런데 `NEXT_PUBLIC_*` 은 **빌드할 때 값이 박히므로** env 로 둬도
재배포가 필요하다. 즉 **env 로 얻는 이점이 없으면서 바꾸는 비용만 컸다.**

이제 `lib/config/links.ts` 의 `GUIDE_URL` 이 **유일한 정본**이고, PR 한 줄로 바뀌며 이력이 남는다.

### 「env 우선」을 하루 만에 되물렸다 (2026-09-07 2차)

처음엔 env 가 있으면 그쪽이 이기게 뒀다 — "서버에서 급히 덮을 여지". 배포하고 확인해 보니
**VPS `.env` 에 남아 있던 옛 노션 주소가 조용히 이겨서** 여전히 노션으로 갔다.
여지가 아니라 **함정**이었다.

애초에 env 로 둘 이유가 없었다 — `NEXT_PUBLIC_*` 은 **빌드할 때 값이 박히므로** 서버에서
고쳐도 재배포가 필요하다. 서버 들어가 고치고 재배포할 바엔 PR 한 줄이 빠르다. 즉
**긴급 수단으로서 이점은 0 이고, 낡은 값이 조용히 이기는 위험만 있었다.** 그래서
`guideUrl()` 에서 env 참조를 **제거**했다. 테스트가 재발을 막는다.

(VPS `.env` 의 옛 줄은 이제 아무 데도 안 쓰이므로 남아 있어도 무해하다. 청소는 선택.)

## 영향 범위

`guideUrl()` 을 쓰는 **세 곳이 동시에** 바뀐다:
- 시작 팝업(`NoticePopup`) 「📚 사용 가이드 보기」
- 새소식 페이지(`/updates`)
- 상단 헤더 메뉴(`TopHeader`)

셋 다 `target="_blank"` — 카페로 나가도 앱 탭은 남는다.

## 검증 못 한 것 (정직 고지)

**링크가 실제로 열리는 화면을 나는 못 봤다.** `cafe.naver.com` 이 내 도구(브라우저·웹 가져오기)
양쪽에서 도메인 단위로 차단돼 있다 — 로그인 문제가 아니라서 쿠키가 있어도 안 된다.
**수강생 브라우저에는 아무 영향 없다**(차단은 내 도구에만 걸린 것). 배포 후 belie 가 폰에서
한 번 눌러 ①게시판이 뜨는지 ②네이버 앱으로 튕기지 않는지 확인이 필요하다.
