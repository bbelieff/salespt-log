# 영업기록 없이 추가 업체 ↔ 미팅 연결 (2026-09-29, belie)

## 왜
「영업기록 없이 업체추가」로 만든 02 행(AK=`manual:…`)은 링크 검색에서 일부러 빠진다. 그래서 나중에 같은 업체를
일정·계약에서 계약으로 바꾸면 **02 행이 하나 더 생겨 수임비가 두 번 잡혔다**(매출 이중계상).

## belie 결정
- 양방향: ① 일정·계약에서 계약 전환 시 같은 이름(띄어쓰기·(주) 무시, 포함 관계 포함) 수동 업체가 있으면 연결 팝업
  ([연결하기]/[따로 등록]) ② 실무/수납 1뎁스 `영업기록 없음 ＋` → 미팅 고르기 → 같은 팝업.
- 연결하면 **계약일 = 미팅 날짜**(앱의 계약일 규칙).
- 값이 다르면 **최근에 기록한 쪽을 기본**으로, 칸마다 선택 가능(업체명·수임비·업체정보 칸별).

## 구현
- 서비스 `linkMeetingToContract`: 같은 02 행을 재사용(새 행 0) — `relinkContractRow`(C/D/E + AK=미팅 id, 이월 미팅이면 AI/AJ)
  → 미팅 `상태 계약·계약여부·수임비·업체명·업체정보(합친 값)` → 06 업체정보 키 이동(+DB 옛 키 정리) 후 합친 값 저장
  → 할일·History `contractRef`·업체명 새 키로. 02·미팅 실패는 오류, 06·할일 실패는 `failures` 로 알림.
- "최근" = `sheet_rows.updated_at`(행 마지막 DB 저장 시각, `readRowsUpdatedAt`). 사람 편집 시각이 따로 없어 근사 —
  수렴·백필 잡도 갱신할 수 있다. 모르면 실무/수납 쪽 기본. 화면은 기본값만 정하고 사용자가 고른다.
- 거절: 이미 연결된 행, 다른 업체에 이미 붙은 미팅, 미팅 날짜 없는 미팅. 목록은 취소·연결된 미팅 제외.
- API: `GET/POST /api/contract-payment/[row]/link-meeting`, `GET /api/meetings/linkable`.

## 범위 밖(자율결정)
- 연결 끊기(되돌리기) 버튼은 넣지 않았다 — 끊으면 미팅은 계약인데 02 링크가 없어 다음 계약 저장 때 새 행이 생긴다.
  필요하면 미팅 상태까지 함께 다루는 별도 카드로.
- 이름 비슷한 수동 업체가 여럿이면 첫 번째만 제안한다.
