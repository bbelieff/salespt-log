# 시트 없는 수강생 고유 번호 — 케이스별 단계 독립

belie 지시(2026-11-10): "조심스럽게 — 샌드박스에서 테스트 후 계정 케이스로 나누고, 케이스별 테스트가
통과하면 그때 하나씩 시트로부터 독립시키자."

## 1. 핵심 설계 (ADR-0038)
- 고유 번호 = DB `spreadsheet_id` 값. 기존 시트 ID 는 그대로(데이터 이동 0), 새 시트 없는 수강생은 `local:<uuid>`.
- 빈 번호 금지(섞임 사고). 시트 API 단일 관문이 `local:` 을 네트워크 전에 막는다.

## 3. 단계와 통과 조건
| 단계 | 할 일 | 통과 조건 | 상태 |
|---|---|---|---|
| 1 | 번호 규칙·시트 관문·케이스 시험(샌드박스, 합성 데이터) | `tenant-key`·관문·케이스 A~F·I·X 시험 초록, 기존 동작 변화 0 | 완료 #1378 |
| 2 | 시트 없는 번호가 지나가는 화면·API 전수 점검 — 시트를 읽던 곳(프로필 날짜 `readBundle`, 미러, 전광판, 상단 「시트 열기」 링크, 기수 생성)이 `hasRealSheet` 로 건너뛰게 | 케이스 B 사용자로 주요 화면 API(대시보드·DB관리·일지·일정·계약·금고·지출·할 일) 샌드박스 시험 초록, `[no-sheet]` 오류 0 | **완료** — 아래 §6 |
| 3 | 실전 1명: 0기에 합성 시험 수강생 1명을 `local:` 번호로 생성 → 로그인·저장·새로고침 확인 | 운영 화면에서 저장/재조회 일치, 시트 호출 0, 다른 수강생 영향 0 | 완료 #1399 — 운영 「보고 편집」 확인 |
| 4 | 기수 생성을 DB 만으로(#798 재작성: 빈 번호 → `local:` 번호) | 새 기수 생성 시험·연습 기수 1회 실측 | **구현 완료 — 운영 실측 대기** (§8) |
| 5 | 기존 시트 수강생 독립 = 기수 하나씩 시트 미러 끄기(BBE-69 S2 를 기수 단위로) | 기수별 관찰 1일, 화면 숫자 변화 0 | 대기 |

각 단계는 앞 단계 통과 후에만 시작한다. 실패하면 그 단계 PR 만 revert.

## 5. 이미 알게 된 위험
- `sheet_rows` 는 (번호, 탭, 행키) 로만 나뉜다 — 빈 번호면 서로 덮어쓴다(시험 X 로 재현). #798 은 그대로 병합 금지.
- 레지스트리 쓰기는 아직 시트 먼저 → DB 순서. 시트 없는 수강생은 DB 직접 쓰기가 필요하다(4단계).
- 레지스트리 DB 읽기가 실패하면 시트로 폴백 → 그 순간 시트에 없는 수강생은 로그인 안 됨(일시적). 3단계 전에 대응 결정.

## 8. 4단계 — 시트 없이 기수 만들기 (2026-11-11)
#798(빈 번호로 DB insert)은 기록 섞임 위험으로 보류했고, 같은 목적을 `local:` 번호로 다시 만들었다.
- 관리자 「기수 만들기」 팝업에 **「시트 없이 만들기」** 체크(숫자 기수만). 체크하면 시트 복제·폴더 매칭 없이
  DB 명단에 사전등록 행(이메일 빈칸·`local:` 번호·수강 날짜)만 만든다(`cohort-create-sheetless.ts`).
- 막는 경우: 아레나 · 시트 정본 기수(`isDbReadPilot` 아님) · 수강시작일 없음 · 명단 DB 읽기 꺼짐.
  같은 (기수, 이름)이 명단에 이미 있으면(시트 사전등록 행 포함) 건너뜀 — 시트 행과 같은 자연키를 DB 에서 덮으면
  시트→DB 백필이 번호를 지운다.
- 명단 쓰기 DB 판(`users-sheetless.ts`): 클레임(사전등록 행에 이메일 채우기·직원 공유 추가)·한 칸 고치기
  (승인·담당·팀·유보·부서)·정렬·삭제. 시트 명단에 없는 시트 없는 행일 때만 동작 — 시트 수강생 경로 불변.
- 시험: `tests/service/sheetless-cohort-create.pglite.test.ts` 7개 — 생성→클레임→팀·담당·정렬→삭제, 명단 시트 쓰기 0.
- 아직 안 됨: 아레나 시트 없는 생성(회사 폴더·명단 시트 얽힘), 시트 없는 수강생의 아레나 재참여(이전 행 보관),
  아레나 전광판 DB 집계. 운영 실측 = 연습/시험 기수에 이름 1개로 「시트 없이 만들기」 → 명단 표시 확인.

## 9. 5단계 — 기수별로 시트에서 떼어 내기 (2026-11-11)
스위치: `lib/config/sheet-detach.ts` `SHEET_DETACHED_COHORTS`(지금 빈 목록 = 동작 변화 0) · 판정 `lib/repo/sheet-detach.ts`.
떼어 낸 기수 수강생은 시트 번호를 그대로 쓰지만 **미러 7종을 안 보내고, 시트 보충 읽기도 안 한다**
(얼어붙은 시트에서 DB 에서 지운 행이 되살아나는 것을 막기 위해 둘을 같이 끈다). 행 번호는 DB 가 정한다.
일부러 남긴 시트 읽기: 업체정보(옛 개명 행의 내용은 시트에만 있다)·수강 날짜(DB 없을 때) — 둘 다 안 변하는 값.

**넣기 전 확인(기수마다)**
1. 카페봇이 그 기수 개인 시트로 과제를 채점하지 않는다 — `HW_ACTIVE_COHORTS`·`JOURNAL_SHEETS` 밖.
   (2026-11-11 기준 활성 11·12·13기 → **넣으면 안 됨**. 숫자 점수는 한 번 박히면 영구라 낡은 시트로 매기면 되돌릴 수 없다.)
2. 아레나 기수가 아니다(전광판이 시트를 읽음). 아레나 행과 시트를 같이 쓰는 수강생은 자동으로 제외된다.
3. 그 기수 DB↔시트 대조 차이 0 — 보충 읽기를 끊으면 DB 에 없는 시트 행은 앱에서 안 보인다.
4. belie 확인: 그 기수 구글 시트를 직접 여는 사람(트레이너·수강생)이 낡은 값을 보게 된다.

`tests/repo/sheet-detach.test.ts`(판정 규칙 6). 되돌리기 = 목록에서 빼는 PR(그 사이 시트는 낡아 있음 — 필요하면 재백필).
