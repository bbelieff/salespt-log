# 시트 없는 수강생 고유 번호 — 케이스별 단계 독립

belie 지시(2026-11-10): "조심스럽게 — 샌드박스에서 테스트 후 계정 케이스로 나누고, 케이스별 테스트가
통과하면 그때 하나씩 시트로부터 독립시키자."

## 1. 핵심 설계 (ADR-0038)
- 고유 번호 = DB `spreadsheet_id` 값. 기존 시트 ID 는 그대로(데이터 이동 0), 새 시트 없는 수강생은 `local:<uuid>`.
- 빈 번호 금지(섞임 사고). 시트 API 단일 관문이 `local:` 을 네트워크 전에 막는다.

## 2. 계정 케이스
| # | 케이스 | 오늘 모습 | 시트 독립 순서 |
|---|---|---|---|
| A | 기존 시트 수강생(DB 기수 0·4·6·7·8·9·10·11·연습·아레나) | 시트 ID 번호, DB 정본 + 시트 미러 | 5단계 — 기수별로 미러 끄기 |
| B | 시트 없는 새 수강생 | 없음(이번에 생김) | 2~4단계의 주인공 |
| C | 한 번호를 여러 이메일이 공유(직원·가족) | 같은 시트 ID | B 와 함께 |
| D | 숫자기수 + 아레나 재참여(행 2개) | 아레나 행 우선 | 아레나 생성 경로 별도(4단계 뒤) |
| E | 트레이너·관리·관리자 | 번호 "" (기록 통 없음) | 변화 없음 |
| F | 준비행(이메일 빈칸, 본인 연결 전) | 번호 있음·이메일 "" | B 의 생성 경로에서 함께 |
| G | 0기 GM 시험 계정 | DB 기수 | 3단계 첫 실전 대상 |
| H | 레거시 1·2·3·5기 | 시트 정본 | 범위 밖(별도 트랙) |
| I | 시트 없는 수강생 둘 | — | 기록 분리 필수 |

## 3. 단계와 통과 조건
| 단계 | 할 일 | 통과 조건 | 상태 |
|---|---|---|---|
| 1 | 번호 규칙·시트 관문·케이스 시험(샌드박스, 합성 데이터) | `tenant-key`·관문·케이스 A~F·I·X 시험 초록, 기존 동작 변화 0 | **이번 PR** |
| 2 | 시트 없는 번호가 지나가는 화면·API 전수 점검 — 시트를 읽던 곳(프로필 날짜 `readBundle`, 미러, 전광판, 상단 「시트 열기」 링크, 기수 생성)이 `hasRealSheet` 로 건너뛰게 | 케이스 B 사용자로 주요 화면 API(대시보드·DB관리·일지·일정·계약·금고·지출·할 일) 샌드박스 시험 초록, `[no-sheet]` 오류 0 | 대기 |
| 3 | 실전 1명: 0기에 합성 시험 수강생 1명을 `local:` 번호로 생성 → 로그인·저장·새로고침 확인 | 운영 화면에서 저장/재조회 일치, 시트 호출 0, 다른 수강생 영향 0 | 대기(실데이터 추가 — 합성 계정) |
| 4 | 기수 생성을 DB 만으로(#798 재작성: 빈 번호 → `local:` 번호) | 새 기수 생성 시험·연습 기수 1회 실측 | 대기 |
| 5 | 기존 시트 수강생 독립 = 기수 하나씩 시트 미러 끄기(BBE-69 S2 를 기수 단위로) | 기수별 관찰 1일, 화면 숫자 변화 0 | 대기 |

각 단계는 앞 단계 통과 후에만 시작한다. 실패하면 그 단계 PR 만 revert.

## 4. 샌드박스
- 합성 데이터 pglite 시험: `tests/repo/sheetless-account-cases.pglite.test.ts`(케이스 표와 같은 기호).
- 실데이터 모양 확인이 필요하면 `scripts/ops/masked-snapshot.mjs` → `sandbox-load.mjs`(개인정보 가린 사본, 로컬 PGlite) — 2단계에서 사용 검토.

## 5. 이미 알게 된 위험
- `sheet_rows` 는 (번호, 탭, 행키) 로만 나뉜다 — 빈 번호면 서로 덮어쓴다(시험 X 로 재현). #798 은 그대로 병합 금지.
- 레지스트리 쓰기는 아직 시트 먼저 → DB 순서. 시트 없는 수강생은 DB 직접 쓰기가 필요하다(4단계).
- 레지스트리 DB 읽기가 실패하면 시트로 폴백 → 그 순간 시트에 없는 수강생은 로그인 안 됨(일시적). 3단계 전에 대응 결정.
