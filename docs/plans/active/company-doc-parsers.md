# 업체정보 「문서로 자동입력」 — 서류 파서 4종 (PR-5)

## 1. Scope

- 파서 4개를 만들어 `registry.ts` `PARSERS` 에 등록한다. 팝업·비교표·기본 체크 규칙(PR-4)은 그대로.
- 등록 후 "이 문서는 곧 지원돼요" 상태는 없어진다. 등록 안 된 종류는 "모르는 문서" 뿐이라 팝업은 종류를 고르라고 안내한다.
- 금액 표기 헬퍼 중복(파서마다 따로 만든 만원·백만 포맷터)은 `lib/document-ocr/amount.ts` 하나로 합쳤다.

## 2. 서류별 채우는 칸

| 서류 | 칸 | 모양 |
|---|---|---|
| 신분증(주민등록증·자동차운전면허증) | 대표자이름 · 대표자생년월일 · 주민등록번호 · 자택주소지 | "80.01.01" · **"800101-" 만** · 주소 두 줄까지 이어 붙임 |
| 부가세 과세표준증명 | 반기별매출 · 금년도매출 · 과년도매출 · Y2 · Y3 · 면세수입금액 | "25년 상반기 1.2억"(최신 먼저, 여러 줄) · "26' 6월 100백만" · "25' 250백만" · "25년 3,200만" |
| 재무제표(표준재무제표증명) | 결산연도 · 과년도매출(결산연도에 맞는 Y-1/Y-2/Y-3 칸, 3년 넘으면 생략) · 영업이익 · 당기순이익 · 이자비용 · 자산총계 · 부채총계 · 자본총계 · 부채비율 · 이자보상배율 · 당기순이익률 · 매출증가율 | 금액 "3,200만"/"-3,200만" · "122.2%" · 자본≤0 이면 "자본잠식"+경고 · "2.4배"(이자비용 0/없음이면 비움) |
| 임대차계약서 | 소재지 · 임차보증금 · 임차월세 · 임차면적 · 소유여부 | "1,000만" · "50만"(부가세 별도면 경고) · "33㎡(10평)"(1평=3.3058㎡ 환산) · "임차 : 보 1000만, 월 50만". 계약기간·임대인·용도는 읽지 않음(belie 결정) |

- 부가세: 같은 기간이 여러 번이면 수정 > 확정 > 예정 하나만. 확정(1~6월)이 예정(1~3월)을 품으면 확정만. **자율결정**: 기간이 서로 안 겹치는 예정(1~3월)+확정(4~6월) — 법인처럼 확정신고가 예정 뒤 3개월만 담는 경우 — 는 더한다(확정만 쓰면 반기 매출이 절반으로 줄어든다). 날짜 없이 "1기 예정/확정" 표기만 있으면 지시대로 확정만. 끊어진 줄에서 이어 읽은 금액은 신뢰도 0.6 + 경고.
- 재무제표: "(단위: 원/천원/백만원)" 을 읽어 환산, 없으면 원으로 읽고 경고. 과목명은 번호를 뗀 뒤 **시작**이 맞을 때만(상품매출액·부채와자본총계 오인 방지). 자산총계 ≠ 부채+자본(1% 초과)이면 세 칸 신뢰도 0.4.
- 임대차: "금 일천만원정"·"金 10,000,000원"·"₩10,000,000"·"1억 2천만원" 을 읽는다. 서로 다른 금액 후보가 여러 개면 첫 값 + 신뢰도 0.4 + 경고.

## 3. 금액 표기 — 한 가지 (`lib/document-ocr/amount.ts`)

- `formatManwon`(새 금액 칸 전부): 만 원 반올림, 쉼표. 1억 이상은 억을 앞에 — 억 아래가 천만 단위로 떨어지면 "1.2억", 아니면 "1억 2,500만"(반올림으로 금액이 바뀌지 않게). 음수 "-3,200만", 1만 미만 "5,000원", 0 "0원". `{ sep: false }` = 소유여부 문구용 "1000만".
- `formatBaekman`(기존 매출 칸): "250백만".
- **자율결정**: 부가세 파서 초안은 1억 이상을 0.1억으로 반올림("1억 2,500만" → "1.3억"), 재무제표 초안은 억 없이 "250,000만", 임대차 초안은 "1억 2,000만" 이었다. 한 모양으로 합치며 "정확도 유지 + 예시 '1.2억' 유지" 규칙으로 정했다. 되돌리기 = `amount.ts` 한 함수.

## 4. 개인정보 — 뒷자리·면허번호는 파서 밖으로 못 나간다

1. 팝업은 OCR 원문을 state 에 넣기 전 `redactOcrText` 로 가린다: 13자리 번호는 법인등록번호(라벨 값)만 남기고 `앞6-*******`, 운전면허번호(옛 양식·지역명 포함, 숫자 사이 공백 포함)는 통째로, **이번 PR 추가** — 숫자 사이에 공백이 낀 대시형 주민등록번호("800101 - 1 234 567")도 가린다. 면허번호 식은 `DRIVER_LICENSE_ID` 하나를 신분증 파서와 같이 쓴다.
2. 신분증 파서는 받은 글에서 면허번호·면허/식별번호 라벨 값을 먼저 지우고, 주민등록번호에서 앞 6자리와 7번째 자리(세기 판정용, 반환 안 함)만 꺼낸 뒤, 번호를 모두 지운 글로 이름·주소를 읽는다. 뒷자리 사이 공백이 여러 칸이어도 같은 줄이면 통째로 지운다. 마지막으로 주민등록번호 칸 외 값에서 7자리 이상 숫자를 한 번 더 지운다.
3. 주민등록번호 칸 값은 `normalizeRrnFront` → "NNNNNN-". 반영 직전 `diff.ts` `sanitizeForKey`, 서버 zod transform 이 한 번 더 자른다(PR-3/PR-4).
4. 다른 파서 3종도 13자리 번호를 원문에서 지운 뒤 읽는다. 경고 문구는 고정 문장이라 원문 숫자가 들어가지 않는다.
- 테스트: `tests/document-ocr/parse-id-card.test.ts`(값·경고·문서경고 JSON 에 뒷자리·면허번호가 대시·공백을 빼도 없음, 가린 원문 → 레지스트리 경로), `tests/components/company-doc-autofill.test.ts`(팝업 화면 글자 전체에 뒷자리·면허번호 없음).
- **알아 둘 점**: 팝업은 가린 원문으로 파싱하므로 7번째 자리가 늘 안 보인다 → 생년월일 세기는 늘 추정(YY>올해 YY → 19xx, 아니면 20xx)이고 생년월일 칸에 "1900년대생으로 봤어요… 확인해 주세요" 경고·정확도 "보통"이 붙는다. 표시값은 "YY.MM.DD" 라 세기가 화면 값에 영향을 주지 않는다(윤일 검증에만 쓰임). 7번째 자리를 state 에 남기지 않는 쪽(belie 결정)을 우선했다.

## 6. 남은 위험

- **실물 OCR 미실측**: 모두 합성 텍스트로만 검증. 실제 tesseract 출력(표 열 순서, 줄 쪼개짐, 한글 금액 오독)은 배포 후 비식별 샘플로 확인 필요.
- 부가세: 줄마다 "첫 번째 큰 금액 = 과세표준" 가정. 과세표준 앞에 다른 금액 열이 오는 양식이면 틀린 값. 열 단위로 읽히는 OCR(기간 전부 → 금액 전부)은 대부분 놓친다.
- 재무제표: 당기·전기를 숫자 순서로만 구분 — 한 줄에 소계 열이 더 있는 K-GAAP 양식은 전기를 잘못 볼 수 있다. 쉼표 없는 1~3자리 숫자는 주석번호로 보고 뺀다.
- 임대차: 면적은 "임대할 부분" 줄 우선, 없으면 가장 작은 값(여러 호실 계약은 틀릴 수 있음). 첫 "소재지" 라벨만 사용.
- 신분증: 주소 라벨이 없고 발급기관 줄에 청장·시장 글자가 없으면 그 줄을 주소로 붙일 수 있다.
- 되돌리기: 이 PR squash revert(스키마·시트 변경 없음 — 데이터 영향 0). 파서 하나만 끄려면 `PARSERS` 에서 그 줄만 빼면 팝업이 "모르는 문서" 안내로 돌아간다.
