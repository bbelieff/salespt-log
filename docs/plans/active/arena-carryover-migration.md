# 아레나 재참가 — 이월 마이그레이션 & 집계 분리

## 0. 원칙
- **활성 관리 시트는 1개**(아레나 시트). 헷갈림 방지의 최우선 규칙.
- **공정성**: 아레나 시작(시즌 기준일, 예 2026-06-12) *이전*의 파이프라인은 점수에 넣지 않는다. 아레나 기간에 **새로 일군 활동만** 집계.
- 갈라치는 단위 = **레코드(행) 단위 깃발**(`아레나 집계 여부`), 업체 단위 아님.

## 1. 로그인 / 시트 전환 / 옛 일지
- 종강 기수 시트는 **읽기전용 아카이브**로 보존. 아레나 참가자는 **아레나 시트가 유일한 작업 공간**.
- 로그인 라우팅: 한 이메일이 (6기 archived) + (A1-6기 active) 두 레지스트리 행을 가질 수 있음 → **active 아레나 행 우선**. 6기 행은 `status=archived`, 라우팅 미사용.
- 아레나 대시보드에 **"이전 N기 일지 보기(읽기전용)" 버튼** → 아카이브 시트 링크. 마이그레이션 안 된 옛 미팅 히스토리도 여기서 다 조회.

## 2. 마이그레이션 (자동)
- **트리거**: 6기 grad 가 아레나 클레임 완료 시, 그 사람의 이전 기수 시트(레지스트리 archived 행에서 spreadsheetId)에서 **자동 1회 실행**. (멱등 — 이미 이월된 행 재삽입 금지: 원본 행 id를 이월 메타에 보관해 중복 방지.)
- **이월은 항상 '아레나 행' 기준** (carryover-trainer-blocks-arena §B, 2026-06-18): `migrateArenaCarryover` 는 `findUserByEmail`(선호 행)이 아니라 **`findActiveArenaRowByEmail`** 로 아레나 행을 직접 잡는다. 수강생출신 트레이너가 아레나에도 참가하면 [숫자기수·아레나·T] 3행이 되는데, `pickPreferredUser` 가 T(trainer)를 최우선 반환해 이월이 막혔다(최정한 케이스). 회장(captain_of)도 동일 — **아레나 행에 있어야** me/captain 이 읽는다.
- **수동 아레나 등록 가드(B, 표준 절차)**: admin 이 prep 행에 email 을 직접(스크립트 등) 채워 재참가시키면 claimAccount 를 우회해 자동 이월/이전기수 archived 가 **안 돈다**. 따라서 수동 등록 직후 **admin '이월 실행'(arena-carryover) 을 반드시 1회** 누른다 — 이 한 번이 6기 파이프라인 복사 + 이전 기수 행 archived 까지 멱등 처리한다.
- **이월 대상 (자동 추출)**:
  - **04 업체관리**: 상태=`예약`(진행예정·미완료) 미팅 → 아레나 04에 복사.
  - **02 계약수납**: 계약 업체(기존 계약 행) → 아레나 02에 복사.
  - ※ **완료된 옛 미팅 히스토리·취소·과거 4지표 카운트는 이월 안 함**(아카이브에서 조회).
- 복사된 모든 행 = **`이월` 플래그**(§3).

## 3. 집계 규칙 (핵심 — 레코드 단위 깃발)
- 04/02 각 행에 **`구분` 값**: `이월` | (빈값=native/아레나).
- **`이월` = 아레나 점수 전부 제외** (생산/유입/컨택/미팅/계약/수임비/수수료).
- **native(빈값) = 집계 포함.** 아레나에서 새로 만든 모든 행 = native — **이월 업체라도 아레나 기간에 새로 잡은 미팅은 새 행 = native = 집계**(사장님 규칙).
- **계약/수납은 출발 미팅의 깃발 상속**:
  - 이월 미팅 → 계약돼도 그 계약/수납 = `이월`(제외).
  - native(아레나 신규) 미팅 → 계약 = native(포함).
- 결과: "아레나 시작 전부터 끌고 온 건"은 통째로 제외, "아레나 중 새로 일군 건"은 인정.

## 4. 집계 경로별 제외 적용 (구현 포인트)
- **01 영업관리 주차 카운트(생산/유입/컨택/미팅)**: 이월 미팅은 주차 카운트에 더하지 않음(마이그레이션이 04에만 넣고 01 카운트는 증가 X). 신규 미팅만 카운트.
- **계약/수납 집계(전광판·대시보드)**: 02 기반 합산이 `구분=이월` 행을 SUM에서 제외.
- **전광판(feat/arena-scoreboard)**: 기수 평균 모수·지표에서 이월 제외(입금자 모수와 별개 필터).
- 즉 **모든 집계 SUM/COUNT에 `구분≠이월` 가드**를 일관 적용.

## 5. UI (한 시트, 안 헷갈리게)
- 이월 카드: **"이월" 뱃지 + 흐린 색** + "이 건은 아레나 점수에 들어가지 않습니다" 한 줄.
- 대시보드/전광판: **2줄 표기** — `아레나 집계`(점수) / `전체(이월 포함)`(실제 파이프라인). 무엇이 점수인지 항상 명확.
- 필터 토글: "이월 숨기기/보기".

## 6. [3] '기존' 카테고리와 개념 통일
- 일반이벤트 `기존`(기존 고객, 05 투두, 비집계)과 **같은 "아레나 비집계" 패밀리**. 깃발 의미 공유 → 사장님·코드 모두 단일 개념("아레나 집계 여부")으로 이해.

## 7. 데이터 / SSOT 영향
- 04 업체관리·02 계약수납에 **`구분` 컬럼 추가**(이월/빈값) + 이월 원본행 id(중복 가드). SHEET_RANGES + sheet-structure.md 갱신.
- 레지스트리: archived 행 status + 이전 시트 링크 노출(me 서비스).
- 마이그레이션 repo/service 신규(읽기=이전 시트, 쓰기=아레나 시트, belie OAuth/SA).

## 8. 후속 / 엣지
- 동명 업체 중복(이월 vs 신규 같은 업체) 표시 정리 — 카드에 "이월/신규" 뱃지로 구분, 합산은 깃발로.
