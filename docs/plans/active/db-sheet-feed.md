# DB 시트 자동 확인 (07~21시 매시간 새 DB만)

status: verified — 구현(2026-11-06, §8). 운영: 0016·0017 마이그레이션 적용 후 동작.

## 1. 왜
애드프로 같은 DB 업체는 수강생마다 구글시트를 하나 주고, 새 고객을 그 시트 아래에 계속 붙인다. 지금은 수강생이 주소를 붙여넣어 「가져오기」를 매번 눌러야 하고, 잊으면 DB가 늦게 들어와 첫 통화가 늦어진다.

## 2. 수강생이 겪는 흐름
1. DB관리시트 → DB 가져오기 → 시트 주소 붙여넣기 → 자동 배치(지금과 같음). 이미 있는 업체는 「이미 있는 N건 제외」로 빠진다(이미 됨).
2. 확인 화면 아래에 새 체크칸 **「이 시트를 하루 3번 확인해서 새 DB만 자동으로 추가」**. 공급처·유형·열 연결은 이번에 확인한 그대로 기억한다.
3. 이후 정해진 시각마다 서버가 시트를 읽어 새 줄만 목록에 추가한다(유입 실적은 §6-2 팝업에서 수강생이 고른 뒤). 화면 위 안내 줄: 「애드프로 시트에서 새 DB 3건 들어왔어요 · 마지막 확인 13:00」.
4. 자동으로 넣기 애매한 줄(번호 이상·이름 없음 등)은 넣지 않고 **「확인 대기 N건」**으로 모아 두고, 누르면 지금의 가져오기 확인 화면이 그 줄들만 띄운다.
5. 관리: 가져오기 창 「연결된 시트」에서 끄기·지금 확인·연결 해제. 최대 3개.

## 3. 「새 DB」 판단 (두 겹)
- **이미 본 줄 기억**: 줄마다 (전화번호 숫자 + 업체명) 지문(해시)만 저장. 이미 본 지문은 다시 넣지 않는다 → 수강생이 지운(휴지통 비운) DB가 다시 살아나지 않는다. 고객 원문은 저장하지 않는다.
- **목록 중복 검사**: 서버 기존 `isSameLead`(사업자번호·이름·전화) 검사를 그대로 — 손으로 먼저 넣은 업체와 겹치면 넣지 않는다.
- 처음 연결할 때 시트에 있던 줄은 그 순간 「본 줄」로 기록(그때 수강생이 고른 것만 들어감).

## 4. 구조
- **분석기 이동**: 지금 분석기는 화면 폴더(`app/(app)/db-sheet/_components`)에 있어 서버가 못 쓴다 → 순수 함수 그대로 `lib/analytics/db-import/`로 옮기고 화면은 거기서 가져온다(동작 동일, 기존 시험 132개로 확인).
- **저장**: 새 표 `db_sheet_feeds`(수강생 시트 id · 구글시트 id·탭 · 공급처·유형·열 연결 · 유입 반영 여부 · 본 줄 지문 · 마지막 확인 시각·결과·연속 실패 수 · 켜짐). 마이그레이션 추가만.
- **시계**: 새 cron 을 만들지 않고 이미 15분마다(07~21시) 도는 서버 시계(`/api/internal/push/dispatch`)에 「DB 시트 확인」을 붙인다. 정한 시각 칸(예: 09:00·13:00·18:00)마다 시트당 한 번만(같은 칸 두 번 실행 방지). VPS 설정 변경 없음.
- **쓰기**: 기존 DB관리 추가 경로(DB 정본) 그대로 — 새 쓰기 방식 없음. 사용자 값 덮어쓰기 없음(추가만).
- **알림**: 새 DB가 들어오면 웹푸시 「새 DB 3건이 들어왔어요」(알림 켠 기기만, 업체명 기본 숨김 규칙 따름).

## 5. 안전장치
- 주소는 docs.google.com 만, 「링크가 있는 모든 사용자」 공유만 읽힘(지금과 같음). 공유가 끊기면 안내 줄 「시트를 열 수 없어요 · 공유 확인」, 3번 연속 실패면 자동 일시정지.

- 로그에는 건수만, 고객 값 없음.
