### 7-3. 시트 실측
- 탭 구성 동일(대시보드/01 영업관리/02~06). **영업관리 탭 실제 이름 = `01 영업관리`**.
- O1/O2 는 **날짜 값**(서식 "6/12"·연도 없음) → 판정은 SERIAL_NUMBER 로 읽어야 한다.
- 제목 형식이 **두 종류**: A1 = `세일즈PT_A1_1기 {이름}_대표님 경영일지` /
  7·8기 = `세일즈PT_ 7기 {이름} 수강생 경영일지` → 7·8기는 "A1→A2 치환"이 불가,
  **새 제목 생성** 규칙 필요(설계도 §2-5 명명 적용).
- cohorts 탭: **A1 행만 존재**(type=arena, status=active, **J 빈칸**), A2 행 없음.

### 7-4. 발견된 결함 — 진단 스크립트(#657·R트랙 산출물)가 항상 실패
1. **env 계약 불일치**: `GOOGLE_SERVICE_ACCOUNT_KEY`(JSON 통짜)만 지원 → 실제 배포 env 는
   `GOOGLE_SERVICE_ACCOUNT_EMAIL` + `_PRIVATE_KEY`(`lib/config/index.ts`) ⇒ **항상 exit 2**.
2. **존재하지 않는 탭** `영업관리!O1` ⇒ 참가자 시트 전수 `Unable to parse range`.
3. (부수) O1 을 FORMATTED_STRING 으로 읽어 "6/12" → 연도 없음 → 판정 불가.
4. (부수) 기대값(J) 미입력일 때 "O1 전부 일치" 라는 **거짓 초록**.
→ 이 PR 에서 4건 수리. 수리 후 라이브 실행 성공(시즌1: 참가자 40시트 스캔 완료·J 미입력만 지적 /
시즌2: A2 행 없음 지적). **W3 검증이 이 스크립트에 의존하므로 선행 필수였다.**

### 7-5. 설계도 정정 제안 — 이월매출은 **쓰는 값이 아니라 계산되는 값**
§3 W2 의 "이월매출 셀 = 기존이월 + A1 시즌매출" 은 **불필요하며 위험**하다.
`splitContractRevenue`(dashboard) 는 계약을 읽는 시점에 `isCarryoverContract` =
**이월 깃발 OR 계약일 < O1(시작일)** 로 분류한다(`lib/types/contract-status.ts`).
⇒ 복사본 O1 을 2026-08-07 로 두면 **8/7 이전 모든 계약(기존 이월 + A1 시즌 실적)이 자동으로
"시즌 전 성과"** 가 되고 시즌 매출은 0에서 시작한다. 셀에 숫자를 써넣으면 §2.5 가드 대상
사용자 값 오염 + 이중계상 위험만 생긴다. → **W2 단계에서 이 항목 삭제**(수용기준은 계산 결과로 검증).

### 7-6. 자율결정 (§0.7 — 되돌리기 = 한 줄 원복)
- **A1 행 J(개강일)는 건드리지 않는다.** 지금 비어 있어 전광판은 "미상(0) = 전 데이터 통과" 상태다.
  A2 J 만 2026-08-07 로 넣으면 8/6 까지는 현행 유지, **8/7 부터 자동으로 시즌2**로 전환된다
  (`resolveCurrentSeason`: unknown(1) > opened(2) 가 거짓이라 A1 공백은 전환을 막지 않는다).
  A1 J 를 지금 채우면 오늘부터 스코프가 A1-* 로 좁혀져 개막 전 표시가 바뀐다 — 불필요한 변경이라 보류.
