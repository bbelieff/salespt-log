# R4 — 8주 제한 해제 · 무제한 CRM (wave-0 설계)

## 0. 결론 (TL;DR)

- **목표(정본 §R4)**: 수료 후에도 쓰는 무제한 CRM. **8주 = "코스 기간"으로 의미 축소**(통계·아레나 집계 기준은 유지) · **사용 자체는 무제한**.
- **R4 4요소**(정본 §R4): ① 8주=코스 기간 재정의(ADR-0031) ② 편집가드(+69일 읽기전용) 제거/재정의 ③ 주차 무제한 모델 + 대시보드 "수강 기간 vs 이후" 구분 + **8주 하드코딩 전수 제거(구조테스트 가드)** ④ 수료생 archived 라우팅 개정(종강 후 로그인 유지). + **§B3 전환 판단 계기판**(admin).
- ✅ **belie 결정 완료(2026-07-26)**: **G1 = 편집가드 완전 해제** · **G2 = 수료생 정상 진입**. ADR-0031 accepted 로 박제 → wave-1 착수 근거(§4).
- 🔴 **wave-1 파생 위험(실측)**: 11주+ 는 시트 주차 블록이 없어 **DB-only** 인데, 무필터 집계가 그 행까지 합산하면 대시보드가 **영구 부풀린다** → **집계를 1~10주로 클램프**하는 조치를 W1-1 에 동반(§4-1).
- **선행조건**(정본 §R4 제목): **"R3 이후에만 가능"** → W0-C(DevD) 선행 게이트 장부(R3 공식 재판정)가 wave-1 의 gate.
- **8주 하드코딩 전수 목록 = W0-B(DevE)** `scratchpad/r4-hardcode-inventory.md` 가 정본. 본 문서 §3 은 그 인벤토리를 **소비하는 뼈대**이며, 완성 시 편입한다(현재는 알려진 앵커만 예시).
- **wave-0 = 코드 0줄.** 본 문서 + ADR-0031 초안이 W0-A 산출물. 실제 코드는 wave-1(§6 PR 분할)에서.

> ⚠️ 본 문서의 코드 지점 주장은 W0-B 전수 인벤토리로 **교차검증 후 확정**한다. 현재 상태 = 설계 뼈대 + 알려진 앵커.

## 1. 현행 제약 (왜 8주에 막혀 있나 — 실측 요지)

R4 가 풀어야 할 "8주 벽"은 네 층에 박혀 있다(전수는 W0-B):

1. **종강·주차 기준** — ADR-0005: 종강총회 = O1+50(7기+), 주차 = `weekIndexOf(date, O1)`(O1 기준 연속). 통계·퍼널은 **8주 기준**으로 계산(CLAUDE.md §2.5).
2. **편집 유예 가드** — "편집 가능 기간 = 수강시작일 + 69일, 이후 읽기전용"(CLAUDE.md §2.5). 종강 후 데이터가 **읽기전용으로 잠긴다** = 무제한 CRM 의 정면 충돌 지점.
3. **수료생 라우팅** — 종강/미등록 사용자는 `archived` 취급 → 현재는 **클레임(재등록) 유도** 화면으로 라우팅. 수료 후 계속 쓰려면 이 규칙 개정 필요.
4. **8주 하드코딩 산재** — `GRADUATION_OFFSET_DAYS`, 주차 캡, 편집가드 상수, archived 판정 등이 코드·테스트 여러 곳에 흩어져 있음(전수=W0-B).

**알려진 앵커(예시 — W0-B 가 전수·정본)**: `lib/service/me.ts`(GRADUATION_OFFSET_DAYS·편집가드) · `lib/repo/sales.ts`(weekIndexOf/종강 read) · `lib/auth/*`·`app/(auth)/*`(archived 라우팅) · `lib/service/contact-week.ts`(주차) · 통계/퍼널(8주 창).

## 2. 설계 원칙 (R4 불변식)

1. **8주는 사라지지 않는다 — "코스 기간"으로 남는다.** 통계·퍼널·스킬 점수·아레나 집계의 **기준 창(1~8주)** 은 유지한다. 무제한이 되는 것은 **사용·편집·주차 표시**이지 "코스 성과 지표"가 아니다. (지표 창을 바꾸면 과거 기수와 비교 불가 → belie 지표 방향 전환 = 별도 게이트.)
2. **주차는 무제한, 라벨은 이원화.** DB·화면은 수강시작 기준 **연속 주차**(9주차·10주차…)를 계산할 수 있어야 하되, 대시보드는 **"수강 기간(1~8주)" vs "수강 이후"** 를 구분 표시.
3. **읽기전용 잠금 → 정책 게이트.** 편집가드는 코드로 몰래 정하지 않는다 — belie 가 "수료 후 편집 허용 범위"를 정하면(§4 G1) 그 결정을 단일 지점(entitlement, §B2 재사용)에 태운다.
4. **하드코딩 제거는 구조테스트로 박제.** 8주·offset·+69일 magic number 재유입을 `tests/structural` 가드로 물리 차단(재발 방지 = Hashimoto).
5. **비가역·실데이터·수강생 가시 변경은 belie 게이트.** 편집 허용·라우팅·지표 창은 수강생이 겪는 변화 → §4 로 반환. 되돌릴 수 있는 내부 구조(주차 계산 무제한화, 하드코딩 상수화)는 자율 설계.
6. **시트 미러 유지(D3 확정)** — DB 정본 전환 후에도 시트 사본 자동 기록. R4 는 시트 은퇴(R7, 구 R6) 를 하지 않는다.

## 3. 4요소 설계 (뼈대 — W0-B 편입 대기)

### 3-1. ① 8주 = 코스 기간 재정의 → **ADR-0031 (0005 supersede)**
- ADR-0005 는 "종강총회일 계산(O1+50)"과 "주차 카운팅"을 박제했고, **편집유예(+69일)는 명시적으로 out-of-scope** 로 남겼다(0005 §Out of scope). R4 는 그 유예분을 정면으로 다룬다.
- ADR-0031 가 확정할 것: (a) 8주 = 코스 기간(지표 기준 창)으로 의미 축소, 사용 무제한 (b) O1+50 종강 계산은 **불변**(코스 종료일 표식으로 계속 사용) (c) 편집가드 재정의(§4 G1 belie 답변을 담는다) (d) 주차 무제한 모델.
- 초안 = `docs/decisions/0031-unlimited-crm-supersede-0005.md`(status=proposed, belie 게이트 미결 표기).

### 3-2. ② 편집가드 재정의 — 🔴 **belie G1 필요**
- 현행: 수강시작+69일 후 전면 읽기전용. 무제한 CRM 이면 이 잠금을 **제거 또는 재정의**해야 한다.
- 설계는 belie G1(§4) 답변을 **entitlement 단일 함수**(§B2)에 태운다 — "이 사용자, 이 기록, 지금 편집 가능?" 판정을 한 곳으로. (결제 도입 시 같은 함수만 수정 = §B2 취지 재사용.)
- 코드는 belie 답 확정 전까지 **미착수**(선택지만 §4 에 제시).

### 3-3. ③ 주차 무제한 모델 + 하드코딩 제거
- **주차 계산 무제한화**: `weekIndexOf` 는 이미 O1 기준 연속이라 상한이 없다 — 상한을 **거는** 지점(8주 캡·클램프)을 제거. 9주차+ 데이터가 정상 적재·조회되게.
- **대시보드 표시**: "수강 기간(1~8주)" 블록과 "수강 이후" 블록 구분(정본 §R4). 지표는 코스 창(§2 원칙①), 기록·활동은 무제한.
- **8주 하드코딩 전수 제거** — **정본 목록 = W0-B(`scratchpad/r4-hardcode-inventory.md`)**. 각 지점을 (a) 상수/설정로 승격 or (b) 코스-창 판정 함수로 대체 후, **구조테스트 가드**(magic `8`/`50`/`57`/`69`·`archived` 재유입 차단)로 박제.
  - > 📥 **W0-B 편입 슬롯**: 인벤토리 완성 시 이 절에 지점별 (분류/조치/가드) 표를 채운다. consume_condition = 목록 완성 + B ACK.

### 3-4. ④ 수료생 archived 라우팅 개정 — 🔴 **belie G2 필요**
- 현행: 종강/미등록 = archived → 클레임(재등록) 유도. 수료 후 계속 쓰려면 "수료생은 정상 앱 진입(읽기+정책상 편집 범위)"으로 개정.
- archived 의 두 의미 분리 필요: **(가) 수료생**(정상 사용 대상) vs **(나) 실제 미등록/이탈**(클레임 유도 유지). 판정·라우팅 규칙을 belie G2 답변으로 확정.

### 3-5. §B3 전환 판단 계기판 (admin)
- 정본 §B3: admin 에 "수료 후 활성 사용자 수 · 주간 활성 · 8주 이후 잔존율"(PostHog 기반) 카운터 — 유료 전환 판단용 50~100명 도달 확인.
- R4 와 함께 배선(무제한 CRM 이 만드는 "수료 후 사용" 을 계량). 실데이터 수집이라 PostHog 이벤트 정의만 wave-1, 계기판 UI 는 후속 가능.

## 4. ✅ belie 결정 완료 (2026-07-26 확정 — wave-1 착수 근거)

> **G1 = (A) 완전 해제** · **G2 = (A) 정상 진입** 으로 belie 확정. 아래 선택지 원문은 결정 근거로 보존.
> 코드 반영 = wave-1 W1-1(쓰기 무제한) 이후. ADR-0031 가 이 결정을 박제한다.

**G1 — 수료(8주 종료) 후 자기 기록을 계속 고칠 수 있나? → ✅ (A) 완전 해제**
- ① 무엇: 지금은 수강시작 69일 뒤부터 화면이 "읽기 전용"이 됩니다. 무제한 CRM 이면 이 잠금을 어떻게 할지 정해야 합니다.
- ② 선택지: **(A) 완전 해제** — 수료 후에도 계속 입력·수정(권장: 무제한 CRM 취지에 부합) / **(B) 코스 기록만 잠그고 새 기록은 허용** — 8주차까지 데이터는 읽기전용, 9주차+는 자유 / **(C) 현행 유지** — 수료 후 읽기전용(무제한 아님).
- ③ 되돌리기: 게이트 함수 한 곳이라 언제든 정책 변경 가능(revert 안전).
- 🡒 **권장 = (A)** ("한 번 적으면 계속 쓴다"는 CRM 목적에 가장 맞음). → **belie 확정: (A)**. 편집 잠금(+69일·archived 읽기전용) 전면 해제.

**G2 — 수료생이 로그인하면 어디로 가나 / 무엇을 볼 수 있나? → ✅ (A) 정상 진입**
- ① 무엇: 지금 수료·미등록 사용자는 "재등록(클레임)" 화면으로 보냅니다. 무제한 CRM 이면 수료생은 정상 앱으로 들어와야 합니다.
- ② 선택지: **(A) 수료생=정상 앱 진입**(내 기록·대시보드 열람+정책상 편집), 실제 미등록만 클레임 유도(권장) / **(B) 수료생 전용 축소 화면**(열람 위주) / **(C) 현행 유지**.
- ③ 되돌리기: 라우팅 규칙 개정이라 revert 로 복구. 단 **실제 수료생 계정에 영향** → 배포 전 파일럿 1인 실왕복 확인 필요.
- 🡒 **권장 = (A)**. → **belie 확정: (A)**. 수료생=정상 앱 진입, 실제 미등록만 클레임 유도.

### 4-1. 🔴 wave-1 이 떠안은 파생 위험 (W1-1 실측, 2026-07-26)
G1 완전 해제 = **11주+ 저장 허용**인데, 시트 01 영업관리는 **주차 블록이 1~10주까지만 물리적으로 존재**한다
(`salesRowFor` 가 1~10 밖이면 throw). 그래서 11주+ 는 **DB-only**(시트 write·미러 skip)가 유일한 경로다.
그런데 현행 코드는 그 이유로 **DB 쓰기 자체를 막고 있다** — `persistProductionCell` 주석:
"편집 가능 기간(1~10주) 밖이면 **DB 에도 쓰지 않는다** — 시트가 담을 수 없는 행이 DB 에 생기면
**무필터 집계(대시보드 채널생산·유입대기)가 영구히 부풀기** 때문."
→ 실측 확인: `channelStackingFromDb`(dashboard-aggregates)는 salesRows 를 **주차 필터 없이 전부 합산**한다
(courseStart 인자조차 없음). **11주+ 쓰기를 열면서 이 클램프를 같이 넣지 않으면 대시보드가 영구 부풀린다.**
→ **W1-1 필수 동반 조치**: 집계를 **시트 표현 가능 창으로 클램프**. 오늘 데이터엔 11주+ 행이 존재할 수
없으므로 **현재 수치는 완전 불변**(시트↔DB parity 도 그대로), 내일부터의 부풀림만 차단한다(§2 원칙①).
- **리터럴 금지(FOREMAN 판정 2026-07-26)**: 클램프 상한은 **W1-0 이 박은 `MAX_SHEET_WEEK`**
  (`lib/config/cohort-dates.ts`)를 **소비**한다. 코드·테스트에 `10` 을 직접 쓰지 않으며
  `tests/structural/period-hardcode.test.ts`(G1~G8) 가드를 통과하는 것으로 증명한다.
  (같은 이유로 통계 창은 `STATS_WEEKS`, 편집유예 잔재는 `EDIT_WINDOW_DAYS` 로만 참조.)

> 📌 **11주+ 데이터는 손실이 아니다.** 클램프는 **집계(대시보드 지표)에서 제외**할 뿐, 저장은 DB 정본에
> 그대로 남는다(조회·편집 가능). **11주+ 기록을 화면에 어떻게 보여줄지는 "표시층 설계"로 이월**한다
> — R4-1(주차 무제한 모델 · "수강 기간 vs 이후" 구분 표시)에서 다룬다. 즉 지금은 **보존하되 코스 지표를
> 오염시키지 않는다**가 계약이고, 노출 방식은 후속 PR 의 결정 사항이다.

### 4-4. ✅ 캐시 Date 강등(P0 클래스) 비해당 검증 — W1-1 클램프 (2026-07-29)

#639(전광판 500)가 드러낸 **재발 클래스**: `unstable_cache` 는 JSON 직렬화라 **Date 를 캐시하면 히트 시
string 으로 강등**되는데 타입은 Date 라고 거짓말한다 → 소비처의 `.getTime()` 이 500(me.ts 2026-05-13,
scoreboard 2026-07-29 — 2회 재발). W1-1 의 집계 클램프(`inSheetWindow` → `weekIndexOf` → `getTime`)는
**courseStart: Date 를 새로 소비**하므로 3번째 재발 후보였다. 실측 결과 **비해당**:

1. `dashboard.ts:333` 의 `readProfileBundle` 은 `@/repo/sales` **원본 함수**(캐시 래퍼가 아니다).
   me.ts 의 캐시 래퍼(`cachedReadBundle`)는 애초에 **primitive(courseStartMs)만 저장**하고 호출부가
   Date 로 복원한다(2026-05-13 수리). 다른 분기(`courseStartISOCache`)는 ISO 문자열에서 **로컬 생성**.
2. 같은 `courseStart` 변수가 이미 `terminatedByWeek(contracts, courseStart)`(dashboard.ts:364)로
   `weekIndexOf → getTime` 을 타고 있다 — 강등 값이 흐를 수 있었다면 **대시보드가 이미 500** 이었다.

→ 클램프는 새 캐시 경계를 만들지 않는다. 다만 `inSheetWindow` 는 파싱 실패 시 **fail-closed**(그 행을
집계 제외)라 강등이 생겨도 500 대신 수치 누락으로 degrade 한다. 향후 이 경로에 캐시를 끼우려면
#639 규칙(**경계는 ISO 문자열, 소비처가 parseISO 복원**)을 따를 것.
