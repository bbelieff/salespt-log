## PR 1 — 화면 동작 변화
- 컨택 화면 주소의 `?date=` 가 형식만 맞고 없는 날짜(예: 02-30)면 이제 무시한다(전에는 그대로 넣어 빈 화면).
- 그 외 동작 동일(같은 값·같은 라벨). 검증: `tests/util/shared-rules.test.ts`.
- 되돌리기: squash 커밋 revert 1회.

## PR 2 — 화면 동작 변화
- 수납 칸 규칙을 `lib/analytics/contract-slots.ts` 하나로. 기관 목록·상세 카드·강조색·업무 현황·대시보드 후속 업무가 같은 판정.
- **메모만 적힌 칸이 이제 상세 카드에도 보인다**(전에는 목록에만 보이고 상세에서 숨어 메모가 안 보였음). 그 칸은 진행률 평균에 0% 로 들어가 강조색·완료 표시가 그만큼 반영된다.
- 공백만 있는 칸은 「입력됨」이 아니다(목록 쪽이 이미 그렇게 판정 — 상세가 맞춰짐).
- 검증: `tests/components/contract-slots.test.ts`. 되돌리기: revert 1회.

## PR 3 — 화면 동작 변화
- 「같은 업체인가」(사업자번호 10자리·이름·전화 9자리 이상)를 `lib/util/db-sheet-identity.ts` 하나로 — 가져오기·직접 등록 경고와 서버 저장 차단이 같은 판정.
- 국제 번호 변환 하나로: 「+82 010-…」처럼 0이 한 번 더 붙은 번호가 이제 010… 으로 바르게 바뀐다(전에는 서버·경고에서 0010… 이 되어 중복을 못 잡음).
- 검증: `tests/util/db-sheet-identity.test.ts`. 되돌리기: revert 1회.

## PR 4 (⑧ + ②) — 화면 동작 변화
- ⑧ 주간목표 주차 창(이번 주·지난주·누적 시작)을 `goalWeekOf`·`goalWeekWindow`(week.ts) 하나로 — 서버 목표 조회와 코치 개요가 같은 계산(옛 두 계산과 답이 같음을 130일×3개 시작일로 대조). 「오늘(한국)」 함수 5벌 → `todayKST` 하나(달력 주 계산은 한 벌뿐이라 그대로).
- ② 「DB 로 읽고 쓰나」 37곳 → `usesDbStorage(수강생)` 하나. 수강생을 넘기면 유보 보정·운영 스위치를 안에서 처리.
- **바뀌는 것**: 유보로 숨긴 DB 기수 수강생이 주간목표 코치 개요·아레나 이월·최근 추이에서도 DB 기록을 본다(전에는 그 세 곳만 시트로 갔다). 다른 수강생은 동일.
- 바로잡음: 조사 보고서의 「기록 옮기기가 운영 스위치 무시」는 오판 — `dbEnabled()` 안쪽이라 원래 안전했다.
- 검증: `tests/util/week-windows.test.ts`, `tests/service/storage-gate.test.ts`, 전체 4,134개 통과. 되돌리기: revert 1회.

## PR 5 (③ + ④) — 화면 동작 변화
- 서버 `/api/dashboard` 가 더 이상 비용 원장의 반복 지출을 만들지 않는다(조회가 쓰기를 하던 문제). 반복 지출은 원장 조회(`/api/expenses`)가 맡는다 — 대시보드 화면도 원장을 같이 불러오므로 생성 시점은 그대로.
- 서버의 안 쓰는 재무 사본 삭제: kpi 의 영업이익·총매출·이월 등(읽는 화면 0), 원장 합계 계산, 테스트 전용 옛 매출 함수. kpi 는 누적수임비만(그림자 대조용).
- 비용 원장 창은 재무 칸이 직접 연다 — 같은 기간·같은 숫자(페이지 왕복·서버값 대체 경로 제거).
- 그대로: 채널별 성과 카드의 비용은 수강 기간분(ADR-0034 의도된 범위), 아레나 순위표 매출.
- 검증: 조회 시 원장 생성 0회(`tests/service/dashboard-sheet-latency.test.ts`), 원장 창 값=비용 칸(`tests/components/dashboard-finance-channels.test.ts`), 전체 4,146개 통과.
