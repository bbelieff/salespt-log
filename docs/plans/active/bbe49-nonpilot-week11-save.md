# BBE-49 (P0) — 비파일럿 수료자 컨택 저장 500 수리

> **📄 이 문서는 무엇인가요?**
> - **한 줄 요약**: 파일럿이 아닌 기수(7기 등)도 수료 후 11주+ 컨택 기록을 저장·조회할 수 있게, 시트 물리한계 밖 날짜만 DB 경로로 우회한다.
> - **누가 읽나요**: 개발자
> - **어떤 기능·작업과 연결?**: `lib/service/sales-write.ts`(쓰기) · `lib/service/contact.ts`(일별 조회) · `lib/service/contact-week.ts`(주간 퍼널)
> - **읽고 나면 알 수 있는 것**: ① 500 의 물리적 원인 ② 왜 DB_READ_COHORTS 확대가 아닌가 ③ 어디까지만 고치고 무엇을 남겼나
> - **관련 문서**: `docs/incidents/2026-08-05-bbe49-nonpilot-week11-save.md`(원인·리뷰 반영표·잔여 한계), Linear BBE-49

## 1. 원인

7기(개강 5/15, 수료 7/4, 현재 12주차) 김현지 계정 라이브 재현 — `/contact` 저장 →
`POST /api/daily/2026-08-05` **500** `"영업관리 좌표 계산 실패: … 편집 가능 기간(1~10주) 밖"`.
`daily-source.DB_READ_COHORTS`(8·9·연습+아레나)에 7기가 없어 쓰기 정본이 "sheet" 로 결정되고,
시트 경로의 `salesRowFor` 가 `week > MAX_SHEET_WEEK(10)` 에서 무조건 throw 한다.
ADR-0031(수료 후에도 계속 기록)와 모순 — 시트엔 11주+ 좌표가 **물리적으로 없다**.

## 2. 범위 (의도적으로 좁게)

`DB_READ_COHORTS` 에 7기를 넣는 wave-2 전체 확대가 **아니다**(대시보드·통계·아레나 전 영역 영향,
belie 결정 사항). 이 PR 은 "시트에 좌표가 없는 날짜"만 DB 로 보낸다:

1. **쓰기** `persistSalesRows` — 비파일럿이어도 `weekIndexOf(date, 시트 O1) > MAX_SHEET_WEEK` 면 DB 저장,
   시트 미러는 건너뜀(좌표가 없어 no-op). `dbEnabled()` 가드 포함(롤백 레버 보존).
2. **읽기** `loadDay` — 같은 조건에서 그 날 4지표만 DB. 누적합·미팅·현수막 주문합은 **시트 정본 유지**
   (비파일럿은 DB 백필 이력이 없어 재계산하면 0 이 된다).
3. **주간 퍼널** `loadWeekMeetings` — 비파일럿 11주+ 에서만 퍼널을 DB 로 재계산(미팅 카드는 시트 유지).

판정 원천은 **시트 O1 단일** — 읽기와 쓰기가 같은 값을 봐야 read/write 비대칭이 안 생긴다.
