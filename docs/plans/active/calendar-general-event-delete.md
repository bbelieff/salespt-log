# 캘린더 일반이벤트 삭제 UI (소형 feat)

- **상태**: 구현 완료 → PR 대기
- **트랙**: A (DevA) · 2026-07-15
- **브랜치**: `feat/calendar-general-event-delete`

## 1. 문제 (설계 누락)

`GeneralEventModal` 은 **생성 전용**이다 (삭제 코드 0건). 일반이벤트는 `Todo` 이지만
`type === "일반"` 이라 실무·수납 탭 목록에 렌더되지 않는다. 그런데 캘린더 일자상세의
ToDo 카드는 **타입 구분 없이** `/payment?focus=<id>` 로 점프시켰다 →
일반이벤트를 누르면 그 항목이 없는 탭으로 이동. **만든 뒤 지울 방법이 없는 고아 데이터.**

(캡처 임무 뒷정리 중 실측 확인 — 테스트로 만든 "세무사 상담"을 앱에서 지울 수 없었다.)

## 2. 스코프

- **한다**: 일자상세 일반이벤트 카드에 휴지통 버튼 → 확인 다이얼로그 → 삭제.
- **안 한다**: 일반이벤트 **수정**(제목·날짜·시간). 지우고 다시 만들면 되고, 수정 UI 는
  생성 모달 재사용/폼 상태가 붙어 소형 feat 범위를 넘는다. **필요성 보이면 belie 결정함.**
- 미팅·실무 타입 카드는 기존 원칙 유지(원래 탭으로 안내) — 동작 무변경.

## 3. 구현

- `app/(app)/calendar/_components/TodoDayCard.tsx` **신규** — 일자상세 ToDo 카드 1건.
  page.tsx 가 496줄(캡 500)이라 인라인 추가가 불가능 → 카드 블록을 그대로 옮기고
  거기에 삭제 UI 를 얹었다. 마크업·색(tokens)·gcal 토글 동작은 이관 전과 동일.
- 삭제 = **기존 경로 재사용** — `useRemoveTodo` → `DELETE /api/todos/[id]`.
  즉 R3-2 에서 DB 정본으로 전환된 todos 쓰기 경로(+시트 미러 +`syncTodoRemoved`)를
  그대로 탄다. **repo/service 무변경** (UI 전용 PR).
- 구글 캘린더: 삭제 시 담아둔 이벤트도 함께 사라진다(`syncTodoRemoved`). 확인 모달에
  그 사실을 한 줄로 고지 — "연결 해제만으로는 구글에 남는다"는 함정과 짝을 이룬다.
- 확인 모달은 payment `DeleteConfirmModal` 패턴(z-[300], max-w-sm) 인라인 재현.
  삭제 중 버튼 비활성 + 실패 시 모달 유지 + 인라인 에러.

## 4. 되돌리기

UI 전용 단일 PR → `git revert <squash-sha>` 하나로 원복(카드는 다시 /payment 로 점프).
데이터 경로를 새로 만들지 않았으므로 되돌려도 남는 흔적 없음.
