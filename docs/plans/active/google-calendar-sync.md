# 구글 캘린더 동기화 (앱 → 구글, 단방향)

## 0. 확정 결정 (2026-07-06 사용자)
- **방향**: 단방향 앱→구글. 구글에서의 수정은 앱에 안 돌아옴(SSOT=시트 원칙 유지). 양방향(webhook) 기각 — 복잡도 대비 가치 낮음(YAGNI).
- **대상**: ① 미팅 예약(04) ② 일반이벤트(05, 기존/기타) ③ 실무투두(05) 예정일 있는 항목 — 전부.
- **전파**: 앱에서 수정(날짜·시각·업체명 등)·삭제 시 구글 이벤트도 patch/delete. 미팅 완료는 과거 이벤트로 유지.
- **연결 단위**: 수강생 본인 구글 계정. opt-in(연결 버튼 누른 사람만). **대상 캘린더는 사용자가 선택**(기본=primary, 연동 카드 드롭다운 — 2026-07-06 추가 확정). 전용 캘린더 *생성*은 후속.

## 1. 인증 — 수강생 개인 OAuth (ADR-0028 신규 작성)
- 로그인(NextAuth) 스코프는 **무변경**. 캘린더 탭의 [구글 캘린더 연결] 버튼 → 별도 OAuth 동의
  (scope 2개: `calendar.events` + `calendar.readonly` — 후자는 캘린더 목록 드롭다운용 읽기 전용.
  calendar.events 만으로는 calendarList 조회 불가) → per-user refresh token 획득.
  ADR-0015(관리자 Drive 토큰)와 같은 패턴의 사용자판.
- **토큰 저장**: 레지스트리 users 탭 신규 컬럼 `gcal_token` — AES-256-GCM 암호화(AUTH_SECRET 파생키),
  평문 저장 절대 금지. + `gcal_settings`(JSON: 대상 3종 on/off). 컬럼은 끝에 append(shift 금지),
  sheet-structure.md §6 등재.
- 연결 해제 = 토큰 컬럼 비움 + (가능하면) 구글 token revoke. 기존 구글 이벤트는 남김(안내 문구).
- ⚠️ **운영 리스크**: `calendar.events` 는 Google 기준 sensitive scope — 앱이 브랜드 검증 전이면
  동의 화면에 "확인되지 않은 앱" 경고 또는 테스트 사용자(100명) 제한. 단기: GCP 동의화면
  테스트 모드에서 수강생 이메일을 테스트 사용자로 등록(현 인원 ~40명, 여유) 또는 경고 안내 문구.
  장기: 브랜드 검증 신청. 사전 GCP 작업은 §5.

## 2. 데이터 — 이벤트 매핑·멱등
- **04 미팅**: 신규 컬럼 `gcal_event_ids` 1개 append(현재 마지막 컬럼 뒤 — 구현 시 실제 끝 컬럼
  git/시트에서 확인). **05 실무투두**: 동일하게 append. sheet-structure.md 등재.
  ★값 = **사용자별 JSON 맵** `{"이메일": "eventId"}` — 한 시트 멀티 계정(부부·직원)이 각자
  연결해도 충돌 없이 각자 캘린더에 등록(2026-07-06 QA 에서 발견된 설계 구멍 보완).
- 멱등 규칙(사용자 단위): 내 이메일 키에 id 없으면 insert 후 저장, 있으면 patch, 삭제 시
  delete 후 내 키만 제거. §2.5 bulk-write 보존 가드 준수.
- 이벤트 내용(비-PII 최소) — **제목은 업체명/할일이 맨 앞**(모바일 잘림 방지, 2026-07-06 확정.
  `[세일즈PT]` prefix 금지 — 출처 식별은 제목이 아니라 extendedProperties 로):
  - 미팅: 제목 `{업체명} 미팅`, 시작=예약일+예약시각(기본 1시간), 장소=H, 설명=앱 링크 + "세일즈PT 경영일지".
  - 일반이벤트: 제목 `{이벤트명}`, 카테고리(기존/기타)·출처는 설명에.
  - 투두: 예정일자만 있으면 **종일 이벤트**, 예정시각 있으면 시각 이벤트. 제목 `{할 일 제목}`.
  - 앱 생성 이벤트 식별: `extendedProperties.private.salesptId = {행 id}` — 제목과 무관하게 추적·멱등.
- **대상 캘린더 선택**: calendarList.list 로 쓰기 가능 캘린더 드롭다운(기본 primary),
  gcal_settings 에 calendarId 저장. 캘린더 변경 시 신규 이벤트는 새 캘린더로, 기존 이벤트는
  [전체 다시 동기화] 실행 시 events.move 로 이동(안내 문구 표시).
- 이월 미팅도 예약 상태면 동기화 대상(수강생 실제 일정이므로). 아레나 집계와 무관.

## 3. 동기화 엔진
- `lib/repo/gcal-client.ts` — googleapis calendar v3 (googleapis 는 lib/repo/ 전용 규칙 그대로).
  `lib/service/gcal-sync.ts` — 매핑·멱등·설정 판정 단일 진입점.
- **훅 지점(service 레이어)**: 미팅 생성/수정/삭제·상태 변경, 일반이벤트/투두 생성/수정/삭제 —
  각 서비스 유스케이스 끝에서 fire-and-forget 호출.
- **베스트에포트·비차단**: 구글 API 실패해도 앱 저장은 성공(경고 로그·PostHog 이벤트). 재시도 1회.
  연결 안 한 사용자·꺼진 대상은 즉시 skip(비용 0).
- [전체 다시 동기화] 버튼: 현재 시트의 대상 항목 전체를 멱등 push(실패 복구용). 페이지네이션·quota
  주의(사용자당 이벤트 수십 개 수준이라 여유).
- 토큰 만료/철회 감지 → gcal_token 무효 표시 + 설정 카드에 "다시 연결해 주세요" 상태.
