# 오류신고 1단계 (2026-10-25 belie)

belie 지시: 「우측하단 플로팅 아이콘으로 버그리포트 · 나머지 N건은 전체보기 버튼 안으로 · 박스 왼쪽 아래 오류신고 · 캡처·설명」 → 「스샷에 그림판처럼 체크·텍스트·박스」 → 목업 승인 「좋다」.

## 화면
- 빠른 보기 창 아래 줄: 왼쪽 「🐞 오류신고」, 오른쪽 「대시보드에서 N건 더 보기 ↗」(N=0 이면 「대시보드에서 전체 보기」). 별도 「나머지 N건」 글자 삭제.
- **캡처 = 실제 화면 그대로** (belie 2026-10-25 「다시 그린 캡처가 실제와 다르면 없는 오류가 신고되고 받는 쪽이 혼동」 → 결정 「실제 화면 찍기」).
  - PC 크롬·엣지: 오류신고 → 빠른 보기 창 닫힘 + 브라우저 「이 탭 공유」 허락 → 개인정보 가림을 실제 화면에 잠깐 씌우고(0.6s) 탭 영상 한 장 → 공유 즉시 끔 → 신고 창. (처음 만든 html-to-image 「다시 그리기」 방식은 폐기, 의존성 제거.)
  - 휴대폰·사파리(탭 찍기 없음)·허락 거절: 그림 없이 신고 창 → 「📷 화면 캡처하러 가기」(창을 숨기고 아래 「캡처했어요 · 신고로 돌아가기」 버튼만, 적은 내용 유지) → 휴대폰 캡처 → 「🖼 사진 붙이기」. PC 는 Ctrl+V 도.
  - 신고마다 `context.captureMethod` = tab(실제 탭) / upload(직접 올린 사진) / none 기록 → 받는 쪽이 출처를 안다.
- 미리보기를 누르면 그림판: 박스·펜·글자(빨강 하나)·**가리기**(끌어서 진회색으로 덮기 — 직접 올린 사진의 전화번호·이름용)·되돌리기·전체 지우기·취소·완료.
- 문제 종류 6개(필수 1개) · 설명(선택, 2000자) · 사진 「바꾸기」·「빼기」.
- 보낸 뒤 「접수했어요 · 고치면 새소식으로 알려 드릴게요」.

## 개인정보
- 자동으로 찍은 탭은 찍는 순간 회색으로 가림: 전화·이메일·비밀번호 입력칸, 이름표(aria-label·name·placeholder·label)가 전화/연락처/이름/대표자/담당자/계좌/주민/생년/아이디/이메일/주소인 칸, 값이나 글자에 전화번호·주민번호·계좌형 숫자·이메일이 있는 요소, 표 머리칸이 그런 이름인 열 전체, `data-private`.
- 사업자명·업체명·날짜·금액은 가리지 않는다(원인 찾기에 필요).
- 직접 올린 사진은 자동으로 못 가린다 → 신고 창에 「전화번호·이름이 보이면 ■ 가리기로 덮어 주세요」 안내. 저장은 관리자만 보는 운영 DB.
- 함께 보내는 최근 오류 메시지도 긴 숫자·이메일을 지운다. 저장은 운영 DB `bug_reports` 에만 — 공개 저장소·외부 이슈로 보내지 않는다.

## 서버
- `POST /api/bug-reports`(로그인 필수): 문제 종류·설명·그림(data URL ≤3MB)·맥락(화면 주소·제목·화면 크기·브라우저·PostHog 재생 링크·최근 오류 ≤10·표시 수) Zod 검사.
- 표는 처음 쓸 때 `create table if not exists`(손으로 돌릴 마이그레이션 없음). 한 사람 24시간 20건 상한(429).
- 관리자(ADMIN_EMAILS) 휴대폰 알림 = 기존 웹 푸시로 「🐞 오류신고 · N기 이름 · 종류」. 알림 실패는 접수를 막지 않는다. 카카오톡은 앱에서 보낼 수 없어(카페봇 VPS 전용) 웹 푸시로 대신했다.

## 한계
- 실제 탭 찍기는 PC 크롬·엣지에서 매번 브라우저 허락 창이 한 번 뜬다(브라우저 보안 규칙 — 끌 수 없음). 허락 창에서 다른 탭·창을 고르면 그 화면이 찍힌다.
- 미리보기 창(내장 브라우저)은 화면 공유가 막혀 있어 실제 탭 찍기는 여기서 확인하지 못했다 → 배포 후 belie PC 크롬에서 한 번 확인 필요(NOT_RUN).
