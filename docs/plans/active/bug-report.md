# 오류신고 1단계 (2026-10-25 belie)

belie 지시: 「우측하단 플로팅 아이콘으로 버그리포트 · 나머지 N건은 전체보기 버튼 안으로 · 박스 왼쪽 아래 오류신고 · 캡처·설명」 → 「스샷에 그림판처럼 체크·텍스트·박스」 → 목업 승인 「좋다」.

## 화면
- 빠른 보기 창 아래 줄: 왼쪽 「🐞 오류신고」, 오른쪽 「대시보드에서 N건 더 보기 ↗」(N=0 이면 「대시보드에서 전체 보기」). 별도 「나머지 N건」 글자 삭제.
- 오류신고 → 빠른 보기 창 닫힘 → 신고 창 즉시(「화면을 찍는 중이에요…」) → 닫힘 동작(0.52s) 뒤 지금 보이는 화면을 JPEG 로 찍어 미리보기.
- 미리보기를 누르면 그림판: 박스·펜·글자(빨강 하나)·되돌리기·전체 지우기·취소·완료. 완료하면 표시가 합쳐진 그림으로 바뀐다.
- 문제 종류 6개(필수 1개) · 설명(선택, 2000자) · 설명 칸에 Ctrl+V 로 직접 찍은 캡처 붙여넣기(긴 변 1600px JPEG 로 줄임) · 「빼기」로 캡처 없이.
- 보낸 뒤 「접수했어요 · 고치면 새소식으로 알려 드릴게요」.

## 개인정보
- 찍기 전에 회색으로 가림: 전화·이메일·비밀번호 입력칸, 이름표(aria-label·name·placeholder·label)가 전화/연락처/이름/대표자/담당자/계좌/주민/생년/아이디/이메일/주소인 칸, 값이나 글자에 전화번호·주민번호·계좌형 숫자·이메일이 있는 요소, 표 머리칸이 그런 이름인 열 전체, `data-private`.
- 사업자명·업체명·날짜·금액은 가리지 않는다(원인 찾기에 필요).
- 함께 보내는 최근 오류 메시지도 긴 숫자·이메일을 지운다. 저장은 운영 DB `bug_reports` 에만 — 공개 저장소·외부 이슈로 보내지 않는다.

## 서버
- `POST /api/bug-reports`(로그인 필수): 문제 종류·설명·그림(data URL ≤3MB)·맥락(화면 주소·제목·화면 크기·브라우저·PostHog 재생 링크·최근 오류 ≤10·표시 수) Zod 검사.
- 표는 처음 쓸 때 `create table if not exists`(손으로 돌릴 마이그레이션 없음). 한 사람 24시간 20건 상한(429).
- 관리자(ADMIN_EMAILS) 휴대폰 알림 = 기존 웹 푸시로 「🐞 오류신고 · N기 이름 · 종류」. 알림 실패는 접수를 막지 않는다. 카카오톡은 앱에서 보낼 수 없어(카페봇 VPS 전용) 웹 푸시로 대신했다.
