# 업무도구 「간편인증 서류 조회」 — 대표 휴대폰 승인 한 번으로 홈택스 증명서를 업체 서류함에

## Intent (왜)
belie(2026-11-08): 업무도구에 간편인증 스크래핑을 만든다. 수강생이 고객(업체 대표)에게 서류를 일일이 받는 대신, **수강생이 앱에서 대표에게 간편인증을 보내고 → 대표는 휴대폰에서 승인만 → 홈택스 증명서를 자동으로 받아 → 업체별 서류함에 저장 → 수강생이 조회·업체정보 반영**까지 한 번에.

## 결정 (2026-11-08 belie)
- **흐름은 「직접 요청형」 하나로 통일.** 고객에게 링크를 보내 고객이 인증수단을 고르는 「링크형」은 만들지 않는다 — 링크 발송·공개 페이지·알림톡 계약이 빠져 워크플로우와 비용이 준다. 고객은 링크를 받지 않고 인증 알림만 승인한다.
- **채권자변동조회는 보류.** CODEF 공개 상품에 없음(크레딧포유는 계정 관리 상품만), 신용정보법 §39의2 본인 열람 정보라 제3자 수집이 민감.
- **주민등록번호는 받지 않는다.** 홈택스 회원 간편인증(이름+생년월일+휴대폰)만. 비회원은 「홈택스 회원가입 후 다시」 안내.
- **업체를 먼저 고르지 않는다**(belie 2026-11-08): 인증부터 보내고, 서류가 오면 사업자마다 DB 관리시트에 연결한다. 연결 순서 ① 사업자번호 일치 → 자동 ② 대표 휴대폰 + 비슷한 상호(`isSimilarDbSheetCompany`) → 자동 ③ 휴대폰만 또는 상호만 → 후보 확인 ④ 없음 → 사업자가 1곳이면 새 DB 자동 생성(유입 미반영), **여러 곳이면 자동 생성 안 함 — 「DB 등록」/「등록 안 함」을 골라야 만든다**(belie 2026-11-09: 유입으로 잡힐 우려·임대사업자 등 영업 대상 아님). 업체정보 반영은 연결된 사업자만.
- **대표의 모든 사업자 서류를 한 번에**(belie): 사업자번호를 지정하지 않으면 모든 계속사업장이 온다(실측 사업자등록증명 2건). 폐업 사업장은 빠진다(CODEF 문서).
- 기본 서류(belie): 사업자등록증명(항상) · 부가세 과세표준증명 최근 3년 · 표준재무제표증명 당기 포함 3개년(1년씩 3번 조회, 같은 세션이라 승인 1번, 홈택스 08~22시). 사업자등록증 「재발급·정정」 자체 API 는 CODEF 에 없음(정정 이력 API 는 있음). 총사업자등록내역 사실증명은 「신청→처리상태」 비동기라 이번 범위 밖.
- **화면의 「고객 동의」 체크는 두지 않는다**(belie 2026-11-08: 어차피 받아야 하는 동의). 동의는 수강생이 통화로 받는 업무 절차로 두고, 고객의 휴대폰 승인 자체가 조회 의사 표시다. 개인정보 처리방침의 위탁(제공사) 항목은 그대로 준비한다.
- **지방세 완납증명(정부24)도 함께**(belie 2026-11-08): CODEF `mw/localtax-payment-certificate/inquiry` — 간편인증 지원, 기관이 달라 **고객 승인 1번 더**, 문서상 주민번호(13자리 또는 생년월일+뒷자리 암호화)와 주소 필수, 정부24 보안문자는 CODEF 가 자동(2회 실패 시 수동). 이 서류를 고를 때만 주민번호 뒷자리·주소 칸을 연다(주민번호 미수집 원칙의 예외 — 저장하지 않고 요청에만 쓴다). 국세 완납증명은 홈택스.
- 화면(belie): 이름·휴대폰은 마스킹 없이 표시. 보낸 인증은 날짜별(오늘 포함)로 접고 그 안에서 이름별 한 줄, DB 연결 + 업체정보 반영이 끝난 사업자는 목록에서 빠짐, 시간 초과·취소는 「기록 삭제」. 원문은 「사업자명 서류이름.pdf」로 바로 내려받기. 같은 대표의 DB 에 없는 사업자는 (사업자 1곳일 때만) 새 DB 자동 생성 — 여러 곳이면 화면에서 「DB 등록」을 고른다(2026-11-09 개정).
- **「공동인증서로 가져오기」 탭**(belie 2026-11-08): 사용자가 고객의 공동인증서를 가진 경우, 휴대폰 승인 없이 인증서 로그인으로 사업자등록·부가세·재무제표 + **4대보험 가입자명부(인증서 전용)**·지방세 완납증명까지 한 번에. 입력은 대표 이름, 휴대폰(선택·DB 연결용), 인증서 파일(.pfx 또는 der+key), 인증서 비밀번호, 지방세면 주소. 인증서·비밀번호는 브라우저에서 제공사 공개키로 암호화해 보내고 서버에 저장하지 않는다(업체 계정 보관함은 비밀번호만 있어 파일은 매번 고름). 목록에는 회색 「인」 띠로 표시.
- **공동인증서 탭 보강(belie 2026-11-09)**: 법인·개인 인증서 모두 받는 서류 6종 동일 — 사업자등록증명·부가세 과세표준증명·표준재무제표증명·국세 완납증명·지방세 완납증명·4대보험 가입자명부(소득금액증명은 간편인증 탭에만). **폐업사실증명**(belie 2026-11-10) — 두 탭 모두 고를 수 있음(기본 선택 아님), 폐업 사업장만 나오고 개인(비사업자) 발급 불가, CODEF 간편인증 목록에 토스 없음. 인증서 종류(법인/개인)는 인증서 안의 정책 OID 로 자동 판별해 「법인 인증서 · 법인 서류로 가져와요」처럼 보여 준다(목업은 파일 이름으로 흉내). 법인 인증서면 법인 서류를 뽑는다(법인 대표 개인 간편인증으로는 법인 서류가 안 될 수 있어 미검증).
- **인증서 파일 변환**: 사용자는 .pfx(또는 signCert.der+signPri.key)와 비밀번호만 넣는다. 변환·접속은 앱이 한다 — 파일을 base64 로, 비밀번호는 제공사 공개키(RSA)로 암호화해 제공사 API 에 보내면 제공사가 기관에 로그인한다. 정확한 파라미터 이름(pfx 직접 지원 여부 등)은 구현 때 CODEF 문서로 확인(미검증).
- **지방세 주소 = 시·군·구 검색기(belie 2026-11-09)**: 정부24 발급기관 선택용으로 시·도+시·군·구를 검색해 고른다(「강남」「수원」처럼 일부만 쳐도). 목록은 기존 정본 `lib/util/admin-regions.ts`(SIDO·SIGUNGU, 지방세 부과 단위라 일반구 제외) 재사용. 법인 인증서면 라벨이 「본점 소재지」. CODEF 파라미터가 상세 주소까지 요구하면 구현 때 칸을 더한다(미검증).
- **화면 2단 + 하위 펼침(belie 2026-11-09)**: ① 보내기·가져오기 | ② 보낸 인증(날짜 → 사람 → 업체). 받은 서류·DB 연결·업체정보 반영은 따로 칸을 두지 않고 ② 의 업체 바로 밑에 펼친다. 업체·사람 줄은 제목행 전체를 눌러 여닫고, 요청의 업체가 1곳이면 바로 펼쳐 둔다. 업체는 여러 개를 함께 열 수 있다. 넓은 PC 에서는 학생 셸 전폭(PageContainer fluid), ① 은 1/3 폭. 사람 줄은 이름·번호·수단 띠와 상태·버튼(「다시」로 줄임)을 한 줄에, 칸이 모자라면 상태·버튼만 다음 줄로. 업체 줄도 넓으면 한 줄, 좁으면 두 줄. 펼침 규칙: 칸마다 처음 보일 때의 기본값(오늘·진행 중·업체 1곳)으로 정한 뒤 고정 — 저절로 닫히지 않고, 저절로 열리는 것은 새로 보내거나 다시 보낸 요청뿐(승인 완료·다른 업체 열기·업체 닫기로 사람·날짜 칸이 접히던 오류 수정, 클릭 시나리오 6개로 확인).
- 목록 표시(belie): 이름 칸 폭 고정으로 전화번호 시작 맞춤, 그 옆에 「수단 아이콘 + 날짜·시각」 띠(휴대폰은 시각만), 상태와 버튼은 한 줄, 실패 서류는 「재무제표 실패」처럼 이름으로.

## CODEF 데모 실측 (2026-11-08, belie 본인 계정·카카오 간편인증, 개인사업자)
| 확인 | 결과 |
|---|---|
| 1차 인증 요청 → 휴대폰 알림 | 약 2초, `CF-03002`(continue2Way, method=simpleAuth) |
| 승인 전 2차 요청 | 오류 아님 — `CF-03002`(대기) 반환. **2차 확인은 3번까지**, 3번째도 미승인이면 `CF-12872` 로 거래 종료 |
| 승인 후 증명서 | 사업자등록증명 약 9초(`CF-00000`) |
| 완료 뒤 같은 id 로 다른 서류를 따로 요청 | 승인 다시 요구(`CF-03002`) — 세션이 이어지지 않음 |
| **같은 id 로 서류들을 동시에 요청** | 먼저 온 요청만 2차 인증, 나머지는 줄 서서 대기. **승인 1번에 두 건 모두 도착**(부가세 과세표준증명이 5초 뒤 추가 승인 없이). 첫 요청이 실패하면 줄 선 요청도 같은 오류로 실패 |
| 4대보험 사업장 가입자명부 | 문서상 **공동인증서만**(간편인증 불가) → 이번 범위에서 제외 |
| 법인 대표 개인 간편인증으로 법인 증명 | 미측정(리드엠에스씨는 개인사업자) |

설계 반영: ① 서류 요청은 **같은 세션 id 로 한꺼번에** 보내고 첫 2차 인증만 처리. ② 승인 감지는 확인 3번 한도 → 간격을 넓게(예: 30·90·200초) + 「고객이 승인했어요」 버튼으로 즉시 확인. ③ 4대보험은 목업에서 제외. 실측 스크립트는 저장소에 넣지 않음(세션 임시 폴더), 키·개인정보·응답 값은 출력·기록하지 않음.

## CODEF 공동인증서 문서 확인 (2026-11-09, developer.codef.io 상품 페이지, 실호출 아님)
- 인증서 전달: 6개 상품 모두 `certType:"pfx"` + `certFile`(pfx 를 base64 문자열 그대로) 지원 — der/key 변환 불필요. `certPassword` 는 CODEF publicKey 로 RSA 암호화. 단 국세 납세증명(`nt/proof-issue/tax-cert-all`)은 certType 목록에 "1"/"2" 만 있어 pfx 는 실호출로 확인 필요.
- 개인/법인을 고르는 파라미터는 없다 — **상품(엔드포인트)으로 나뉜다.** 인증서 종류를 앱이 판별해 상품을 고른다.

| 서류 | 개인(개인사업자) 인증서 | 법인 인증서 |
|---|---|---|
| 사업자등록증명 | 홈택스 `nt/proof-issue/corporate-registration` (문서 확인) | 홈택스 같은 상품 — 출력부에 법인등록번호 항목만 있어 간접 확인. 대안: 정부24 `mw/corporation-business-registration/proof` (법인 명시) |
| 부가세 과세표준증명 | 홈택스 `nt/proof-issue/additional-tax-standard` (문서 확인) | 홈택스 쪽 법인 언급 없음(미확인). 대안: 정부24 법인사업자 부가세 과세표준증명 (법인 명시) |
| 표준재무제표증명 | 홈택스 `nt/proof-issue/standard-financial-statements` (문서 확인) | 같은 상품, 「법인의 경우 yyyyMM」 명시 (문서 확인) |
| 국세 납세증명 | 홈택스 `nt/proof-issue/tax-cert-all` (문서 확인) | 같은 상품 간접 확인. 대안: 정부24 `mw/proof-issue/corporation-tax-cert-all` (법인 전용) |
| 지방세 납세증명 | 정부24 `mw/localtax-payment-certificate/inquiry` — 주소·휴대폰 필수 | **별도 상품** 정부24 `mw/corporation-localtax-payment-certificate/inquiry` (공동인증서만) — 법인등록번호·사업자번호·주소·전화 |
| 4대보험 가입자명부 | `pp/4insure/business-establishment-subscribers` — 개인/법인 구분 문서에 없음(미확인). 로그인 뒤 사업장 목록이 와서 고르는 2단계, 가입자 300명 초과 사업장은 오류 | 같음 |

- **지방세 주소 형식(문서 확인)**: `address` 는 시·군·구가 아니라 **도로명주소(도로명 + 건물번호, 예 「세종대로 110」)**, 상세는 `addrDetail`. CODEF 는 도로명주소 API 결과를 조합하라고 안내한다. → 지금 목업의 시·군·구 검색기로는 부족하다. 도로명주소 검색(행정안전부 도로명주소 API, 별도 승인키 필요)으로 바꿀지 결정 필요.
- 지방세 완납증명은 위택스 상품에는 없고 정부24 뿐. 정부24 비회원 로그인은 보안숫자를 CODEF 가 자동 인식(2회 실패 시 수동).
- 남은 실측: 법인 인증서로 홈택스 1·2·4 번 실제 발급, 국세 pfx, 4대보험 개인/법인 — 데모 키 + 실제 법인 인증서(사용자 제공)로 확인해야 한다.

## 워크플로우 6개
1. **인증 보내기** — 수강생 화면. (업체 선택 없음) 대표 이름·생년월일·휴대폰(PASS면 통신사)·인증수단·받을 서류. 서버가 제공사에 1차 요청.
2. **승인 자동 감지** — 대기 한도 4분 30초(CODEF). CODEF는 2차 확인 3번 한도(실측) → 간격 넓게 + 「고객이 승인했어요」 버튼 병행. 틸코라면 완료여부 API 폴링.
3. **홈택스 자동 조회** — 서류들을 같은 세션 id 로 동시에 요청(실측: 승인 1번에 모두 도착). 요청 경로와 분리된 백그라운드 작업(통화 요약 대기열과 같은 구조).
4. **사업자별 서류함 저장 + DB 연결** — 응답을 사업자번호로 나눠 저장하고 위 순서로 DB 에 연결. 원문(PDF/XML) 암호화 저장(기존 vault 암호화), 핵심 숫자 정형값, 보관 90일(안) 뒤 삭제.
5. **결과 알림·조회·반영** — 웹 푸시(기존 push-sender), 서류함 화면, 「문서로 자동입력」 비교표(CompanyDocDiffTable·buildDiffRows) 재사용.
6. **운영** — 만료 서류 삭제, 하루 호출·실패·비용 집계(고객 정보 없이).
