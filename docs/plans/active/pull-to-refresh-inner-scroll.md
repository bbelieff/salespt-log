# 당겨서 새로고침 ↔ 안쪽 스크롤 (2026-10-24 belie 「모바일 위아래 스크롤이 잘 안 됨」)

## 원인
당겨서 새로고침은 **페이지**가 맨 위(scrollTop=0)면 아래로 끄는 손가락마다 `preventDefault` 를 건다. DB관리시트·실무/수납처럼
높이를 고정하고 안쪽 목록이 스크롤되는 화면은 페이지가 늘 맨 위라, 안쪽 목록을 위로 올리려는 손가락이 전부 막혔다
(아래로 내리기는 되고 위로 올리기만 뻑뻑함). 같은 터치 안에서 먼저 위로 밀었다가 되돌아올 때도 막혔다.

## 수정
- 터치 지점의 조상 중 세로 스크롤 영역이 맨 위가 아니면 새로고침 제스처를 시작하지 않고, 움직이는 중에도 그런 상태면 막지 않는다.
- 페이지·목록 모두 맨 위에서 끌면 기존처럼 새로고침.

## 2차 (같은 날 — belie 「위아래 스크롤 해결해. 특히 안드로이드가 더 그렇더라」)
- 원인: 문서 전체에 `touchmove` 를 `passive:false` 로 달아 두면 안드로이드 크롬은 **모든 스크롤**을 JS 처리까지 기다린다
  (화면이 무거울수록 뻑뻑). 앱 전체에서 막을 수 있는 터치 리스너는 이것 하나였다(grep 실측).
- 수정: 리스너 전부 passive, `preventDefault` 제거. 브라우저 기본 당겨서 새로고침·고무줄은 `globals.css` 의
  `overscroll-behavior-y: none`(모바일 터치 화면만)으로 끈다. 안쪽 스크롤 영역은 터치 시작 때 한 번만 찾는다(움직일 때마다 스타일 계산 X).
- 시험: 리스너 passive 확인 + 당김 표시 동작 4건.
- 미확인: 실제 안드로이드 폰 확인은 belie 필요. 그래도 뻑뻑하면 다음 후보 = 하단 탭바의 배경 흐림(blur 20px)이 스크롤마다 다시 그려지는 비용.
