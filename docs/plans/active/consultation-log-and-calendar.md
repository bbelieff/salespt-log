# 업체정보 & 캘린더 3종 기능 기획

## 0. 개요 (3개 기능)
- **[1] 캘린더 이벤트 클릭 → 해당 탭의 그 이벤트로 이동·포커스.**
- **[2] 예약비고 → 업체정보**: 04 업체관리에 구조화 필드 추가(미팅 단위 작성), **계약 시 06 업체정보 탭에 스냅샷으로 쌓기**, 드롭다운+팝업 UI, TXT 추출(업체관리 폴더, 업체당 1파일 덮어쓰기).
- **[3] 기존고객 일반이벤트**: 캘린더에 일반이벤트(투두) 추가. 05 실무투두에 저장하되 통계·아레나 미집계. 색상 구분, +버튼 팝업, 첫 추가 시 경고 모달(다시 안 보기).

## 1. 저장 설계 (확정)

### 1-1. 04 업체관리 컬럼 확장 (업체정보 = 미팅 단위 작성)
- 현재 A~S(19컬럼). **T부터 업체정보 필드 추가** (기존 수식 컬럼 N/O/Q/S 뒤라 안전).
- **[업체] 12 컬럼**: 개업일 · 사업자구분 · 사업자등록번호 · 소재지 · 소유여부 · 업종/주생산품목 · 과년도매출 · 금년도매출 · 기대출사업자 · 4대보험직원 · 특허및인증 · 업체기타메모
- **[대표자] 8 컬럼**: 대표자이름 · 연락처통신사 · 신용점수 · 기대출개인 · 자택주소지 · 대표소유여부 · 동종업계경력 · 대표기타메모
- **커스텀필드 JSON 1 컬럼**(`업체정보_커스텀`): "필드추가+"로 만든 비정형 필드만 `{"업체":{...},"대표자":{...}}` 형태로 담음.
- 합계 = 20 고정 + 1 JSON = **21 컬럼 추가** → 04 가 S(19)에서 약 AN(40)으로 확장.
- ⚠️ SSOT 갱신: `lib/config/index.ts` SHEET_RANGES.meetings.range(`A2:S`→`A2:AN`) + 필드 좌표 맵 추가, `docs/domains/sheet-structure.md` 04 섹션, `lib/types`(Meeting 확장). §2.5 bulk-write 보존 가드 동일 적용(raw 값 skip).
- **단위 주의**: 업체정보는 미팅 행에 붙으므로, 한 업체가 미팅 여러 번이면 최신 미팅 행의 업체정보를 갱신(편집은 그 미팅 카드에서). 계약 시 그 행을 06으로 스냅샷.

### 1-2. 06 업체정보 (계약 고객 표 — 신규 탭, 동기화 사본)
- **신규 탭 `06 업체정보`**, `ensureTodoTab` 패턴으로 자동 생성. **04와 동일하게 필드별 컬럼(셀)** 로 관리(JSON 덩어리 아님).
- **계약 시 1행 추가**: schedule 계약 액션(02 계약수납 행 생성 지점)에서 그 업체의 업체정보를 04에서 **복사해 06에 1행 추가** = "쌓인다"(계약 고객이 늘수록 행 누적).
- **동기화(박제 아님)**: 04 원본이 바뀌면 06의 같은 업체 행도 갱신. 실무/수납에서 편집해도 04 원본+06 둘 다 갱신(§3-1, §6). → 06 = "계약 고객만 모아 보는 동기화 표".
- 컬럼 = 04 업체정보 필드 미러 + 업체명·계약일·계약ref(02 행 키)·갱신시각.
- 키 = 업체명(+계약ref). 새 좌표 SHEET_RANGES.companyInfoArchive + sheet-structure.md 신규 섹션.

### 1-3. 05 실무투두 재사용 (일반이벤트)
- 일반이벤트 = **05 실무투두 row**, `contractRef`/`institutionRef` 빈값, `showOnCalendar=true`.
- **생성 카테고리 2종 선택**: `기존`(기존 고객 관리) · `기타`(개인 일정 등). 분류값을 05 실무투두에 저장(기존 type 미팅/전화/메시지/기타 와 별개 "분류" 컬럼이거나 type 확장 — 구현 시 정리).
- 통계·아레나 미집계: 투두는 4지표/퍼널 집계 대상 아님 → 자동 충족. dashboard/scoreboard 등 집계 경로가 일반이벤트를 안 건드리는지만 점검.

### 1-4. 연동 (탭 간)
- **일정/계약(schedule)**: 04 미팅 행에서 업체정보 직접 읽기/쓰기.
- **실무/수납(payment)**: 06(계약 스냅샷)에서 업체명·계약ref로 업체정보 읽기.
- **연결 키 = 업체명**(현 구조 유지). 동명 업체·오타 위험은 MVP 범위 밖(후속에서 업체ID 검토 — §6).

## 2. [1] 캘린더 이벤트 클릭 → 이동·포커스
- 현재: 캘린더(읽기전용)에서 선택일 우측 패널의 미팅/투두 카드 클릭 시 **아무 동작 없음**(`app/(app)/calendar`). "일정·계약 탭으로/실무·수납 탭으로" 버튼만 있음.
- 변경: **카드(또는 셀 안 pill) 클릭 → 해당 탭으로 이동 + 그 이벤트 포커스**.
  - **미팅** → `/schedule?date=YYYY-MM-DD&focus=<meetingId>` (이미 `?date=` 주차 align 존재 → `focus` 파라미터만 추가).
  - **투두/일반이벤트** → `/payment?focus=<todoId>` (또는 투두가 속한 탭). 일반이벤트는 연동 탭이 없으므로 캘린더 내 상세 팝업으로 대체 가능(§4).
- schedule/payment 페이지: `focus` 파라미터 읽어 해당 카드로 **스크롤 + 하이라이트 링(pulse)**. 기존 contact 의 `focus`/highlight 패턴(`ChannelTabsAndPanel` highlightKey ring) 재사용.
- 토큰: 하이라이트 링은 기존 focus pulse 토큰 재사용(신규 색 불필요).

## 3. [2] 업체정보 (UI · 저장 · 추출 · 연동)

### 3-1. 진입·표시 (드롭다운 + 팝업)
- **컨택관리(contact)·일정/계약(schedule)**: 기존 "예약비고" 입력 자리를 **"업체정보"**로 교체.
  - 기본은 **드롭다운(collapse)** — 접으면 요약 1줄, 펼치면 [업체]/[대표자] 필드 그룹 inline 편집.
  - **"팝업으로 보기/편집" 버튼** — 전체 화면 모달(필드 많아 집중 편집용). 기존 모달 패턴(`CrossTabHintModal`/`TodoFormModal`, z-[300]) 재사용.
- **실무/수납(payment)**: 계약 카드에 **업체정보 드롭다운 + 팝업 버튼** 추가. 06에서 읽고 **편집 가능** — 저장 시 **04 원본 + 06 둘 다 갱신(동기화)**. 어느 탭에서 고쳐도 한 업체정보가 일관 유지.

### 3-2. 필드 구성 (모달/드롭다운)
- [업체] 그룹: 1-1의 12필드 + **필드추가+**(커스텀, JSON 저장).
- [대표자] 그룹: 1-1의 8필드 + **필드추가+**.
- 하단: **저장** 버튼(04 행 update) · **업체정보생성(TXT 추출)** 버튼(§3-3).

### 3-3. TXT 추출 (업체정보생성)
- 버튼 클릭 → 업체정보 필드를 **사람이 읽는 텍스트**로 포맷 → **`업체관리` 폴더 또는 `피드백업체` 폴더**에 **업체당 1파일 덮어쓰기**.
  - 대상 = 그 수강생의 참가자 루트 폴더 하위 `업체관리`(또는 `피드백업체`) 폴더. 예시(사용자 제공, 참고용):
    - 아레나 참가자 예: https://drive.google.com/drive/folders/16C_WfkETUpWRH3eCLhFhprzNOG-MJASx
    - 일반기수 예: https://drive.google.com/drive/folders/1hmFfuai9npxY-qKvCFbEApL4430yYqdc
  - 파일명: `업체정보_{업체명}.txt` (덮어쓰기 = 항상 최신 1본).
  - 본문: [업체]/[대표자] 라벨:값 줄 + 추출시각.
- 구현: `lib/repo/drive-client.ts` 파일 쓰기(belie OAuth = `ADMIN_DRIVE_REFRESH_TOKEN`). findFolderByName 계열로 `업체관리`/`피드백업체` 탐색, 없으면 생성.
- ⚠️ "쌓기"는 **06 탭(계약 고객 동기화 표)**, **TXT 는 업체당 1본 덮어쓰기** — 둘은 별개 sink.

### 3-4. 저장 흐름
- 저장 → 04 업체관리 그 미팅 행의 T~AN 컬럼 update(+커스텀 JSON). §2.5 가드 준수. 계약 고객이면 06 같은 업체 행도 동기화.
- 계약 액션 시 → 04 업체정보를 06에 1행 추가(이후 동기화 유지, §1-2).

## 4. [3] 기존고객 일반이벤트

### 4-1. 저장·집계
- 05 실무투두에 `type="일반"`으로 저장(1-3). 통계·아레나 미집계.

### 4-2. 색상 구분
- 채널 4색(매입DB 파랑/직접생산 초록/현수막 주황/콜지기소 보라)·투두 slate-700 과 **구분되는 신규 색 1개** 필요.
- 제안: 중립 회색 계열 또는 미사용 hue(예: teal/cyan) — `docs/design/tokens.md`에 "일반이벤트" 색 토큰 추가 후 캘린더 pill·레전드 반영. (4채널 고정색 규칙 불변)

### 4-3. +버튼 · 생성 팝업
- 캘린더(현 읽기전용)에 **+버튼** 추가 → 일반이벤트 생성 모달.
- 모달 입력: **카테고리(기존/기타) · 이벤트명 · 업체명 · 상세내용 · 날짜 · 시간** → 05 실무투두 매핑(분류=기존/기타, 제목=이벤트명, 업체명, 상세=상세내용, 예정일자=날짜, 예정시각=시간, showOnCalendar=true). '기타'(개인 일정)는 업체명 선택 입력.
- 저장 → `appendTodo()`(+`ensureTodoTab`) → 캘린더 즉시 반영.

### 4-4. 경고 모달 (다시 안 보기)
- 일반이벤트 **첫 추가 시** 모달: "일반이벤트로 추가하는 일정은 다른 탭에 연동되지 않습니다. 기존업체 관련 실적은 아레나에 포함되지 않지만 캘린더에서 관리할 수 있습니다."
- **"다시 보지 않기" 체크박스** → 체크 시 localStorage(예 `hideGeneralEventHint`) 저장, 이후 미표시. (기존에 다시-안보기 패턴 없음 → 신규. localStorage 사용 — 앱 본체라 가능)

## 5. 디자인·토큰 영향
- 신규 토큰: 일반이벤트 색 1개(tokens.md). 그 외 모달·드롭다운·하이라이트는 기존 토큰/컴포넌트 재사용.
- 신규/확장 컴포넌트는 `docs/design/components.md` 등재 후 구현(업체정보 드롭다운, 업체정보 모달, 일반이벤트 생성 모달, 일반이벤트 경고 모달, 캘린더 +버튼).
