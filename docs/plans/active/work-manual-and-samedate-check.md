# 업무매뉴얼 버튼 + 같은 날 빨간 확인

**요청**: belie 2026-09-05

## [1] 실무·수납 탭 — 「이전 계약업체 등록」 → 「업무매뉴얼 보기」

같은 자리, 같은 모양(파란 톤 버튼)으로 교체. 노션 페이지를 **새 탭**으로 연다.

**기능은 지우지 않았다.** 버튼 + 2단계 모달을 통째로
`app/(app)/payment/_components/PriorContractRegister.tsx` 로 옮겼다. 되살리는 법은 그 파일
머리말에 두 줄로 적혀 있다(import 한 줄 + JSX 한 줄). **서버는 손대지 않았다** —
`POST /api/contract-payment/prior` 와 `lib/service/contract-payment-add.ts` 그대로라 붙이는
즉시 동작한다.

**이미 등록된 이전 계약은 그대로 보인다.** 02 계약수납관리에 남아 있고, 실무·수납 목록과
「이월 매출」 카드에 계속 집계된다(`isCarryoverContract`). 버튼이 사라진 것뿐이다.

주소는 `lib/config/links.ts` 의 `WORK_MANUAL_URL` 한 곳에만 둔다 — 바뀌면 한 줄만 고친다.
(테스트가 컴포넌트 하드코딩을 막는다.)

## [2] 저장 전 확인 — 같은 날은 빨강

기록하는 날짜와 미팅 예정일이 같으면 그 칸을 **빨강**으로 칠하고 칸 안에
**「확인 필요 · 기록일과 미팅예정일 동일」** 사유를 적는다.

**왜 색을 나눴나** (belie: "노란색으로 하면 헷갈릴 수 있음"): 노랑은 이미 **못 채운 칸**이
쓰고 있다. 둘 다 노랑이면 「채우면 되는 것」과 「맞는지 봐야 하는 것」이 섞여 안 읽힌다.

| 색 | 뜻 | 저장 |
|---|---|---|
| 노랑 | 아직 못 채웠어요 | **잠김** |
| 빨강 | 확인 필요 — 기록일 = 미팅예정일 | 가능(막지 않음) |

빨강이어도 **막지 않는다** — 당일 미팅은 실제로 있다. 판단은 수강생이 한다.
