# 데스크탑 반응형 + Toss UX Writing 개선

## 1. 문제
- 브레이크포인트가 전부 모바일(xs360~2xl768) → **데스크탑(≥1024px)에서 모바일 레이아웃이 화면 전체로 늘어나** 가독성↓·시선 이동 과다.
- 문구가 길거나 기계적 → 이해·신뢰도↓.

## 2. 반응형 전략 (사용자 결정: 혼합)
- **브레이크포인트 추가**: `pc:1024`, `wide:1280` (tailwind.config.ts). 데스크탑 규칙은 `pc:`/`wide:` 프리픽스만 사용.
- **PageContainer**(components.md §10): 페이지 루트를 감싸 데스크탑 폭 제어.
  - 입력 중심(컨택·일정·DB·로그인·온보딩) = `width="narrow"`(중앙정렬 max-w-2xl).
  - 정보 중심(캘린더·실무수납·대시보드·관리자) = `width="wide"`(max-w-6xl) + 내부 멀티컬럼.
- **캘린더·실무수납**(사용자 강조): 넓게 쓰되 가로 공간을 멀티컬럼으로 활용해 **세로 스크롤 압박을 줄임**.
- 모바일 레이아웃·구조는 **그대로 보존**(회귀 위험 최소화). 데스크탑 분기만 추가.
- 채널 4색·미팅 5색·brand-red 등 **색 토큰 변경 없음**(고정 규칙 유지).

## 3. 화면별 작업
| 화면 | 컨테이너 | 데스크탑 처리 |
|---|---|---|
| 컨택관리 | narrow | 중앙정렬, 주간/채널 패널 여백·타이포 정돈 |
| 일정·계약 | narrow→wide(주간 카드 많음) | 주간 미팅 카드 pc 2단 |
| 실무/수납 | wide | 진행 슬롯/계약 카드 pc 2단·wide 3단 (스크롤 압박↓) |
| DB관리 | narrow | 중앙정렬, 4채널 섹션 정돈 |
| 캘린더 | wide | 달력 + 일자상세를 pc 2단(달력 좌, 상세 우)로 — 세로 스크롤↓ |
| 대시보드 | wide | KPI·퍼널·채널·주간차트 pc 2~3단 그리드 |
| 관리자(users/cohorts/trainers) | wide | 카드 리스트 pc 2~3단 멀티컬럼 |
| 로그인/온보딩 | narrow | 중앙정렬 카드, 데스크탑 여백 |

## 4. Toss UX Writing 원칙 (카피 전수 적용)
1. **간결**: 군더더기 제거. 한 번에 한 메시지.
2. **명확**: 모호어 금지. 무엇을·왜를 분명히.
3. **사용자 언어**: 시스템/개발 용어 대신 사용자가 쓰는 말.
4. **친근한 높임말**: "~할게요 / ~했어요 / ~해 주세요" 톤. 명령·딱딱함 지양.
5. **핵심 먼저**: 중요한 정보·행동을 앞에.
6. **행동 가능**: 버튼은 동사+목적("저장" → "기록 저장하기"는 과함 → 맥락상 "저장"). CTA는 결과가 보이게.
7. **존중·안심**: 실패·삭제 메시지는 비난 없이, 다음 행동을 안내.

적용 대상: 버튼 라벨, 토스트(성공/실패), confirm 다이얼로그, 빈 상태, 배너, placeholder, 온보딩/로그인. (카피 전수표는 작업 중 본 문서 부록에 누적.)

## 6. 검수·배포 체크리스트 (사용자 PC)
1. `npm install` (이미 posthog-js 반영).
2. `npm run check` (typecheck·lint·structural·test·doc-drift) 초록.
3. `npm run build` (next build) 성공.
4. 데스크탑 폭(1280/1440)·모바일 폭(390)에서 각 화면 육안 확인(스크린샷 권장).
5. 브랜치 커밋 → PR → CI 초록 → 머지.
6. 배포(VPS/CI) — `docs/playbooks/deploy-vps.md`.
