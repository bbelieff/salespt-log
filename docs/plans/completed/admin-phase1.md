# 관리자 모드 1단계 정리 — 자리 옮기기·숨기기

## Intent
belie(2026-11-13 결정, 2026-11-16 「진행」): 제품은 고객(교육기관·영업조직)마다 DB 를 따로 두는 한 서버로 간다. 그 전에
관리자 화면을 «자리 옮기기·숨기기» 만으로 정리한다. 데이터 이전·API 계약 변경 없음, 모든 주소 유지.

## Acceptance Criteria
- [x] 메뉴 다섯 묶음: 운영 현황(/admin · /admin/reports) · 사람(수강생·트레이너·트레이너 페이지) · 과정(기수·아레나) · 알림(/admin/popup, 이름만 변경) · 설정(/admin/settings 신설). PC 왼쪽 메뉴와 폰 메뉴가 같은 목록(`lib/config/admin-nav.ts`).
- [x] 홈 = 「오늘 할 일」: 승인 대기 수강생·트레이너, 담당 없는 활성 수강생, 기수 생성 실패분(있을 때만), 새 오류 신고 — 숫자 + 링크. 읽기 전용 service `getAdminTodoCounts`.
- [x] 안 쓰는 기능의 진입점 숨김(`lib/config/admin-features.ts` — reserve·cohortArchive·shareScores 모두 false): 「유보 처리」, 활성 기수 「보관 처리」, 아레나 화면의 「공유왕 →」. 유보 수강생 목록·복귀, 보관한 기수 목록·활성화는 늘 보인다. 「실패분 재시도」는 실패가 있을 때만(기존 동작 확인). 서버 라우트·데이터 변경 없음.
- [x] 중복 정리: 트레이너 관리 ⑤ 수강생 명단확인 → 수강생 관리 링크.
- [ ] 트레이너 관리 ① 담당부여 제거 — **하지 않음**. 수강생 관리에는 «한 트레이너에게 여러 수강생을 한꺼번에(기수·전체 일괄)» 배정, 트레이너 정렬·관리부서 이동·내보내기가 없다. 수강생 관리 링크 옆에 「수강생별 담당 배정은 수강생 관리에서」 안내만 더했다.
- [x] 죽은 컴포넌트 `TrainerPlayerToggle` 삭제(가져다 쓰는 곳 0) + 문서 줄 삭제.
- [x] `app/admin/layout.tsx` 서버 가드(마스터·관리부서) — 화면별 가드는 유지(설정·DB 대조·알림은 마스터 전용).
- [x] 오류 신고함 `/admin/reports`(읽기 전용, 마스터·관리부서): 최신순 20건씩, 시각·보낸 사람·보던 화면·내용·상태·캡처(한 장씩). repo 읽기 함수 + service 권한 확인. 스키마 변경 없음.
- [x] `docs/scope.md` 머리말을 현재 범위로.

## 설계 메모
- 진단 도구(시스템 상태 띠 = 예전 「DB 파일럿」, DB 대조 링크, 동기화)는 설정 > 진단(기본 접힘)으로 옮겼다. 동작·API 는 그대로.
- 오류 신고 읽기는 표를 만들지 않는다(표가 없으면 빈 결과). 캡처(data URL, 최대 3MB)는 목록 쿼리에 싣지 않는다.
- 「새 오류 신고」는 status=new 이고 최근 7일인 건 — 상태를 바꾸는 기능이 아직 없어 기간으로 끊었다.
- 오류신고 푸시 알림을 누르면 `/admin` 대신 `/admin/reports` 로 간다.
- 메뉴 이름(「트레이너」 등 역할 이름)은 `lib/config/admin-nav.ts` 한 곳에 모았다 — 고객별 용어사전으로 옮길 자리.

## 범위 밖 / 남은 것
- 오류 신고 상태 변경(확인 중·처리함), 답장.
- 전광판의 「공유왕」 탭(수강생에게 공지하는 화면이라 이번엔 그대로).
- ① 담당부여를 없애려면 수강생 관리에 일괄 배정이 먼저 필요하다.
- 기능 스위치를 고객별 설정(DB)으로 옮기는 일.
- `/api/arena-self` 는 화면에서 부르는 곳이 없다(토글이 이미 죽어 있었음) — 라우트는 그대로 두었다.
