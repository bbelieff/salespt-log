## 구현 메모
- 조회·집계(`useTodayFollowUps`·`summarizeFollowUps`)·API·DB 는 손대지 않았다. 훅에 `hasRecords`(기록이 하나라도 있는지)만 더했다.
- 옛 목록 창(`.ft-panel` 표)은 「예정된 일 · 7일 안」 전용으로 남겼다(`FollowUpsDetailPanel`). 호버로 열리던 단계별 창은 없어졌다 — 단계는 구역 안 목록을 좁힌다.
- 줄을 누르면 그 줄 아래에 이유·세부 정보가 펼쳐진다(옛 창의 행 상세를 잃지 않으려고 — 목업에는 없던 것).
- 「날짜 확인」은 건수가 있을 때만 다섯 번째 칩으로 나온다(옛 「날짜 확인 N건」 버튼 대체).
- 「오늘 N건 처리」는 어림값: 그날 본 남은 건수의 최댓값 − 지금 남은 건수. 계정이 다르면 섞이지 않게 계정 표시의 짧은 해시를 함께 적는다. 관리자가 다른 사람 화면을 볼 때는 세지 않는다. 정확한 값은 2단계(서버 처리 기록).
- 진행도 줄은 폰도 한 줄로 압축하면서 「M/D 시작」·「종강총회」 글과 폰의 오늘 날짜를 뺐다(D-day 배지가 종강을 알린다).
- 띠를 두 번 그리지 않으려고 폰에서는 바깥 띠를 `display: contents` 로 풀고 CSS `order` 로 매출 묶음만 내린다.

## 전환 효과
1. **이어지는 전환** — `useZoneTransition`(`document.startViewTransition` + `flushSync`). 펼침/접기·0건 접힘은 구역 상자까지, 칩·단계 필터는 줄만 잇는다(구역이 살아 있어야 칩 표시가 미끄러지는 게 보인다). 240ms 감속 곡선, 전환 중에만 `<html class="tz-vt">`, root 는 전환에서 제외. 줄 이름은 앞쪽 6줄만.
2. **선택 바탕이 옮겨 가는 칩** — `useSlidingThumb` + `sliding-thumb.css`(transform·width·height 220ms). 급한 정도 칩 + 대시보드 기간 칩(`PeriodPicker slidingIndicator`, 기본 꺼짐 — 다른 화면은 그대로).
- 다시 쓴 기존 효과: `fx-skeleton`(불러오는 중) · `fx-grow-x`(비율 막대, 화면을 열 때) · `fx-check-pop`(0건이 된 순간의 체크).
- 알려진 한계: 구역 아래 구역들은 전환에 넣지 않아 구역 높이가 바뀔 때 즉시 자리를 옮긴다(구역만 240ms 로 이어진다).
