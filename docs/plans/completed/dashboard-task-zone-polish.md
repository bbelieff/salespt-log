# 할 일 구역 — 검수 후속 2건

## 배경
[펼친 목록 높이](dashboard-task-zone-expand-height.md) 검수에서 「손대지 않고 둔 것」으로 적은 두 가지를 belie 가 고치라고 지시했다(2026-11-25).

## 1. 구역 높이가 바뀔 때 아래 묶음이 뛰어오름
- 원인: 펼침/접기 · 0건 접힘 전환에서 구역만 전환 이름을 받았다. 이름이 없는 아래 묶음(성과 제목·성과·차트, 폰은 매출 띠)은 전환 없이 바로 새 자리로 가서, 줄어드는 옛 구역 그림과 약 0.2초 겹쳤다.
- 수정: 구역 상자까지 찍는 전환(`html.tz-vt-zone`) 동안 아래 묶음에도 이름을 준다. 이름이 겹치면 브라우저가 전환 전체를 취소하므로 page 가 `data-tz-after="1~5"` 순번을 주고 CSS 가 순번마다 다른 이름을 건다. 알림 권유 판은 하나뿐이라 클래스로 건다.
- 범위: 구역 높이가 바뀌는 전환만. 칩·단계로 좁히는 전환은 구역을 찍지 않으므로(칩 표시가 미끄러지는 모습을 살리기 위해) 그대로다.
- 미지원 브라우저 · 동작 줄이기: 전환 자체가 시작되지 않으므로 영향 없음.

## 2. 좁혀 둔 조건의 일이 0건이 됨
- 증상: 칩·단계로 좁혀 둔 채 화면에 머무는 동안 그 조건의 일이 모두 처리되면 「이 조건에 해당하는 일이 없어요」만 남고, 다른 남은 일이 가려진다.
- 수정: 조회 결과가 바뀌는 순간에, 바뀌기 전에는 조건에 맞는 일이 있었는데 바뀐 뒤 하나도 없고 남은 일은 있으면 조건(칩·단계)을 풀고 목록을 접는다.
- 그대로 두는 경우: 사용자가 직접 0건짜리 조건을 고른 경우. 안내 문장(「전체」를 누르면…)이 그대로 뜬다.

## 수용 기준
- 0건으로 접힐 때와 펼침/접기 때 아래 묶음이 구역과 같은 길이로 움직이고 겹치지 않는다(전환을 느리게 해서 중간 장면 확인).
- 좁혀 둔 조건이 조회 변화로 0건이 되면 「전체」로 돌아가 남은 일이 보인다. 조건에 맞는 일이 남아 있으면 건드리지 않는다.
- 전환 이름 중복 없음(시험으로 고정).
