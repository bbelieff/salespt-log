# 주간 보드 길찾기 — 주소 고르기·직접 적기 (시안 v45)

- 요청: belie 2026-11-12 시안 댓글 「주소지가 애매하면 직접 적을 수 있게 함. 미팅카드, 업체정보, 그외 등록된 정보들(사업자등록증명등) 중 가장 신빙성있는걸 가져오기」 → v45 → 2026-11-13 「v45 운영 반영」.
- 확인한 사실: 사업자등록증 판독(`lib/document-ocr/parse-certificate.ts`)·간편인증 사업자등록증명(`lib/service/simple-auth-parse.ts`)이 읽은 주소는 따로 저장되지 않고 업체정보 「소재지」 칸을 채운다. 그래서 「사업자등록증」을 별도 후보로 두지 않고 소재지가 그 값을 대표한다.

## 수용 조건
- [x] 후보 순서(`@/util/map-links` `routeCandidates`): 직접 적은 주소 → 미팅 장소(번호까지 있는 주소) → 업체정보 소재지 → 미팅 장소(그 밖). 첫 후보가 기본값·「추천」. 기존 규칙(주소꼴 장소 우선, 아니면 소재지)과 같은 결과에 직접 적은 주소만 앞에 더했다.
- [x] 후보가 둘 이상이면 출처·주소를 보여 주고 눌러 바꾼다.
- [x] 번호가 없는 주소는 주황 안내 + 입력칸이 처음부터 열림. 「주소 직접 적기」→「이 주소로」.
- [x] 적은 주소는 이 기기에 미팅별로 기억(localStorage `map-route-own`, 최근 50건). 「업체정보 소재지로 저장」을 누르면 업체정보에 저장(기존 미팅 저장 함수).
- [x] 1280px 미만 목록 카드의 길찾기(MapRouteButton)는 그대로.

## 시안과 다른 점
- 시안의 「사업자등록증」 후보 줄은 없다(위 사실). 미팅 장소가 번호까지 있는 주소면 소재지보다 앞(그 미팅이 실제로 열리는 곳 — 2026-11-07 승인 규칙 유지).
- 소재지 저장은 묻지 않고 「업체정보 소재지로 저장」 링크로 둔다.

## 범위 밖
미팅별 주소를 DB 에 저장하는 새 칸, 목록 화면 길찾기 변경.
