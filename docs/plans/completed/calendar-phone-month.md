# 캘린더 탭 폰·태블릿 월 보기 — 꽉 찬 달력, 그 날 창, 「주 | 월」

## Intent (왜)
belie 2026-11-12 「pc는 먼저 진행하고 폰화면기획 따로」 → 폰 기획안·시안 → 2026-11-13 「바텀탭 아니고 사이드탭 · 구글캘린더처럼 일당 서너개는 일정이 보여야」 → 시안 v2 → 「추천대로 구현」.
폰 캘린더는 칸 글씨가 잘려 읽기 어렵고, 일정을 누르면 다른 탭으로 넘어갔다. 달력을 화면 가득 쓰고 그 자리에서 처리하게 한다.
시안: docs/design/prototypes/calendar-phone.html (v2). PC: docs/plans/completed/calendar-month-board.md

## Acceptance Criteria (수용 기준)
- [x] 1280px 미만 캘린더 = 달력이 화면 높이를 꽉 채우고 칸마다 일정 이름 3줄 이상(5줄 달 4~5줄, 6줄 달 3~4줄), 넘치면 「+N」
- [x] 메뉴는 지금처럼 왼쪽 사이드탭(하단 탭 없음). 달 이동·「주 | 월」은 페이지 띠에
- [x] 날짜 칸 → 아래에서 올라오는 그 날 창(메모·전체 일정·「+ 일정」), 일정 → 같은 자리에서 미팅 결과·투두·일반 일정 지우기, 「뒤로」로 목록 복귀
- [x] 「대기 N」 → 이번 달 미팅 결과·결과 대기 목록, 톱니 → 요일 순서·구글 캘린더
- [x] 일정·계약 탭 폰 화면 페이지 띠에 「주 | 월」(미팅 카드는 그대로 — 2단계)
- [x] 데이터·저장은 PC 한 달 보드와 같은 함수(`useMonthData`) — 계약 장부 연결 규칙 불변
- [x] `bash scripts/check.sh` 통과, 합성 화면 390×844 · 900×760 · 1100×800 확인 — CI·배포·로그인 화면은 worklog

## 추천안과 다르게 둔 곳
- 「한 달 보드를 1024px부터」는 하지 않았다. 실제 화면은 사이드탭 224px 이 자리를 차지해 그 폭에서 보드 달력 칸이 56px 쯤으로 좁아진다(기획안의 「100px쯤」은 사이드탭을 빼먹은 계산). 보드는 주간 보드와 같은 1280px 부터, 1024~1279px 는 꽉 찬 달력을 넓게 쓴다.
- 「+ 일정」은 시안의 간단한 창 대신 기존 일반 일정 만들기(GeneralEventModal: 분류·업체명·시간·첫 안내)를 쓴다 — PC 한 달 보드도 같은 것으로 되돌렸다(#1431 에서 분류·업체명 칸이 빠졌던 것).
