# 할 일 구역 — 줄 칩과 오른쪽 열 보기 전환

## 배경과 승인
- 기획서: https://claude.ai/artifact/FCc1WcovjEkNjsdSbbCSsd
- belie 2026-11-25: 「PC 풀사이즈에서는 공간이 있으니 행 안에서 칩으로 어떤 일인지 분류해 안내」 → 기획 → 「우측열에 토글로 종류·단계·이유 뷰, 단계는 스텝 아이콘으로 어디가 병목인지」 → 「좁은 PC 에서 열기 버튼이 아래로 내려갈 필요 없음, 중복 빼고 한 줄로」 → 「좋다 B로 진행」.
- 기획서의 권고를 그대로 따른다: 종류 이름 여섯 가지, 이유 문구는 쉬운 말로, 「몰림」은 건수 기준.

## 결정
1. **종류 칩**(PC 전체): 줄 맨 앞 배지 옆, 같은 폭, 색 없이 아이콘 + 두세 글자. 전화 · 날짜 · 미팅 · 기록 · 정하기 · 할 일.
2. **이유 칩**(넓은 PC, 줄 본문 칸 760px 이상): 최대 두 개, 「열기」 왼쪽. 나머지는 줄을 펼치면 보인다.
3. **좁은 PC**: 이유 칩과 「STEP n 단계」 글자를 빼서 「열기」가 늘 같은 줄에 있다. 폰은 지금 그대로(칩 없음).
4. **오른쪽 열**: 「단계 · 종류 · 이유」 보기 전환. 한 번에 한 기준만 보이고 보기를 바꾸면 고른 조건이 풀린다 → 좁히는 방법은 늘 둘(급한 정도 칩 + 오른쪽 열 하나). 고른 조건은 목록 위에 「…만 보는 중 · 풀기」.
5. **단계 보기**: 사이드 탭과 같은 STEP 배지(`StepBadge`)를 세로 흐름으로. 건수 · 급한 정도 막대(길이 = 건수 비례) · 가장 오래 밀린 날수 · 7일 넘게 밀린 건수. 건수가 혼자 가장 많고 3건 이상인 단계에 「몰림」. STEP 1 DB생산은 흐리게(세지 않음 — 주간 목표에서 봄).
6. 마지막으로 본 보기는 이 기기에 기억한다(`followups-side-view`). 저장소를 못 써도 동작한다.

## 분류 규칙 (`lib/analytics/follow-up-work-kind.ts`)
| 종류 | 근거 |
|---|---|
| 전화 | `lead:` 항목(첫 연락·다시 연락) |
| 날짜 | `lead:` 이면서 「다음 연락일 정하기」 |
| 미팅 | `meeting:` (오늘 미팅·미팅 준비) |
| 기록 | `meeting:` 이면서 「미팅 결과 입력」 |
| 정하기 | `stalled:` (다음 할 일 정하기·진행기관과 다음 할 일 확인) |
| 할 일 | `todo:` (직접 등록한 할 일·공고 신청 준비) |

이유는 이미 계산된 `reasons` 를 쉬운 말로 바꾼다: 진행기관 없음 → 기관 없음, 다음 할 일 없음 → 다음 할 일 비어 있음, N일 이상 진행 정체 → N일 넘게 멈춤, 조건 대기(단기관리) → 조건 대기, 공고 신청 준비 → 공고, 미팅 결과 미입력 → 결과 안 적음, 「재통화 · 다음 연락일 없음」은 둘로 나눈다. 「미완료 할 일」은 정보가 없어 칩을 만들지 않는다. 모르는 이유는 그대로 보여 준다.

## 수용 기준
- PC 줄의 「열기」가 어떤 폭에서도 줄 아래로 떨어지지 않는다(이유 칩 유무와 무관).
- 폰 줄은 바뀌지 않는다.
- 오른쪽 열 세 보기의 건수가 목록과 맞고, 누르면 그 조건으로 좁혀진다. 보기 전환 시 조건이 풀린다.
- 분류가 기대는 문구가 생성 코드와 어긋나면 시험이 실패한다.
