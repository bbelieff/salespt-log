# 8/7 개막일 아침 점검표

## 0. 오늘(8/6) 안에 먼저 끝내야 하는 것 — 아직 안 끝남

이 두 가지는 **직접 구글시트를 열어서 눈으로 봐야** 확인되는 것들이라, 이 세션(AI)이 대신 할 수 없었습니다. 8/7 전에 belie가 직접 봐 주세요 (2분이면 됩니다).

1. **대시보드에 `#VALUE!`가 떠 있는지** — 10기 학생 시트 아무거나 열어서 대시보드 탭 확인.
   - 뜬다면: [ID로 수식 설치] 버튼을 다시 눌러서 재설치.
2. **영업관리 탭 O1(수강시작일)·O2(종강일)이 날짜로 제대로 들어갔는지** — O1=2026-08-07, O2=2026-09-26 이어야 합니다.
   - 숫자나 글자로 보이고 날짜 모양이 아니면 잘못 들어간 것 — `docs/playbooks/arena-season-launch.md` "이미 만들어진 시트를 고칠 때" 항목과 같은 방식으로 다시 넣어야 합니다(텍스트 말고 날짜 값으로).

이 두 가지는 8/5 작업 기록에 "belie 육안 2분"으로 이미 적혀 있던 항목인데, 이 문서를 쓰는 시점까지 아직 완료 표시가 안 되어 있었습니다.

## 3. 서버 자체에 문제가 있어 보일 때

1. `https://salesptlog.online` 자체가 안 뜨거나 계속 에러면 — **코드를 되돌리지 말고 먼저 상태부터 본다.**
2. Claude Code 세션에게 "배포 상태 확인해줘" 요청 — GitHub Actions "Deploy to VPS" 최근 실행 결과를 봐 줍니다.
3. 진짜 배포 실패(코드 문제)로 확인되면 → 롤백은 CLAUDE.md §6.8 절차(직전 정상 버전으로 되돌리고 재배포) — Claude Code 세션에게 그대로 요청하면 됩니다.
4. **VPS 접속 타임아웃**처럼 보이는 실패는 코드 문제가 아닌 경우가 많습니다(오늘 하루에도 여러 번) — 롤백하지 말고 재시도부터.

## 4. 이 점검표를 만들면서 실제로 확인한 것 / 확인 못 한 것

정직하게 남깁니다 — 아래 "확인 못 한 것"은 belie나 실제 계정을 가진 사람이 한 번은 직접 밟아봐야 하는 부분입니다.

**확인함**
- 클레임 화면 코드(성공/실패 경로) 전부 읽음 — 로직상 문제 없음.
- 빈 이름·한 글자 이름을 넣으면 제출 버튼이 아예 눌리지 않는 것 라이브로 확인.
- 로그인 안 된 채로 제출하면 에러 없이 로그인 화면으로 안전하게 돌아가는 것 라이브로 확인.
- 관련 자동 테스트 92개 전부 통과(클레임 매칭·기수 파싱·아레나 가드 등).
- 10기 시트 6개·레지스트리 사전등록 6행은 8/5에 이미 실측 확인됨(별도 기록).
- 클레임 즉시 활성화 로직 확인 — **학생이 클레임하면 관리자 승인 없이 바로 사용 가능**합니다(승인 버튼 누를 필요 없음).

**확인 못 함 (이 세션의 한계)**
- **실제 구글 계정으로 로그인해서 클레임 성공까지 끝까지 밟아보는 것.** 이 세션은 AI라 구글 계정으로 로그인할 방법이 없고, 실제 학생 6명 중 한 명의 이름으로 테스트하면 그 학생의 1회성 클레임 기회를 써버리게 되어(계정 소진 위험) 시도하지 않았습니다. → **belie 또는 신뢰 가능한 계정을 가진 사람이 위 §1-③처럼 클레임 성공 사례를 한 번은 직접 확인하는 것을 권장**합니다.
- **카페(네이버 카페) 쪽 0주차 과제 기록 연동.** `hw_config`는 이 웹앱(경영일지) 레포와 완전히 분리된 별도 시스템(카페봇, `salespt-cafe-bot`)이 관리합니다. 이 세션은 그 프로젝트에 접근 권한이 없어 "10기 추가 후 0주차 기록이 실제로 들어가는지"는 검증하지 못했습니다. → **카페 세션(담당자)에게 직접 확인 요청 필요**.
