# 아레나 시즌 개막 체크리스트

## 왜 두 값을 맞춰야 하나

전광판은 서로 다른 두 곳에서 값을 읽는다. **둘 다** 새 시즌 개막일이어야 한다.

| # | 값 | 어디에 | 무엇을 결정 |
|---|---|---|---|
| ① | 시즌 개강일 | `cohorts` 탭 시즌 행(`A{n}`) **J열** | 전광판 **시즌 번호·주차** (`arena-season-config`) |
| ② | 수강시작일 | 참가자 개인시트 **`영업관리!O1`** | 시트 대시보드 `C33:H40` **주차 버킷** = 전광판 **표·랭킹 숫자** |

## ⚠️ ②를 놓치면 생기는 일 (가장 큰 위험)

`create-arena-members`(로스터 생성)는 **개강일을 쓰지 않는다**. 일반 기수 생성(`create-cohort-members`)과
다른 점이다. 그래서 복제된 시트에는 **템플릿의 O1 이 그대로** 남는다.

템플릿이 이전 시즌 개강일을 갖고 있으면:

- 개막일 기록이 `weekIndexOf(개막일, 이전 개강일)` = **9주차 이상**으로 계산된다
- 전광판이 읽는 대시보드는 **1~8주만** → 새 시즌 기록이 통째로 빠진다
- **전광판에 새 시즌 참가자가 전원 0.0** 으로 시즌 내내 표시된다
- 개강일+70일이 지나면 참가자 **본인 대시보드도 집계가 멈춘다**

헤더는 "아레나 시즌N · 1주차"라고 정상으로 보이기 때문에 **눈치채기 어렵다**. 반드시 확인한다.

## 절차

1. **시즌 템플릿 준비** — 마스터 템플릿을 복사해 `영업관리!O1` = 개막일, `O2` = 종강일(O1+50, ADR-0005)로 설정.
2. **cohorts 시즌 행에 템플릿 지정** — `A{n}` 행 **E열(templateSheetId)** 에 위 시트 ID.
   (또는 [아레나 추가] 모달의 템플릿 ID 칸에 직접 입력 — 기본값은 일반 마스터라 **그대로 두면 안 된다**.)
3. **로스터 생성** — 관리자 화면 [아레나 추가].
4. **시즌 개강일 입력** — `/admin/cohorts` → `A{n}` 행 **[시즌 개강일]** 에 개막일 저장.
   - 빈칸이면 전광판은 시즌 번호를 표시하지 않고 데이터도 자르지 않는다(안전 degrade).
   - 미래 날짜면 그 날짜부터 전환된다(개막 전에는 이전 시즌 유지).
5. **진단 실행** — VPS 에서:
   ```bash
   node scripts/ops/arena-season-readiness.mjs --season 2
   ```
   읽기 전용이며 ①②를 모두 점검한다. 종료코드 0 = 준비 완료, 1 = 조치 필요(문제와 해결법 출력).
6. **개막일 당일 확인** — 전광판 헤더가 `아레나 시즌N · 1주차` 이고 표에 숫자가 들어오는지 육안 확인.

## 이미 만들어진 시트를 고칠 때

로스터를 먼저 만들었다면 각 참가자 시트의 `영업관리!O1`·`O2` 를 직접 수정한다.
날짜는 **텍스트가 아니라 날짜 값**으로 입력한다(`USER_ENTERED` 규칙 — 과거 `#VALUE!` 사고 참고:
`docs/worklog-archive/2026-07.md` 9기 건). 수정 후 5번 진단을 다시 돌린다.
