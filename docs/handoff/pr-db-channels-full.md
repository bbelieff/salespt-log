## 1. 확정 위험 해결 (반드시 이대로 반영)

- **R1 컨택 생산 칸**: 편집 스테퍼 제거 → 채널별 **읽기전용 표시**(자물쇠). 매입DB=유입대기, 직접생산=생산기간, 현수막=오늘 게시/남은, 콜지기소=발굴(오늘 수). "오늘 합계" 칸은 헤더+첫 행 세로 병합(첫 행은 합산 제외), 유입~미팅예약만 4채널 합산.
- **R2 현수막 1:N (확정)**: 주문 1행 + 게시 N행. 게시 로그를 `03 DB관리` 내 새 섹션 `AF:AI`에 두고(주문 행은 P:V 그대로 1행 유지), `productionCountFor(현수막)`을 **게시일(AH)** 기준 Σ게시수(AI)로 재정의(기존 `날짜`=발주일 매칭 제거). 상세 = §3.
- **R3 직접생산 기간·2단계 (확정 — 정식 컬럼 방식 E)**: `I:N`을 **`시작일(I)·종료일(J)·소재(K)·기간예산(L)·생산개수(M)·기타(N)`** 로 재배치. **`개당단가`는 시트 저장 안 함** → 화면에서 `예산÷개수` 계산 표시(대시보드 비용은 `기간예산` 사용이라 안전). 정식 날짜 타입 2칸(파싱 불필요·정렬/집계 안정). **상태 컬럼 없이 `생산개수` 빈=생산중·채움=완료로 파생.** '생산 시작'=시작/종료일·예산 기록(생산개수 빈). '추가'=생산개수 입력(완료). `productionCountFor(직접생산)` = 종료일(J)==date AND 생산개수 채워짐일 때 Σ생산개수. 비용(예산)은 시작 시 반영. **마이그레이션(1회)**: 레거시 `날짜·소재·예산·생산개수·개당단가·기타` → 시작=종료=날짜, 소재·예산·생산개수 이동, 개당단가 드롭, 기타 이동. formulaCols에서 개당단가 제거.
- **R4 부가세 (확정 — 시스템 원칙)**: 돈 입력(비용·매출 공통)마다 **`부가세여부`를 저장**하고 **인식은 항상 부가세 제외**(미포함=그대로, 포함=÷1.1). DB생산 비용: 매입DB·현수막에 `부가세여부` 컬럼 추가 — 파생 가능한 `주문금액`(=개당단가×개수) 시트 저장을 빼 자리 확보(대시보드는 계산값으로 read). 입력=총액+개수+부가세→개당단가(부가세 제외) 역산. 부가세여부 저장으로 원 총액도 역산 복원(재편집 완벽). ⚠️ **직접생산 I:N은 이미 6칸 만석** → 예산 부가세여부 추가는 컬럼 자리 부족(상세 §3). **매출측(수임비·수수료 수납)은 이 문서 범위 밖 → 별도 워크스트림**(아래 §7).
- **R5 유입대기**: `생산누적 − 유입누적`(수강시작~선택일, 매입DB 채널만). 시트 수식 신설 금지 — service/클라 파생(이미 E·F를 읽는 `readWeekFunnel`/loadDay 경로 활용). 누적 기준 = **전체 수강기간**.
- **R6 보존가드**: 현수막 게시 N행을 쓰는 신규 함수는 §2.5 의무 대상 → `db.ts` 패턴(findFirstEmptyRow + isSumRow 필터)으로 row 단위 안전 확보, 타 사용자값 비침범. `writeProductionCell`의 overwrite 면제는 ADR-0020 한정이라 신규 함수엔 적용 안 됨.
- **R7 게이미피케이션**: `lib/service/gamification.ts`가 `r.production`을 XP에 사용 → 집계 방식 변화로 XP 총량이 달라질 수 있음(부수효과). **XP 가중치는 건드리지 말 것**(건드리면 ADR 필요). 회귀만 확인.
- **R8 SSOT 문서**: `sheet-structure.md`(현수막 1:N·직접생산 기간/상태·부가세 컬럼), `data-model.md`(Zod 타입) 동시 갱신. 신규 최상위 `SHEET_RANGES` 키 추가 시 sheet-structure에 등재(doc-drift). stale 라인 수정: L56 "03 DB관리 MVP 미사용"→가동 중, L730 "H=컨택성공"→미팅예약.

## 2. 채널별 확정 스펙

| 채널 | DB생산 입력 | 컨택 첫 행(읽기전용) | 생산 집계 기준일 |
|---|---|---|---|
| 매입DB | 구매 단건: 주문일·총금액·주문개수·부가세여부 → 개당단가 역산 | 유입대기 = 생산누적−유입누적 | 구매일 |
| 직접생산 | ① 생산 시작(기간 시작~종료·소재·예산) → ② 기간 후 생산개수 입력·추가(완료). 개당단가=예산÷개수 | 생산기간 표시(기간 밖 −) | 기간 종료일 |
| 현수막 | ① 주문(주문일·총금액·주문장수·부가세→장당가 역산) → ② 도착일 → ③ 게시(게시일·게시수, 주문장수까지 N건 추가) | 오늘 게시 / 남은(주문−게시누적) | 게시일 |
| 콜·지·기·소 | 영업기회 단건(구분·접수일·대표자·업체·소개처·연락처·조건). 비용 없음 | 발굴(생산) 오늘 수 | 접수일 |

공통(컨택): `유입·컨택진행·미팅예약` 스테퍼 + "모든 DB채널 합산". 첫 행은 채널 고유값이라 합산 제외(합계 제목 세로 병합). 디자인 정본 = `docs/design/prototypes/` 의 본 세션 시안.

생산 시작/도착/게시·주문 등 단계 = 기존 `미팅 예약→완료` 패턴 재사용(새 멘탈모델 0).

## 3. 시트 스키마 변경 (03 DB관리 + 연동)

> **부가세 원칙(시스템 공통)**: 비용·매출 입력마다 `부가세여부` 저장, 인식은 항상 부가세 제외(미포함=그대로, 포함=÷1.1). 아래는 비용측(DB생산). 매출측은 §7.

- **매입DB (B:G)**: `구매일·업체명·개당단가·주문개수·부가세여부·기타`. 기존 `주문금액`(=개당단가×개수) **시트 저장 제거 → 그 자리에 `부가세여부`**. 주문금액은 대시보드가 계산값으로 read. 개당단가는 부가세 제외(입력 총액·개수·부가세→역산).
- **직접생산 (정식 컬럼)**: `I:O` 재배치(**스페이서 O 흡수**, 현수막 `P:V` 위치 불변) = `시작일(I)·종료일(J)·소재(K)·기간예산(L)·생산개수(M)·부가세여부(N)·기타(O)`. 개당단가 시트 저장 X(화면 계산=예산÷개수). 상태 컬럼 없음(생산개수 유무 파생). 집계=종료일&완료. 인식 예산=부가세 제외. 마이그레이션 1회: 레거시 날짜→시작=종료, 개당단가 드롭.
- **현수막 (확정)**: 주문 섹션 `P:V` = `주문일·업체명·도착일·개당단가·주문개수·부가세여부·기타`(기존 `주문금액`→`부가세여부` 의미 변경, 주문금액 계산값). **게시 로그 = `03 DB관리` 내 새 섹션 `AF:AI`** (콜지기소 `AD` 뒤, 스페이서 `AE` 다음). `SHEET_RANGES.dbManagement.sections` 안에 nested 추가(신규 최상위 키 아님 → doc-drift 부담↓). 1행=1게시, 앱 append/update/delete:
  - `AF 게시id`(UUID, 키) · `AG 주문ref`(= `주문일\|업체명`, P:V의 날짜+업체명 합성) · `AH 게시일`(date) · `AI 게시수`(number)
  - 한 주문이 여러 날 게시 → 같은 `주문ref`로 게시 행이 아래로 누적(주문 행은 1행 유지).
  - 집계: 현수막 생산(E) = Σ`AI` where `AH`==date. 같은 게시일 여러 건이면 합산.
  - 남은 = (주문ref의 P:V 주문개수) − Σ(같은 주문ref의 AI).
  - 보존가드(§2.5): id 기준 자기 행만 update, append는 `AF` 빈 행 + FORMULA pre-read로 타값 비침범. 게시수 합이 주문개수 초과 못 하게 입력 검증.
- **집계 재정의**: `productionCountFor`을 채널별 기준일/상태에 맞게 분기 재작성(직접생산=종료일&완료, 현수막=게시일 로그 합). `syncProduction` 호출 지점(주문/게시/생산완료/삭제)마다 해당 날짜 E 재집계.
- **남은/유입대기**: 시트에 컬럼 신설 말 것 — 읽을 때 service/클라에서 파생.

> 운영 중(아레나 시즌1) 전 수강생 시트 영향 → 컬럼 추가·마이그레이션은 소수 시트 먼저 검증, plan에 명시.

**저장·인식 규칙(확정)**
- 모든 비용 **저장값 = 부가세 제외(인식값)**. 입력 시 부가세 포함이면 ÷1.1 후 저장. `부가세여부`는 재편집·감사용 플래그(원 총액 역산 복원).
- 대시보드·영업이익은 저장된 ex-VAT 값을 그대로 read(추가 보정 불필요). 단 기존에 `주문금액`을 시트에서 읽던 대시보드 경로는 **계산값(개당단가×개수)** 으로 바꿀 것.
- `01 영업관리 E(생산)` 좌표·쓰기 방식 불변(DB집계 소유, `writeProductionCell`). **집계 기준일만 채널별**: 매입DB=구매일, 직접생산=종료일&완료, 현수막=게시일, 콜=접수일.
- `SHEET_RANGES.dbManagement.sections`에 `현수막게시`(AF:AI) nested 추가 + 각 섹션 cols/formulaCols 갱신. `data-model.md` Zod 타입, `sheet-structure.md`는 **구현 PR이 갱신**(현재 SSOT는 코드 반영본 유지).
- 매출측(04 수임비·02 수납) 컬럼 위치는 §7 — 다음 기획에서 확정.

## 7. 매출측 부가세 표준화 (별도 워크스트림 — 이 문서 범위 밖, 후속 PR)

부가세 원칙(§3 상단)은 **매출에도 동일** 적용: 수임비·수수료 수납 입력 시 `부가세여부` 기록, **매출 인식은 항상 부가세 제외**(미포함=그대로, 포함=÷1.1).

**저장 규칙(비용과 동일)**: 저장값 = 부가세 제외(인식값). 입력 시 포함이면 ÷1.1 후 저장, `부가세여부`는 플래그(원 입금/청구액 ×1.1 역산 복원). → 영업관리 O·대시보드·D3/D4 등 합계 수식은 그대로 두면 자동 ex-VAT.

- **수임비** (`04 업체관리!L`): 저장을 **부가세 제외 수임비**로(입력 포함이면 ÷1.1). **신규 `AT = 수임비_부가세여부`** (확장 AQ~AS 뒤 append, 컬럼 이동 금지). 04 `L`을 참조하는 수식(N/O/Q·영업관리 O 수임비합계 SUMIFS)은 L이 ex-VAT면 자동 ex-VAT. 02 `E`(수임비 미러)도 ex-VAT.
- **수수료 수납** (`02 계약수납관리` 슬롯 수납액 `Q/W/AC`): 저장을 **부가세 제외 수납액**으로. **신규 `AK/AL/AM = 수납1/2/3_부가세여부`** (이월 `AI/AJ` 뒤 append). D3/D4 수납총액 SUMIFS는 자동 ex-VAT. 승인금액(P/V/AB)도 같은 슬롯 부가세여부 적용.
  - **확정: 슬롯별** — 진행기관마다 부가세가 다를 수 있어 `AK/AL/AM`로 각 슬롯 독립 기록(계약당 단일 안 폐기).
- **영업이익** = 부가세 제외 수임비 − 부가세 제외 DB비용 → 양쪽 다 ex-VAT라 일관.
- **ADR 필요**: "부가세 처리 표준(입력 시 부가세여부 기록, 인식은 항상 부가세 제외)" — 비용·매출 공통 1건으로. 게이미피케이션/대시보드 수치가 ex-VAT로 바뀌는 부수효과 회귀 확인.
- 별도 PR로 분리(매출 탭은 DB생산과 다른 영역): 예 `feat/revenue-vat-standardize`. 다음 기획에서 컬럼 위치·재계산 범위 시안 확정 후 진행.
