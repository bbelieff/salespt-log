## 1. 확정 위험 해결 (반드시 이대로 반영)

- **R1 컨택 생산 칸**: 편집 스테퍼 제거 → 채널별 **읽기전용 표시**(자물쇠). 매입DB=유입대기, 직접생산=생산기간, 현수막=오늘 게시/남은, 콜지기소=발굴(오늘 수). "오늘 합계" 칸은 헤더+첫 행 세로 병합(첫 행은 합산 제외), 유입~미팅예약만 4채널 합산.
- **R2 현수막 1:N (확정)**: 주문 1행 + 게시 N행. 게시 로그를 `03 DB관리` 내 새 섹션 `AF:AI`에 두고(주문 행은 P:V 그대로 1행 유지), `productionCountFor(현수막)`을 **게시일(AH)** 기준 Σ게시수(AI)로 재정의(기존 `날짜`=발주일 매칭 제거). 상세 = §3.
- **R3 직접생산 기간·2단계 (확정)**: `I:N` 컬럼 추가/이동 없음. `날짜`(I) → **`기간` 텍스트("시작~종료")** 로 의미 변경(I:N 인접 섹션으로 꽉 차 신규 컬럼 불가). **상태 컬럼 없이 `생산개수` 빈=생산중·채움=완료로 파생.** '생산 시작' = 기간·예산 기록(생산개수 빈). '추가' = 생산개수 입력(완료). `productionCountFor(직접생산)` = 기간 종료일 == date AND 생산개수 채워짐일 때 Σ생산개수. 비용(예산)은 시작 시 반영. 마이그레이션: 레거시 단일 날짜 = "시작=종료" 단일일 취급, 파싱은 "~" 유무 분기.
- **R4 부가세 (확정)**: 부가세 토글은 **입력 시점 역산 헬퍼**일 뿐, **새 컬럼 추가 안 함**(매입DB B:G·현수막 P:V가 인접 섹션으로 꽉 차 컬럼 확장 불가). 저장은 기존처럼 **부가세 제외 개당단가·주문금액만**. 역산 = 총액 ÷ (포함이면 1.1) ÷ 개수. ⚠️ 트레이드오프: 부가세여부는 미저장 → 재편집 시 토글은 기본값, 개당단가는 부가세 제외값으로 표시(원 총액 복원 안 됨). 합계·영업이익 기준 불변.
- **R5 유입대기**: `생산누적 − 유입누적`(수강시작~선택일, 매입DB 채널만). 시트 수식 신설 금지 — service/클라 파생(이미 E·F를 읽는 `readWeekFunnel`/loadDay 경로 활용). 누적 기준 = **전체 수강기간**.
- **R6 보존가드**: 현수막 게시 N행을 쓰는 신규 함수는 §2.5 의무 대상 → `db.ts` 패턴(findFirstEmptyRow + isSumRow 필터)으로 row 단위 안전 확보, 타 사용자값 비침범. `writeProductionCell`의 overwrite 면제는 ADR-0020 한정이라 신규 함수엔 적용 안 됨.
- **R7 게이미피케이션**: `lib/service/gamification.ts`가 `r.production`을 XP에 사용 → 집계 방식 변화로 XP 총량이 달라질 수 있음(부수효과). **XP 가중치는 건드리지 말 것**(건드리면 ADR 필요). 회귀만 확인.
- **R8 SSOT 문서**: `sheet-structure.md`(현수막 1:N·직접생산 기간/상태·부가세 컬럼), `data-model.md`(Zod 타입) 동시 갱신. 신규 최상위 `SHEET_RANGES` 키 추가 시 sheet-structure에 등재(doc-drift). stale 라인 수정: L56 "03 DB관리 MVP 미사용"→가동 중, L730 "H=컨택성공"→미팅예약.

## 2. 채널별 확정 스펙

| 채널 | DB생산 입력 | 컨택 첫 행(읽기전용) | 생산 집계 기준일 |
|---|---|---|---|
| 매입DB | 구매 단건: 주문일·총금액·주문개수·부가세여부 → 개당단가 역산 | 유입대기 = 생산누적−유입누적 | 구매일 |
| 직접생산 | ① 생산 시작(기간 시작~종료·소재·예산) → ② 기간 후 생산개수 입력·추가(완료). 개당단가=예산÷개수 | 생산기간 표시(기간 밖 −) | 기간 종료일 |
| 현수막 | ① 주문(주문일·총금액·주문장수·부가세→장당가 역산) → ② 도착일 → ③ 게시(게시일·게시수, 주문장수까지 N건 추가) | 오늘 게시 / 남은(주문−게시누적) | 게시일 |
| 콜·지·기·소 | 영업기회 단건(구분·접수일·대표자·업체·소개처·연락처·조건). 비용 없음 | 발굴(생산) 오늘 수 | 접수일 |

공통(컨택): `유입·컨택진행·미팅예약` 스테퍼 + "모든 DB채널 합산". 첫 행은 채널 고유값이라 합산 제외(합계 제목 세로 병합). 디자인 정본 = `docs/design/prototypes/` 의 본 세션 시안.

생산 시작/도착/게시·주문 등 단계 = 기존 `미팅 예약→완료` 패턴 재사용(새 멘탈모델 0).

## 3. 시트 스키마 변경 (03 DB관리 + 연동)

- **매입DB**: `부가세여부` 컬럼 추가. (개당단가·주문금액은 부가세 제외 저장 유지)
- **직접생산 (확정)**: `I:N` 유지. `날짜`(I) → `기간` 텍스트("시작~종료") 의미 변경. 상태 컬럼 없음(생산개수 유무로 파생). 소재(J)·기간예산(K)·생산개수(L)·개당단가(M, 수식 예산÷개수)·기타(N) 그대로. 집계 = 종료일 & 생산개수 채워짐. 마이그레이션: 레거시 단일 날짜는 "~" 없는 단일일로 파싱.
- **현수막 (확정)**: 주문 섹션 `P:V`는 **컬럼 변경 없음**(부가세는 입력 헬퍼, 저장 부가세 제외 유지). **게시 로그 = `03 DB관리` 내 새 섹션 `AF:AI`** (콜지기소 `AD` 뒤, 스페이서 `AE` 다음). `SHEET_RANGES.dbManagement.sections` 안에 nested 추가(신규 최상위 키 아님 → doc-drift 부담↓). 1행=1게시, 앱 append/update/delete:
  - `AF 게시id`(UUID, 키) · `AG 주문ref`(= `주문일\|업체명`, P:V의 날짜+업체명 합성) · `AH 게시일`(date) · `AI 게시수`(number)
  - 한 주문이 여러 날 게시 → 같은 `주문ref`로 게시 행이 아래로 누적(주문 행은 1행 유지).
  - 집계: 현수막 생산(E) = Σ`AI` where `AH`==date. 같은 게시일 여러 건이면 합산.
  - 남은 = (주문ref의 P:V 주문개수) − Σ(같은 주문ref의 AI).
  - 보존가드(§2.5): id 기준 자기 행만 update, append는 `AF` 빈 행 + FORMULA pre-read로 타값 비침범. 게시수 합이 주문개수 초과 못 하게 입력 검증.
- **집계 재정의**: `productionCountFor`을 채널별 기준일/상태에 맞게 분기 재작성(직접생산=종료일&완료, 현수막=게시일 로그 합). `syncProduction` 호출 지점(주문/게시/생산완료/삭제)마다 해당 날짜 E 재집계.
- **남은/유입대기**: 시트에 컬럼 신설 말 것 — 읽을 때 service/클라에서 파생.

> 운영 중(아레나 시즌1) 전 수강생 시트 영향 → 컬럼 추가·마이그레이션은 소수 시트 먼저 검증, plan에 명시.

## 5. 검증(연동) 체크 — 각 PR 수용 기준에 포함

- DB생산 추가/수정/삭제 → 해당 채널·기준일의 `01 영업관리 E` 재집계 정확(시트 직접 확인): 매입DB=구매일, 직접생산=종료일(완료시만), 현수막=게시일별, 콜지기소=접수일.
- 현수막: 주문 20·게시 8+4 → 게시일(6/9·6/11) E에 각 8·4, 컨택 첫 행 "오늘 게시/남은=8" 정확, 남은=주문−게시누적.
- 직접생산: 생산 시작만 한 상태(생산중)에선 E 미반영, '추가'(완료) 후 종료일 E 반영. 컨택 첫 행=생산기간(기간 밖 −).
- 매입DB: 부가세 포함/미포함 토글에 따라 개당단가 역산 일치(총액÷1.1÷개수 / 총액÷개수). 유입대기=생산누적−유입누적.
- 컨택 생산 칸: 편집 불가(읽기전용), 합계는 유입~미팅예약만(첫 행 제외).
- 회귀: 게이미피케이션 XP 비정상 변동 없는지, 보존가드로 타 사용자값 비침범, 구조테스트·doc-drift green.
