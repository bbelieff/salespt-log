# 채널별 유입 수식 가이드 — 시트 stacking 완성용

> **작업 가이드** — 사용자가 시트 직접 박는 4개 셀 수식 (채널별 유입).
>
> "stacking" 의미: prototype의 **funnel 차트는 단계마다 4채널 색깔 stacked 막대로 표시**.
> 즉 단계마다 (매입DB / 직접생산 / 현수막 / 콜·지·기·소) 4 값이 필요. 6단계 × 4채널 = 24개.
> 현재 시트는 **생산/계약** 채널별만 있음 (`01 영업관리!K3:L6`). 나머지 4단계(유입/컨택진행/미팅예약/미팅완료)는 채널별 데이터 없음.
> 코드는 **계약 비율로 비례 분배**해서 임시로 stacking 표시 중. 정확하지 않음.

이 문서는 **유입**부터 시트에 추가하는 가이드. 컨택진행/미팅예약/미팅완료는 동일 패턴 (열만 다름).

## 패턴

기존 매입DB 생산총합 (`01 영업관리!K3`) 수식이 reference:
```
=E10+E14+E18+E22+E26+E30+E34
+E44+E48+E52+E56+E60+E64+E68
+E78+E82+E86+E90+E94+E98+E102
+E112+E116+E120+E124+E128+E132+E136
+E146+E150+E154+E158+E162+E166+E170
+E180+E184+E188+E192+E196+E200+E204
+E214+E218+E222+E226+E230+E234+E238
+E248+E252+E256+E260+E264+E268+E272
```

**구조**:
- 매주 28행 블록 (7일 × 4채널), stride 34 (1주차 row 10, 2주차 44, ..., 8주차 248)
- 각 일자: 4채널 (매입DB/직접생산/현수막/콜지기소) 순서
- 컬럼: E=생산, **F=유입**, G=컨택진행, H=미팅예약

**채널 row offset** (각 일자 첫 row 기준):
- 매입DB: +0
- 직접생산: +1
- 현수막: +2
- 콜·지·기·소: +3

## 추후 (컨택진행/미팅예약/미팅완료 추가 시)

같은 row 패턴, **컬럼만 변경**:
- 컨택진행: F → G
- 미팅예약: F → H
- 미팅완료: 04 업체관리에서 COUNTIFS (별도 — 영업관리 시트엔 raw 없음)

## 셀 위치 알려주면

내가 `lib/repo/dashboard.ts` 에 batchGet 추가하고 `channelMatrix.유입`을 정확값으로 wiring.

추가할 cell 좌표 형식 (예시):
```
N7=매입DB유입, N8=직접생산유입, N9=현수막유입, N10=콜지기소유입
```
